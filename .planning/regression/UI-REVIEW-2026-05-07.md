## Findings

### PASS - Copy: static labels are English, dynamic content may be Russian

- Evidence: `01-viewer-published-archive.png`, `02-lead-report-form.png`, `03-head-dashboard.png`, `04-head-author-report.png`, `05-weekly-report-products.png`.
- Static labels such as `Dashboard`, `Weekly Report`, `Archive`, `My Report`, `Product Status`, `Current Week`, `Next Week`, `Risks & Blockers`, `Decisions`, `Top Priorities`, `Export PDF`, and `Publish & Lock` are English.
- Russian appears in user/product/report content, for example names and item text in `02-lead-report-form.png` and `04-head-author-report.png`; that matches the stated contract.
- Residual polish risk: `03-head-dashboard.png` includes many generated `Lead 1`, `Test User ...`, and `Toast Test ...` rows. This is dynamic/test content, not static UI copy, but it makes product-ready screenshots look polluted.

### PASS - Dashboard lead cards deep-link to author report

- Code: `apps/web/src/components/dashboard/lead-report-card.tsx:119-123` builds `/head/report/<reportId>?authorId=<lead.id>` for non-current leads and `/lead/report/<reportId>?authorId=<lead.id>` for own row.
- Code: `apps/web/src/components/weekly-report/weekly-report-page.tsx:224-235` resolves the focused author and opens exactly one content-bearing product by default.
- Evidence: `04-head-author-report.png` shows the weekly report loaded with the author-focused product expanded.

### FLAG - Activity panel rows use the wrong dashboard deep-link surface

- Code: `apps/web/src/components/dashboard/activity-live-panel.tsx:17-18` documents activity row clicks as `/lead/report/<reportId>?authorId=<leadId>`.
- Code: `apps/web/src/components/dashboard/activity-live-panel.tsx:125` implements that `/lead/report/...` link for every row.
- Impact: on the head dashboard, Activity This Period rows look like drill-down links but route to a lead-owned surface instead of the assembled head report. This conflicts with the dashboard lead-card behavior and can hit role/access friction.
- Fix: use `/head/report/<reportId>?authorId=<leadId>` for head/admin activity rows, or make the route role-aware.

### FLAG - Product accordion empty states are present, but empty rows still look expandable

- Code: `apps/web/src/components/weekly-report/product-accordion.tsx:69-75` correctly detects empty product content.
- Code: `apps/web/src/components/weekly-report/product-accordion.tsx:105-114` disables the button when empty.
- Code: `apps/web/src/components/weekly-report/product-accordion.tsx:145-149` renders `No content submitted for this product.`
- Evidence: `05-weekly-report-products.png` shows many empty products with a visible chevron and an always-visible empty panel. They are disabled in code, but visually read like open accordion sections.
- Fix: remove or mute the chevron for empty rows, add `aria-disabled`, and use a stronger disabled visual state so empty rows do not imply expandable content.

### FLAG - Product accordion can still read as two selected regions

- Evidence: `04-head-author-report.png` and `05-weekly-report-products.png`.
- Code: `apps/web/src/components/weekly-report/product-accordion.tsx:99-102` applies green border/ring to the highlighted accordion.
- Code: `apps/web/src/components/weekly-report/portfolio-overview-table.tsx:112-145` gives portfolio cards strong hover/focus/activation affordance.
- Impact: after navigating from portfolio/author focus, the top overview and the detailed accordion both have high-salience status blocks. The selected accordion is technically singular, but the composition can still read as multiple active sections because status color and selected ring compete.
- Fix: reserve the green ring for the detailed accordion only; use a subtler scroll-target indicator or transient focus state in the portfolio grid.

### FLAG - Disabled PDF export affordance is understandable only via tooltip/title

- Code: `apps/web/src/components/weekly-report/export-pdf-button.tsx:81-89` computes `disabled` and `title="Publish the report first"`.
- Code: `apps/web/src/components/weekly-report/export-pdf-button.tsx:97-105` renders the disabled button with reduced opacity but keeps the visible label as `Export PDF`.
- Evidence: `04-head-author-report.png` shows `Export PDF` as pale/disabled next to `Publish & Lock`.
- Impact: a disabled button's `title` is not reliably discoverable on touch devices or keyboard-only workflows, so the reason for disabled state is under-explained.
- Fix: change visible copy while disabled to `Publish to export PDF` or add adjacent helper text/`aria-describedby`.

### FLAG - Archive cards need stronger focus/click affordance

- Code: `apps/web/src/components/dashboard/report-archive-section.tsx:96-123` renders archive cards as anchors.
- Code: `apps/web/src/components/dashboard/report-archive-section.tsx:99` has hover border only, no explicit `cursor-pointer` and no `focus-visible` ring.
- Evidence: `01-viewer-published-archive.png` and bottom of `03-head-dashboard.png`.
- Impact: keyboard focus and pointer affordance are weaker than lead cards and product cards.
- Fix: add `cursor-pointer`, `hover:shadow...`, and `focus-visible:ring-2 focus-visible:ring-[var(--color-starbucks-accent)] focus-visible:ring-offset-2`.

### PASS - Clickable areas mostly have hover/focus affordance

- Code: `apps/web/src/components/dashboard/lead-report-card.tsx:141-145`, `apps/web/src/components/dashboard/activity-live-panel.tsx:132-135`, `apps/web/src/components/weekly-report/product-accordion.tsx:107-114`, and `apps/web/src/components/weekly-report/portfolio-overview-table.tsx:112-145`.
- These important clickable regions use `cursor-pointer`, hover background/border/shadow, and focus rings.
- Residual risk is limited to archive cards and nav links, which are lower-risk but still part of the product chrome.

### FLAG - Color and typography rely heavily on arbitrary values

- Scan result: 184 matches for arbitrary color/background/border patterns across dashboard, weekly-report, and navigation components.
- Examples: `apps/web/src/components/weekly-report/product-accordion.tsx:27-35`, `apps/web/src/components/dashboard/lead-report-card.tsx:30-33`, `apps/web/src/components/dashboard/report-archive-section.tsx:40-41`.
- Typography scan found many one-off sizes including `text-[9px]`, `text-[10px]`, `text-[11px]`, `text-[13px]`, `text-[28px]`, and `text-[32px]`.
- Impact: current screenshots are readable, but future polish will be harder because color/size decisions are distributed rather than tokenized.
- Fix: promote recurring status colors and micro-label sizes into shared tokens/classes.

---

## Top 3 Priority Fixes

1. Route Activity This Period rows to `/head/report/<reportId>?authorId=<leadId>` for head/admin so dashboard drill-downs consistently open the assembled report.
2. Make disabled `Export PDF` self-explanatory without relying on `title`; visible disabled copy should say why export is unavailable.
3. Reduce accordion ambiguity for empty/highlighted products: mute/remove empty chevrons and ensure only the detailed target reads as selected.

---

## Residual Polish Risks

- Product-ready screenshots contain generated test users/products; this is not static UI copy, but it weakens demo credibility.
- Archive cards are clickable but visually quieter than other interactive cards.
- Color and typography are good enough to ship but should be consolidated before broader design-system reuse.
- Supplemental fresh screenshots show the unauthenticated/default role state rather than the regression journey; primary visual evidence remains the regression PNGs listed above.
