## Overview

v7.0 stabilises the surfaces that v6.0 built fast. The post-v6.0 UX-overhaul wave closed 44 ad-hoc UX issues against a moving target; v7.0 turns those wins into permanent invariants and pays down accumulated technical debt.

**Wave 1 (in scope):**
- **Phase 32 — UX Polish:** closes 4 deferred items from HANDOFF (mapper role read-model, Recharts warnings, Risk schema stageName, real-device iOS) plus a single-source touch-target raise from 40 to 44px across lead-form actions.
- **Phase 33 — API Hardening:** zeroes the ESLint warning floor, adds BullMQ DLQ visibility, documents Prisma 7 schema gotchas, surfaces the push-guard workaround, and adds CI flaky-rate tracking.

**Wave 2-4 (forecast only, NOT in v7.0):** Multi-period roll-up, observability, AI expansion, notification intelligence. Documented in `v7.0-REQUIREMENTS.md` for traceability; not committed to v7.0 scope.

**Multi-tenancy:** permanently deferred until org structure demands it.

## Key Themes

1. **Pay down post-v6.0 UX debt** — every UX item the user flagged but couldn't be closed without a schema or read-model change is closed in Phase 32.
2. **Get to a green-CI baseline** — 0 ESLint warnings, 0 TypeScript errors, no manual `https_proxy=""` workaround. Sets up the team to ship Wave 2-4 from a clean floor.
3. **Surface ops intelligence we built but don't show** — BullMQ DLQ already collects, audit logging already runs, push-guard already enforces. v7.0 makes them visible without inventing new infra.
