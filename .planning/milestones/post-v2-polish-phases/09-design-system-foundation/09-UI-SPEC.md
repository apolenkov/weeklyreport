## Design System

| Property          | Value                                                                                                                                     |
| ----------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| Tool              | shadcn/ui v4 (monorepo CLI: `pnpm dlx shadcn@latest init --monorepo`)                                                                     |

| Component library | Radix UI (via shadcn/ui wrappers)                                                                                                         |

| Dark mode         | Deferred -- not in Phase 9 scope. Tokens are structured for it (background/foreground pairs). next-themes ThemeProvider added in Phase 10 |

## Spacing Scale

Declared values (multiples of 4, standard 8-point grid):

| Token | Value | CSS Variable    | Usage                                               |
| ----- | ----- | --------------- | --------------------------------------------------- |
| xs    | 4px   | `--spacing-xs`  | Icon-to-text gaps, inline badge padding             |
| sm    | 8px   | `--spacing-sm`  | Form field internal padding, compact list item gaps |
| md    | 16px  | `--spacing-md`  | Default element margin, card body padding           |
| lg    | 24px  | `--spacing-lg`  | Section padding within cards, form group gaps       |
| xl    | 32px  | `--spacing-xl`  | Page-level sidebar gutter, navigation padding       |
| 2xl   | 48px  | `--spacing-2xl` | Major section vertical breaks (report sections)     |
| 3xl   | 64px  | `--spacing-3xl` | Page top/bottom padding on desktop                  |

Exceptions:

- Touch target minimum: 44px height for all interactive elements on mobile (hamburger, sidebar items, form controls)
- Sidebar collapsed width: 56px (icon-only mode)
- Sidebar expanded width: 240px

## Typography

Font: Inter loaded via `next/font/google` in `apps/web/src/app/layout.tsx` with `subsets: ['cyrillic', 'latin']`.

| Role    | Size | Weight         | Line Height | CSS Variable          | Usage                                            |
| ------- | ---- | -------------- | ----------- | --------------------- | ------------------------------------------------ |
| Body    | 14px | 400 (regular)  | 1.5         | `--font-size-body`    | All body text, table cells, form inputs          |
| Label   | 12px | 500 (medium)   | 1.4         | `--font-size-label`   | Form labels, badge text, table headers, metadata |
| Heading | 20px | 600 (semibold) | 1.3         | `--font-size-heading` | Card titles, section headings (h2, h3)           |
| Display | 28px | 600 (semibold) | 1.2         | `--font-size-display` | Page titles only (h1)                            |

Rules:

- Maximum 2 font weights in production: 400 and 600. Medium 500 is used only at Label size for optical correction
- All text renders in Russian (lang="ru"). The Inter font must include the `cyrillic` subset
- No font below 12px anywhere in the application (accessibility floor)
- Monospace for code/IDs only: system monospace stack (`ui-monospace, SFMono-Regular, monospace`)

## Color

shadcn/ui uses background/foreground variable pairs in OKLCH. These map to the 60/30/10 visual hierarchy.

### Light Mode Palette (default)

| Role                           | OKLCH Value                  | Hex Approx | Usage                                                |
| ------------------------------ | ---------------------------- | ---------- | ---------------------------------------------------- |
| **Dominant (60%)** background  | `oklch(1 0 0)`               | #FFFFFF    | Page background, main content area                   |
| **Dominant** foreground        | `oklch(0.145 0 0)`           | #1A1A1A    | Body text on background                              |
| **Secondary (30%)** muted      | `oklch(0.97 0 0)`            | #F5F5F5    | Card surfaces, sidebar background, table header rows |
| **Secondary** muted-foreground | `oklch(0.556 0 0)`           | #737373    | Secondary text, placeholders, metadata               |
| **Accent (10%)** primary       | `oklch(0.205 0.064 280.749)` | #1E1B4B    | See "Accent reserved for" list below                 |
| **Accent** primary-foreground  | `oklch(0.985 0 0)`           | #FAFAFA    | Text on accent-colored elements                      |
| Destructive                    | `oklch(0.577 0.245 27.325)`  | #DC2626    | Delete buttons, error states, red traffic light fill |
| Destructive-foreground         | `oklch(0.985 0 0)`           | #FAFAFA    | Text on destructive elements                         |
| Border                         | `oklch(0.922 0 0)`           | #E5E5E5    | Card borders, table cell dividers, input borders     |
| Ring                           | `oklch(0.708 0 0)`           | #A3A3A3    | Focus ring for keyboard navigation                   |

### Traffic Light Colors (domain-specific semantic colors)

These are the core domain colors used throughout the application for project status indication.

| Status | Background               | Foreground               | Border                   | Usage                                                   |
| ------ | ------------------------ | ------------------------ | ------------------------ | ------------------------------------------------------- |
| Green  | `oklch(0.925 0.084 155)` | `oklch(0.365 0.110 152)` | `oklch(0.723 0.150 152)` | Project status "green" badge fill, dashboard row accent |
| Yellow | `oklch(0.945 0.080 85)`  | `oklch(0.475 0.115 65)`  | `oklch(0.785 0.150 75)`  | Project status "yellow" badge fill                      |
| Red    | `oklch(0.936 0.060 25)`  | `oklch(0.505 0.195 25)`  | `oklch(0.715 0.210 25)`  | Project status "red" badge fill                         |
| Unset  | `oklch(0.97 0 0)`        | `oklch(0.556 0 0)`       | `oklch(0.922 0 0)`       | No status selected -- muted appearance                  |

These are defined as CSS custom properties `--color-traffic-green`, `--color-traffic-yellow`, `--color-traffic-red`, `--color-traffic-unset` (with `-foreground` and `-border` suffixes for each).

### Print Fallbacks (PDF-02 requirement)

For `@media print` stylesheet, all OKLCH values must have hex fallbacks. The print stylesheet uses a separate set of CSS variables with hex values to ensure Playwright PDF renders colors correctly in all PDF viewers.

### Accent Reserved For

The accent color (primary) is reserved exclusively for:

1. Primary action buttons ("Submit Section", "Publish Report", "Export PDF", "Save")
2. Active sidebar navigation item background
3. Active tab indicator underline
4. Link text on hover
5. Focus ring on keyboard-navigated elements

Accent must NOT be used for: background areas, decorative elements, traffic light badges, status indicators, borders, or card surfaces.

## DataTable Pattern (DS-05)

The DataTable is a styled wrapper around the native HTML `<table>` element using shadcn/ui Table components. TanStack Table is NOT used in Phase 9 (research STACK.md explicitly advises against it for this user count). Sorting is implemented via client-side array sort on column header click.

### Structure

```
+------------------------------------------------------+
| [Column A ^] | [Column B] | [Column C v] | [Actions] |
+------------------------------------------------------+
| Row 1 data   | data       | data         | [...]     |
| Row 2 data   | data       | data         | [...]     |
| Row 3 data   | data       | data         | [...]     |
+------------------------------------------------------+
```

- Table header row uses muted background (`--color-muted`)
- Sortable columns show chevron-up/chevron-down icon (lucide `ChevronUp`, `ChevronDown`)
- Active sort column header has semibold text
- Rows have `border-bottom: 1px solid var(--color-border)`
- Row hover shows muted background
- Empty table shows centered empty state message (see Copywriting)

## Dialog/Sheet Pattern (DS-07)

### Confirmation Dialog

Used for destructive or irreversible actions (Publish Report, Delete User, Run Carry-over).

```
+----------------------------------------------+
|  Dialog Title                           [X]  |
+----------------------------------------------+
|                                              |
|  Confirmation message body text.             |
|  Explains what will happen.                  |
|                                              |
+----------------------------------------------+
|                    [Cancel]  [Confirm Action] |
+----------------------------------------------+
```

- Dialog overlay: `oklch(0 0 0 / 0.5)` (50% black)
- Dialog width: 480px max, centered horizontally and vertically
- Cancel button: `variant="outline"` (secondary)

## Toast Pattern (DS-08)

Using shadcn/ui `sonner` integration (wraps the Sonner library).

| Event              | Toast Variant | Title                | Description                                   | Duration |
| ------------------ | ------------- | -------------------- | --------------------------------------------- | -------- |
| Draft saved        | `default`     | "Draft saved"        | --                                            | 2000ms   |
| Section submitted  | `success`     | "Section submitted"  | "Your report section has been locked."        | 4000ms   |
| Report published   | `success`     | "Report published"   | "The report is now visible to viewers."       | 4000ms   |
| PDF export started | `default`     | "PDF export started" | "You will be notified when ready."            | 3000ms   |
| User created       | `success`     | "User added"         | "{name} has been added as {role}."            | 3000ms   |
| Delete completed   | `success`     | "Deleted"            | "{entity} has been removed."                  | 3000ms   |
| Network error      | `error`       | "Connection error"   | "Could not reach the server. Try again."      | 5000ms   |
| Validation error   | `error`       | "Invalid data"       | "{field-specific message}"                    | 5000ms   |
| Permission denied  | `error`       | "Access denied"      | "You do not have permission for this action." | 5000ms   |

Position: `bottom-right` on desktop, `bottom-center` on mobile.

Toast maximum visible: 3 stacked. Oldest auto-dismissed.

## Loading Skeleton Pattern (DS-09)

Replace all existing "Loading..." text with skeleton placeholders that match the shape of the content they replace.

| Content Type   | Skeleton Shape                 | Dimensions                  |
| -------------- | ------------------------------ | --------------------------- |
| Page title     | Single rectangle               | h=28px, w=240px             |
| Table row      | 4 rectangles per row, 5 rows   | h=20px, w varies per column |
| Card           | Rectangle with rounded corners | h=160px, w=100%             |
| Badge          | Small rounded rectangle        | h=24px, w=64px              |
| Avatar         | Circle                         | 32px diameter               |
| Button         | Rounded rectangle              | h=36px, w=120px             |
| Form field     | Rectangle                      | h=36px, w=100%              |
| Paragraph text | 3 stacked rectangles           | h=14px, w=100%/90%/60%      |

Skeleton animation: shadcn default pulse (`animate-pulse` from tw-animate-css).

tRPC integration pattern:

```
const { data, isLoading } = trpc.foo.useQuery();
if (isLoading) return <FooSkeleton />;
return <FooContent data={data} />;
```

Each component that fetches tRPC data must have a co-located `*Skeleton` export. Example: `submission-dashboard.tsx` exports `SubmissionDashboard` and `SubmissionDashboardSkeleton`.

## Interaction States

All interactive elements must declare these states explicitly:

| State          | Visual Treatment                                                                                     |
| -------------- | ---------------------------------------------------------------------------------------------------- |
| Default        | Base colors as defined in Color section                                                              |
| Hover          | Background lightens/darkens by 1 OKLCH lightness step; 150ms transition                              |
| Focus          | 2px ring using `--color-ring`, offset 2px. Ring is visible on keyboard focus only (`:focus-visible`) |
| Active/Pressed | Background darkens by 2 OKLCH lightness steps                                                        |
| Disabled       | 50% opacity, `cursor: not-allowed`, no hover/focus effects                                           |
| Loading        | Spinner icon (lucide `Loader2` with `animate-spin`) replaces button label text                       |

Transitions: `transition-colors duration-150` on all interactive elements. No transition on layout properties (width, height, margin) to avoid jank.

## Accessibility Requirements

| Requirement         | Implementation                                                                                                                                                  |
| ------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Color contrast      | All text meets WCAG AA (4.5:1 normal, 3:1 large). Traffic light badges use text labels alongside color                                                          |
| Focus management    | Dialog traps focus. Sheet traps focus. Toast is `role="status"` (not interrupting)                                                                              |
| Keyboard navigation | All interactive elements reachable via Tab. Sidebar items navigable via arrow keys. Escape closes dialogs/sheets                                                |
| Screen reader       | All images have alt text. Icon-only buttons have `aria-label`. Tables have `aria-label` on `<table>` element. Status badges include text label (not color-only) |
| Motion              | Respect `prefers-reduced-motion: reduce` -- disable tw-animate-css animations                                                                                   |
| Language            | `<html lang="ru">` (existing, preserved)                                                                                                                        |

## Monorepo Wiring Checklist (P1 Pitfall Prevention)

These steps prevent the #1 day-one blocker (Tailwind classes invisible in consuming app):

1. `packages/ui/src/styles/globals.css` contains `@source` directive scanning `../../src/**/*.{ts,tsx}` (packages/ui components) AND `../../../apps/web/src/**/*.{ts,tsx}` (consuming app)
2. `apps/web/postcss.config.mjs` uses `@tailwindcss/postcss` plugin
3. `apps/web/next.config.ts` includes `transpilePackages: ['@customreport/ui']`
4. `apps/web/src/app/layout.tsx` imports `@customreport/ui/styles/globals.css`
5. Validation: render a single `<Button>` on the landing page and confirm it has styled classes in the browser
