## Overview

v8.0 shipped CustomReport into a deployable, observable, secured state. v8.1 closes the three gaps that were intentionally deferred at the v8.0 acceptance gate:

1. **Visual identity** — light theme reads "consumer" (Starbucks-inspired green). Internal stakeholders asked for a "more serious / B2B" look. Adds a dark mode baseline + a B2B palette refresh (less green saturation, more neutrals, professional typography). Self-driven PRD + design — no external designer.
2. **AI maturity** — Phase 31 shipped the AI summary card with partial eval coverage. v8.1 builds the eval harness (golden set + rubric runner), prompt regression suite, and observability metrics so AI features can ship safely.
3. **iOS Safari sign-off** — manual real-device verification, captured as a checklist + RUNBOOK addendum + screenshot evidence.

### Phase 44: Reminder Policies (global, period-agnostic)

**Goal:** Replace per-period `ReminderRule` with global `ReminderPolicy` + auto-derived per-period rules. One configured policy → automatically fires for every future Period; current model requires admins to recreate the rule every reporting cycle, which is the surface gap that triggered UFB-036.
**Depends on:** none (independent of brand/AI/iOS work)
**Requirements:** UFB-036 (Reminder Policy model), NOTIF-06 (autogen on Period.create)
**Plans:** 5

Provisional plans:

- [ ] 44-01-PLAN — Prisma schema + data migration. Add `ReminderPolicy {id, kind, offsetMinutes, timezone, audience, active}` model; backfill from existing `ReminderRule` rows by deduping on (kind, offsetMinutes, timezone). Keep `ReminderRule` as the derived/per-period table; add `policyId` FK (nullable for legacy rows during migration window).
- [ ] 44-02-PLAN — Shared zod schema + tRPC contract: `reminderPolicySchema`, `admin.savePolicy`, `admin.removePolicy`, `admin.listPolicies`. Drop the `admin.saveReminderRule` write path (read remains for derived rules visualization).
- [ ] 44-03-PLAN — Period.create hook + backfill cron: when a `ReportPeriod` row is created, generate `ReminderRule` for each active policy (`fireAt = period.deadline + policy.offsetMinutes` in policy.timezone). One-shot backfill for existing open Periods.
- [ ] 44-04-PLAN — UI rework: Reminders Tab now lists Policies (not Rules). Form: kind + offset (numeric hours, +/- for before/after) + timezone select (reuse `TIMEZONE_OPTIONS` from UFB-035) + audience. Derived rules per period shown read-only as a collapsible "Active rules per period" panel.
- [ ] 44-05-PLAN — Tests + audit log: contract tests for policy CRUD, integration test for Period.create autogen, UI test that policy edit propagates to all open periods. Action log entries: `admin.policy.save|remove`.

### Phase 46: Group-Scope Visibility (head sees own group; viewer sees N groups)

**Goal:** Heads see only their own group's leads, sections, reports, dashboards. Viewers see only the groups granted via `ViewerGroupAccess` (Phase 45 / UFB-039 schema). Admins still see everything (god-mode unchanged). Closes UFB-040.
**Depends on:** UFB-039 schema (already shipped: `ReportingGroup.headUserId`, `ViewerGroupAccess`)
**Requirements:** UFB-040 (per-role group-scope filtering)
**Plans:** 5

Provisional plans:

- [ ] 46-01-PLAN — `groupScopeFilter(session)` helper + unit tests. Returns Prisma `where` fragment: `{}` for admin, `{ reportingGroupId: session.reportingGroupId }` for head, `{ reportingGroupId: { in: viewerAccess[] } }` for viewer, `{ id: session.userId }` for lead (own section only).
- [ ] 46-02-PLAN — Apply to dashboard: `reviewService.getSubmissionDashboard(reportId, session)` filters `ReportSection` by `author.reportingGroupId` matching scope. Update `headProcedure dashboard` callsite.
- [ ] 46-03-PLAN — Apply to `archive.list` + `archive.detail`: viewers see only published reports whose group has ≥1 section visible; heads see only their group's slice.
- [ ] 46-04-PLAN — Apply to projects (`/admin/projects` listing for heads is N/A since they no longer see admin), but `weeklyReport.get` and lead lookups must filter by group on queries that surface other leads.
- [ ] 46-05-PLAN — Tests: integration tests covering each role × route matrix. Verify a head from group A cannot see leads/projects from group B; verify viewer Дарья seeing groups [A,B] cannot read group C reports even with direct id.
