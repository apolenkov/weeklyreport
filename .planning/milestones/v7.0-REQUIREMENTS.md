# Requirements: CustomReport v7.0 — PLANNING

**Defined:** 2026-05-04
**Status:** Planning (Wave 1 scoped; Wave 2-4 deferred)
**Predecessor:** v6.0 (5 phases / 22 plans / 37 requirements shipped 2026-04-29) + post-v6.0 UX-overhaul wave (44 ad-hoc tasks closed 2026-04-30..2026-05-04)
**Core Value:** Lead form is stable, mobile-clean, and self-checkpointing; admin/ops surfaces gain the operational intelligence the team has been waiting for; ESLint warning floor drops to single-digit.

> **Scope philosophy:** v7.0 is a stabilisation milestone, not a feature wave. Wave 1 (Phase 32 + 33) closes UX debt and API hardening. Wave 2-4 are forecast only — they are out of scope for v7.0 and will be re-evaluated when Wave 1 ships. Multi-tenancy / department separation is permanently deferred until org structure demands it.

## v7.0 Requirements (Wave 1)

### UX Polish (Phase 32) — closes 4 deferred items from HANDOFF + 1 user-paid item

- [ ] **UX-08** — `ReportSectionReadModel` carries the section author's display role so frontend Revoke vs Request-Reopen gating no longer relies on the hard-coded `currentUser.role = 'Dev Lead'` mapper default. Closes HANDOFF #48 — Head/Admin viewing /lead/report?period=X currently sees Lead UX (Request Reopen instead of Revoke).
- [ ] **UX-09** — Recharts `<ResponsiveContainer>` warnings on /reports/trends initial mount silenced via `minWidth={0}` (or equivalent fix). Cosmetic-only — chart renders correctly at 1088×256 once measured. Closes HANDOFF #47.
- [ ] **UX-10** — Risk schema gains `stageName` field end-to-end (Prisma migration + Zod schema + read model + edit dialog). Unblocks the linkedRiskCount confirm-on-Clear path in stage-chip.tsx (HANDOFF #46) — currently never trips because frontend mapper defaults to placeholder `—`.
- [ ] **UX-11** — Real-device iOS Safari PDF embed sign-off (MOB-06 deferred from v6.0 Phase 30). Playwright virtual `devices['iPhone 14']` covers; need human-on-device confirmation on a real iPhone before closing.
- [ ] **UX-12** — Apple HIG 44px touch-target floor across lead-form action surfaces. Block 1 of post-v6.0 wave shipped 40px (consistency baseline); v7.0 raises to 44px in Item/Risk/Decision/Priority dialog Save+Cancel + ChevronLeft/Right nav buttons. Single-source CSS variable lets future raises happen in one place.

### API Hardening (Phase 33) — production-readiness debt

- [ ] **API-01** — ESLint warning cleanup: ~185 in `apps/api`, ~87 in `apps/web` (predominantly `@typescript-eslint/no-non-null-assertion` in test files). Goal: zero warnings on `pnpm lint --filter @customreport/api` and `pnpm lint --filter @customreport/web`. Test-file assertions replaced with `expectDefined()` helper or proper type narrowing.
- [ ] **API-02** — BullMQ DLQ admin UI: `/admin/jobs` route surfaces `failed` queue contents (job id, attempt count, error preview, last failure time) with a Retry button per row. Phase 28 added a badge but no detail view.
- [ ] **API-03** — Prisma 7 schema audit: document the discovered `migrate reset --skip-seed` quirk (prisma.config.ts does NOT auto-invoke seed despite docs implying it does) in STATE pitfalls. Add a CI check that fails if migrations don't apply cleanly to a fresh DB. Closes Pitfall #11 (informally noted in v6.0 closing notes).
- [ ] **API-04** — Pre-existing TypeScript error rollup: 17 errors in 5 web files + 5 errors in 3 api files (all from prior commits — `nullable_project_status` migration didn't propagate type narrowings, RiskEntry.impact/mitigation became required after schema tightening). One ticket per file, each with a regression test that locks the fix.
- [ ] **API-05** — E2E flakiness regression tracking: CI report adds a flaky-rate metric per spec file (passed-on-retry / total). Phase 27 fixed 5 timeouts in the integration suite (D-1 pitfall); we want to know early if regressions creep back in.
- [ ] **API-06** — Push-guard hook: `git push origin main` currently requires VPN access to `ghe.example.org`. Document the workaround pattern (`https_proxy="" command git push`) in CONTRIBUTING + add a pre-push helper script that detects the no-DNS state and prints the workaround inline. Closes the recurring "13+ commits ahead, can't push" bind.

## Out of Scope (forecast only — NOT in v7.0)

These themes are listed for traceability but will be re-evaluated only after Wave 1 ships. None of them blocks v7.0.

### Wave 2 — Multi-Period Roll-Up & Observability (~6-9 plans)
- Quarterly / multi-period analytics roll-up (Q-over-Q delta, 52-week trend, predictive resolution date)
- Audit dashboard expansion (query trail by role/date/action, CSV export, SOX/SOC2-ready rollup)
- Metrics dashboard (timed submission rate per period, PDF generation latency SLA, BullMQ DLQ inspection)

### Wave 3 — AI Features Expansion (~6-9 plans)
- AI-04: Period-over-period diff narrative
- AI-05: Risk theme clustering
- AI-06: Head's narrative auto-draft seeding (lead-side equivalent NEVER, by policy)
- AI cost optimisation: read-through cache on `contentHash` (mandatory before scaling Sonnet 4.6 layer)
- Golden-set rubric head sign-off (8-12 reports, currently feature-flagged off)

### Wave 4 — Notification Intelligence (~3-6 plans)
- NOTIF-07: Custom reminder schedule per lead (T-48h vs T-24h)
- NOTIF-08: Slack/Teams webhook fallback
- Sentiment-driven escalation rules (risk sentiment=high AND status=draft → page head)

### Permanently deferred until org demands
- Multi-tenancy / department separation — out of scope until CustomReport serves more than one department. Triggers: new department onboarding request, or executive-level decision to extend beyond CoreDev.

## Success Criteria

v7.0 ships when:
1. All 11 Wave 1 requirements have a passing verification (unit/integration test or manual sign-off — UX-11 is the only manual one).
2. ESLint output on both packages prints `0 problems` on `pnpm lint`.
3. TypeScript output prints `0 errors` on `tsc --noEmit -p tsconfig.json` for both `apps/api` and `apps/web`.
4. CI pipeline pushes a green badge on a clean PR through `git push origin main` from the maintainer's machine without manual `https_proxy=""` workaround for >50% of attempts.
5. Mobile audit suite (`e2e/integration/lead-form-mobile.integration.spec.ts`) passes at 44px touch-target threshold (raised from 40px).
