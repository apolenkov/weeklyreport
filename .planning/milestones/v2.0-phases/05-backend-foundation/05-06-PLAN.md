**Step 1: Fix Zod schema for recipientEmail (packages/shared/src/schemas/report.ts)**

The `adminReminderExecutionSchema` at line 191 has `recipientEmail: z.email()`. The Prisma `ReminderExecution` table does NOT store `recipientEmail` -- it only exists at the domain/service layer. The repository mapper returns `recipientEmail: ''` which fails `z.email()` validation.

Change line 191 from:

```
recipientEmail: z.email(),
```

to:

```
recipientEmail: z.string(),
```

This allows empty strings from the repository layer. The service layer populates real emails before sending. No other file references `recipientEmail` in a way that requires email validation -- validation happens at the service boundary (the service receives the email as a parameter).
