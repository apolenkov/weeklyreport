**File 1: `apps/api/src/infrastructure/config/env.schema.ts`**
Create Zod schema that validates required environment variables on startup:
```typescript
import { z } from 'zod';

export const envSchema = z.object({
DATABASE_URL: z.string().url().startsWith('postgresql://'),
DIRECT_URL: z.string().url().startsWith('postgresql://').optional(),
PORT: z.coerce.number().int().positive().default(3001),
NODE_ENV: z.enum(['development', 'production', 'test']).default('development'),
FRONTEND_URL: z.string().url().default('http://localhost:3000'),
AUTH_DEV_MODE: z.string().transform(v => v === 'true').default('false'),
LOG_LEVEL: z.enum(['debug', 'info', 'warn', 'error']).default('info'),
LOG_DIR: z.string().optional(),
});

export type EnvConfig = z.infer<typeof envSchema>;

export function validateEnv(): EnvConfig {
const result = envSchema.safeParse(process.env);
if (!result.success) {
console.error('Invalid environment configuration:');
console.error(result.error.format());
process.exit(1);
}
return result.data;
}

````

Create 4 Prisma repository implementations and their NestJS modules. Each repository:
1. Injects `PrismaService` via constructor
2. Implements the exact interface defined in the corresponding service file
3. Contains a private `toDomain()` mapper that transforms Prisma query results into the Zod domain shape
4. Returns data that satisfies the Zod schema the service layer will parse

**Pattern for each NestJS module (same for all 4):**

```typescript
import { Module } from "@nestjs/common";
import { XService } from "./x.service";
import { XPrismaRepository } from "./x.prisma-repository";

@Module({
  providers: [
    XPrismaRepository,
    {
      provide: XService,
      useFactory: (repo: XPrismaRepository) => new XService(repo),
      inject: [XPrismaRepository],
    },
  ],
  exports: [XService],
})
export class XModule {}
```

**ReviewPrismaRepository:**

- `getSubmissionDashboard(activeReportId)`: Query `reportSection` with `include: { author: true }` where `reportId = activeReportId`. Map each result to `SubmissionDashboardRow` shape: `{ leadId: section.authorId, leadName: section.author.name, status: section.status, submittedAt: section.submittedAt }`.

**ArchivePrismaRepository:**

- `listArchiveReports()`: Query `report` where `status = 'published'`, include `publishedBy`. Map to `ArchiveReportSummary`: `{ reportId: report.id, periodStart, periodEnd, publishedAt: report.publishedAt!, publishedByName: report.publishedBy?.name ?? 'Unknown' }`.
- `getArchiveReport(reportId)`: Query single report with all nested sections (same deep include as publication). Map to `ArchiveReportDetail`. This is a read-only view of a published report.

**PdfExportPrismaRepository:**

- `getPublishedReport(reportId)`: Query report where `id = reportId AND status = 'published'` with full nested sections include. Map to `AssembledReport` domain shape.
- `createExportJob(job)`: `prisma.pdfExportJob.create({ data: { reportId: job.reportId, status: job.status, requestedBy: job.requestedBy } })`. Map result to `PdfExportJob`.
- `getExportJob(jobId)`: `prisma.pdfExportJob.findUnique({ where: { id: jobId } })`. Map to `PdfExportJob | null`.
- `saveExportJob(job)`: `prisma.pdfExportJob.update({ where: { id: job.jobId }, data: { status: job.status, filePath: job.filePath, error: job.error } })`. Map to `PdfExportJob`.

**RemindersPrismaRepository:**

- `getRule(ruleId)`: `prisma.reminderRule.findUnique({ where: { id: ruleId } })`. Map to `AdminReminderRule`.
- `findExecutionByDedupeKey(dedupeKey)`: `prisma.reminderExecution.findUnique({ where: { dedupeKey } })`. Map to `AdminReminderExecution | null`.
- `saveExecution(execution)`: Use `upsert` with `dedupeKey` for deduplication. Map to `AdminReminderExecution`.
- `getExecution(executionId)`: `prisma.reminderExecution.findUnique({ where: { id: executionId } })`. Map to `AdminReminderExecution | null`.
- `listExecutions(ruleId)`: `prisma.reminderExecution.findMany({ where: { ruleId }, orderBy: { createdAt: 'desc' } })`. Map each to `AdminReminderExecution`.

CRITICAL: Each `toDomain()` mapper must match Zod schema field names exactly. Read the Zod schemas in `packages/shared/src/schemas/report.ts` to get exact field names. Prisma field names differ from domain field names (e.g., Prisma `id` may map to domain `jobId` or `ruleId`).
