<objective>
Fix 17 TypeScript Date/string serialization errors that block QA-03 (typecheck clean across monorepo).

Purpose: tRPC's httpBatchLink serializes `Date` objects to ISO strings over JSON, but Zod schemas use `z.coerce.date()` which infers TypeScript `Date` type. The frontend components receive `string` values at runtime but TypeScript expects `Date`, causing 17 TS2322/TS2352 errors across 6 page components. Adding superjson as the tRPC data transformer makes Date serialization/deserialization transparent — the inferred types match the runtime values.

Output: Zero TypeScript errors in both apps/web and apps/api, all 27 frontend tests passing, no type assertion workarounds.
</objective>

    WHY superjson: tRPC v11 with httpBatchLink serializes all data as JSON. JSON has no Date type — Date objects become ISO strings. superjson adds metadata alongside the JSON payload that tells the client which fields were originally Date objects, so the client can reconstruct them. This makes the TypeScript inferred types (`Date`) match the runtime values (also `Date` after superjson deserialization). The Zod schemas in packages/shared stay unchanged — `z.coerce.date()` correctly infers `Date` on both server and client.
