## Copywriting Contract

### Auth Error Page (`/auth/error`)

| Element                       | Copy                                                                                      |
| ----------------------------- | ----------------------------------------------------------------------------------------- |
| Page heading                  | `Authentication Error`                                                                    |
| Error: Keycloak unavailable   | `The authentication service is currently unavailable. Please try again in a few minutes.` |
| Error: Invalid SAML assertion | `Your login attempt could not be verified. Please try signing in again.`                  |
| Error: Generic/unknown        | `Something went wrong during sign-in. Please try again.`                                  |
| Primary CTA                   | `Try signing in again` (links to `/auth/saml/login`)                                      |
| Secondary link                | `Return to home` (links to `/`)                                                           |

**Error code display:** The page receives an error reason via query parameter (`/auth/error?reason=idp_unavailable`). The error message is selected based on the `reason` parameter. If no reason or unknown reason, show the generic message.

**Supported reason codes:**

| Query param `reason` | Displayed message                                 |
| -------------------- | ------------------------------------------------- |
| `idp_unavailable`    | Keycloak unavailable message                      |
| `invalid_assertion`  | Invalid assertion message                         |
| `session_expired`    | `Your session has expired. Please sign in again.` |
| (missing or unknown) | Generic error message                             |

### Loading States (tRPC queries)

| Element                               | Copy                                                          |
| ------------------------------------- | ------------------------------------------------------------- |
| Page-level loading                    | `Loading...` (plain text, centered in page content area)      |
| Inline loading (mutation in progress) | `Saving...` (replaces button text during mutation)            |
| Autosave indicator (existing)         | `Saving...` / `Saved` (no change from current implementation) |

**Loading pattern:** Every page that calls `trpc.*.useQuery()` MUST handle the `isLoading` state by rendering `<p>Loading...</p>` before rendering the main content. Use early return pattern:

```
if (isLoading) return <p>Loading...</p>;
if (isError) return <QueryError error={error} />;
return <MainContent data={data} />;
```

### Error States (tRPC queries)

| Element                         | Copy                                                                                     |
| ------------------------------- | ---------------------------------------------------------------------------------------- |
| Network error heading           | `Connection Error`                                                                       |
| Network error body              | `Could not reach the server. Check your connection and try again.`                       |
| Server error heading            | `Server Error`                                                                           |
| Server error body               | `Something went wrong. Please refresh the page or try again later.`                      |
| Auth error (401/UNAUTHORIZED)   | Redirect to `/auth/saml/login` (no visible error — just redirect)                        |
| Forbidden error (403/FORBIDDEN) | `You do not have permission to access this page. Contact your administrator for access.` |
| Retry CTA                       | `Retry` (button that calls `refetch()`)                                                  |

**Error pattern:** Create a reusable `<QueryError>` component that accepts a tRPC error and renders the appropriate message with a "Retry" button. All pages use this component for consistent error display.

### Destructive Actions

| Action                        | Confirmation approach                                                      |
| ----------------------------- | -------------------------------------------------------------------------- |
| Submit section (existing)     | Modal dialog: "Are you sure?" with "Confirm submit" / "Cancel" (no change) |
| Remove user (admin, existing) | No confirmation (no change from current implementation)                    |
| Logout                        | No confirmation needed (clears cookie, redirects to `/`)                   |

No new destructive actions introduced in Phase 6.

## Interaction States

### Auth Flow States

```text
Unauthenticated user visits protected page
    |
    v
Next.js middleware detects no cookie
    |
    v
Redirect to /auth/saml/login (NestJS)
    |
    v
NestJS redirects to Keycloak login page
    |
    v
User authenticates in Keycloak
    |
    +-- Success: SAML callback -> JWT cookie -> redirect to app
    |
    +-- Failure: redirect to /auth/error?reason=<code>
                    |
                    v
              Auth error page with "Try signing in again" button
```

### Page Loading States (new pattern for all pages)

Every page migrated from localStorage to tRPC gains three states:

| State   | What renders                            | Trigger                   |
| ------- | --------------------------------------- | ------------------------- |
| Loading | `<p>Loading...</p>`                     | `useQuery` initial fetch  |
| Error   | `<QueryError error={error} />`          | `useQuery` error response |
| Ready   | Full page content (existing components) | `useQuery` success        |

### Mutation Feedback States

| State   | What renders                                  | Trigger                   |
| ------- | --------------------------------------------- | ------------------------- |
| Idle    | Normal button text                            | Default                   |
| Pending | Button disabled + text changes to "Saving..." | `useMutation` `isPending` |
| Success | Original button text restored                 | `useMutation` `onSuccess` |
| Error   | Inline error text below the form/action       | `useMutation` `isError`   |

### Autosave Behavior (no change from v1.0)

The autosave indicator (`AutosaveIndicator` component) already handles `idle` / `saving` / `saved` states. In Phase 6, the `onSaveDraft` callback changes from localStorage to `trpc.reports.saveDraft.useMutation()`, but the indicator behavior is identical.
