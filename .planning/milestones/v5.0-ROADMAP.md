### Phase 24: Auth Guards & Session

**Goal:** Unauthenticated users are redirected to login; session context is available throughout the application

**Plans:** 1 plan

- [x] 24-01-PLAN.md — proxy.ts cookie guard + SessionProvider/useSession + 401 interceptor + login `?next=` + `auth.me` tRPC query

**Details:**

- `apps/web/proxy.ts` — Next.js 16 replacement for middleware.ts. Reads `NEXT_PUBLIC_AUTH_STUB` at request time; non-stub mode requires `customreport_session` cookie or 307 redirect to `/?next=<encoded>`. Matcher `/((?!_next|api|trpc|auth|favicon\.ico|$).*)` excludes login, callback, tRPC, REST, internals.

- 401 interceptor link in `trpc.ts` runs BEFORE `httpBatchLink`. Pure helper `createAuthRedirectHandler()` (separately exported for unit tests) detects `httpStatus===401 || code==='UNAUTHORIZED'`, exempts `^/(?:$|auth(?:/|$))`, calls `window.location.assign('/?next=<encoded>')`.
- Login page (`apps/web/src/app/page.tsx`): converted to client component to read `useSearchParams()`. `sanitizeNext()` rejects `'://'` and `'//'`-prefixed paths (open-redirect guard), falls back to `/head/dashboard`.

### Phase 25: Production Logging

**Goal:** Every API request is traceable through structured, file-persisted logs with correlation IDs
**Depends on:** Nothing (independent backend track)
**Requirements:** LOG-01..05
**Plans:** 1 plan

Plans:

- [x] 25-01-PLAN.md — nestjs-cls + async file rotation + tRPC request/response logging

**Details:**

- `nestjs-cls@^6.2.0` global module with `middleware.mount: true` and `generateId: false`, mounted before user middleware.
- `CorrelationIdMiddleware` injects `ClsService` and writes resolved id into store: `cls.set('correlationId', id)` alongside `req.headers['x-request-id']` and `res.setHeader('x-request-id', ...)`.
- `AppLoggerImpl` rewritten on file path: `fs.promises.appendFile` (no more `appendFileSync` on hot path); per-`logDir` promise queue serializes writes (prevents append/rotate interleaving). Active file always `<logDir>/app.log`; on threshold the file is gzip-streamed via `stream/promises.pipeline` into `app.log.<ISO-stamp>.gz` and `fs.truncate(activePath, 0)` keeps inode handle stable. Retention by mtime age (`maxAgeDays` default 30; `maxBytes` default 50 MiB).
- Every entry now includes `correlationId` from CLS when active, otherwise literal `'no-context'`. `child()` forwards `clsService` AND parent's file sink so child loggers don't race with parent on writes.
- tRPC `loggingMiddleware` chained into all 3 procedure helpers BEFORE auth (captures failed-auth attempts). Entry: `info('trpc request start', { phase, stage:'start', procedure, type, userId })`. Exit success/error with `duration` (performance.now → ms) and `status`.
- Decision: enhance existing logger rather than replace with pino (per CONTEXT.md "Don't Replace Logger"; service-level loggers across codebase already consume `AppLogger`).

## Milestone Summary

**Decimal Phases:** none.

**Key Decisions:**

| Decision | Rationale |
|----------|-----------|
| `auth.me` uses `publicProcedure` (D-24-01-A) | Returns `null` instead of throwing — prevents 401 interceptor loop on every page load |
| Single `app.log` + size-based gzip (D-Phase-25) | Simpler than daily-prefix scheme; predictable disk use; rotated archives by mtime |
| Logging middleware applied BEFORE auth | Captures failed-auth attempts for security forensics |
| Enhance existing `AppLoggerImpl` (not replace with pino) | Per CONTEXT.md; service-level loggers across codebase already consume `AppLogger` |
| SyncSource ref pattern (Pitfall 5 guard) | Deterministic infinite-loop prevention without time-based debounce |
| Self-contained mapper modules | Single source of truth; downstream consumers depend only on mapper, never both ends |
| `@trpc/tanstack-react-query` (not classic) | React Compiler compatibility |
| Optional 2nd-arg threading on `createExportJob` | Preserves backward compatibility with 4 stub repositories |
| Mount express.static at absolute resolved path | Same `resolve()` in main.ts AND processor.ts so worker writes and static mount agree regardless of cwd |
| `?next=` open-redirect sanitization (`sanitizeNext`) | Rejects `'://'` and `'//'` prefixes, falls back to `/head/dashboard` |
| Dual `webServer` Playwright config + config-load guard | Real-API testing without risk of dev-DB corruption |
| `context.request.get(...)` for cookie minting | Top-level `request` fixture has its own cookie jar; only `context.request` shares with browser page |
