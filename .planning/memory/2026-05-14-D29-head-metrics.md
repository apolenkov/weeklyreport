# D29 — Head Dashboard: где метрики по лиду, который уже заполнил отчёт?

**Дата:** 2026-05-14  
**Источник:** UAT «вот Артём лид — всё заполнял! а где ещё метрики?»

## Текущее состояние

Компонент `KpiCards` (`apps/web/src/components/dashboard/kpi-cards.tsx`)
показывает три карточки уровня периода:

1. **Submissions** — X/N лидов сдали, кольцевой индикатор %, счётчик ожидающих
2. **Deadline** — дедлайн с временной меткой
3. **Risks & Blockers** — суммарно: Blocked / At Risk / Decisions

Компонент `ProductKpiCard` дополняет данными по продуктам (telemetry summary).
`BlockedAtRiskTable` показывает список заблокированных / под-риском без разбивки
по автору секции.

**Чего нет:** разбивка по лиду — сколько у конкретного лида рисков, решений,
пунктов текущей недели. После сдачи секции его вклад «растворяется» в агрегатах.

## Рекомендация

Добавить блок **«Period Summary»** ниже `KpiCards`:
таблица-строки по лидам (имя, статус секции, кол-во элементов текущей недели,
рисков, решений, дата сдачи). Данные уже есть в `review.dashboard` /
`weeklyReport.get` — нужен маппер и компонент.

Альтернатива — расширить `ActivityLivePanel` перфокартами — но тогда
смешаются «живая активность» и «итоговые показатели», что сложнее читать.

## Компромисс

```
Отдельный блок «Period Summary» (таблица по лидам)
  + Отвечает на вопрос «кто что сдал и сколько» одним взглядом
  + Данные уже есть на бэке, только UI не отображает
  - Новый компонент ~100 строк + маппер

Расширение ActivityLivePanel
  + Меньше новых файлов
  - Смешивает события потока с агрегатами, труднее сканировать

Нет изменений
  - Руководитель вынужден открывать каждую секцию вручную
```

**Рекомендую:** отдельный `PeriodLeadSummaryTable` между `KpiCards`
и `AlertBar`.  
**Решение руководителя:** согласовать приоритет относительно D34 (viewer).
