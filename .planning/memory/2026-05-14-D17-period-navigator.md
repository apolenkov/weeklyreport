# D17 — Period Navigator: более информативная метка периода

**Дата:** 2026-05-14  
**Источник:** UAT «может период написать более конкретно?»

## Текущее состояние

Компонент `PeriodNavigator` (`apps/web/src/components/lead/period-navigator.tsx`)
показывает в `<select>` следующий формат:

```
{p.weekLabel} · {p.dateRange}{p.isCurrent ? " (current)" : ""}{p.isSubmitted ? " ✓" : ""}
```

Пример: `Week 20 · May 11-15 (current) ✓`

Данные приходят через `ReportPeriod` из `mock-data`; реальные значения
`weekLabel` и `dateRange` формируются в маппере.

## Проблема

`weekLabel` содержит только `Week 20`, без года.
При переходе между годами (декабрь-январь) неясно, к какому году относится
неделя. Также разделитель `·` (middot) в `<option>` может плохо
читаться в системных шрифтах некоторых OS.

## Рекомендация

Изменить формат метки на:

```
Week 20, May 11–15, 2026  (current) ✓
```

Конкретно — добавить год в `weekLabel` или `dateRange` в маппере (бэкенд),
заменить `·` на `,` в `<option>`, использовать `–` (en-dash) между датами
вместо `-` (дефис).

Дополнительно: вынести "(current)" из строки `<option>` в отдельный
badge рядом с `<select>` — это видно только при открытом dropdown,
но в закрытом состоянии пользователь не видит маркер.

## Компромисс

```
Расширенный формат (с годом, en-dash, бейдж)
  + Однозначность при межгодовых переходах
  + Бейдж "(current)" виден без открытия dropdown
  - Строка длиннее → нужно проверить truncation на mobile

Минимальный патч (только добавить год)
  + 5 минут работы в маппере
  - Не решает проблему видимости "(current)" в закрытом select
```

**Рекомендую:** расширенный формат + бейдж.  
**Решение руководителя:** утвердить или предпочесть минимальный патч.
