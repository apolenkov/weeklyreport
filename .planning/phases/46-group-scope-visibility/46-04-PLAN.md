# Phase 46-04 — Apply scope filter to weeklyReport.get + lead lookups

**Status:** ready
**Depends on:** 46-01 (helper)
**Requirement:** UFB-040

## Goal

`weeklyReport.get(reportId, session)` (the head's "Weekly Report" view) and
the lead lookups behind it (e.g. searches, project ownership) filter by
group scope. Same matrix as dashboard.

## Acceptance Criteria

- `weeklyReportService.get` (or the equivalent assembled-report path) takes session and applies `groupScopeFilter(session, 'reportSection')`
- `search.byScope` (already partially role-aware per `search.service.ts:63`) replaced with the canonical helper
- Lead lookups in `admin.snapshot` are admin-only post UFB-038 → no change needed there
- Project lookups (`projects.list`-equivalent) filter by `groupScopeFilter(session, 'project')`
- 660+ api tests stay green

## Steps

1. Find `weeklyReportService.get` (verify exact name in `apps/api/src/modules/weekly-report/`)
2. Apply scope filter to the section list it returns
3. Update tRPC callsite (`weeklyReport: router({...})` in trpc.router.ts) to pass `ctx.session`
4. Refactor `search.service.ts:63` block to use `groupScopeFilter` instead of inline role check
5. If a project-listing endpoint surfaces projects to non-admin callers, apply `groupScopeFilter(session, 'project')` there too
6. Test: head from group A cannot pull weekly-report sections of group B

## Verification Commands

```bash
pnpm --filter @customreport/api test -- weekly-report search
pnpm --filter @customreport/api test
```

## Out of Scope

- Lead form (already authorId-scoped)
- AI insights (separate per-section already)
- Carry-over (already carries within the same author)
