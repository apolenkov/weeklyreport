# Phase 46-02 — Apply scope filter to dashboard

**Status:** ready
**Depends on:** 46-01 (helper + UserSession.viewerGroupAccess)
**Requirement:** UFB-040

## Goal

`reviewService.getSubmissionDashboard(reportId, session)` returns only sections
that belong to leads inside the requester's allowed groups. Heads see only
their own group; viewers see only their granted groups; admin sees all.

## Acceptance Criteria

- `getSubmissionDashboard(reportId)` signature changes to `(reportId, session)`
- ReportSection query spreads `groupScopeFilter(session, 'reportSection')` into its where
- tRPC `weeklyReport.dashboard` callsite passes `ctx.session`
- Existing dashboard test fixture updated so a head from group A no longer sees lead-from-group-B sections
- Test added: dashboard call as viewer with empty `viewerGroupAccess` returns 0 sections (not error)
- 660+ api tests stay green

## Steps

1. Add `session` param to `getSubmissionDashboard` (tighten type to `Pick<UserSession, 'role' | 'reportingGroupId' | 'viewerGroupAccess'>` so unit tests don't need to forge the whole session)
2. In the Prisma query, `where: { reportId, ...groupScopeFilter(session, 'reportSection') }`
3. Update `apps/api/src/infrastructure/trpc/trpc.router.ts:301` (`dashboard:`) to pass `ctx.session`
4. Update `review.service.test.ts` — add fixtures for cross-group leak; assert filtered
5. Run full api test
