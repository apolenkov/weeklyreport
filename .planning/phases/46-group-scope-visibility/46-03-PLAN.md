# Phase 46-03 — Apply scope filter to archive list / detail

**Status:** ready
**Depends on:** 46-01 (helper)
**Requirement:** UFB-040

## Goal

`archive.list` returns published reports as before (Reports themselves are
global per period), but the **assembled view inside each report** filters
sections by the requester's group scope. `archive.detail(reportId)` does the
same. Viewers without access return zero sections; admin sees everything.

## Acceptance Criteria

- `archiveService.list(input, session)` adds session param
- Returned report rows still global (Week 18, Week 17, …); per-report section count is filtered for non-admin callers
- `archiveService.detail(reportId, session)` filters sections by `groupScopeFilter(session, 'reportSection')`
- Cross-group leak test: viewer Дарья can browse Week 18, but only sees sections from her granted groups
- 660+ api tests stay green

## Steps

1. Add `session` param to both `list` and `detail` archive methods
2. Apply scope filter to the Prisma `select` of nested `sections` (or post-filter in JS if select is too rigid)
3. Update tRPC callsites (`archive: router({...})` in trpc.router.ts) to pass `ctx.session`
4. Test: integration spec creates leads in two groups, publishes one report, asserts viewer with access to group A sees only group A sections
5. Update `archive.service.test.ts` to cover the new param

## Verification Commands

```bash
pnpm --filter @customreport/api test -- archive
pnpm --filter @customreport/api test
```

## Out of Scope

- Pagination math changes — page sizes still count Reports, not sections
- UI changes (Archive tab consumes whatever the API returns)
