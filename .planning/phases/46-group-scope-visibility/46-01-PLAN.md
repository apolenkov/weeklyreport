# Phase 46-01 — `groupScopeFilter` helper + UserSession extension

**Status:** ready
**Depends on:** UFB-039 schema (already shipped: ReportingGroup.headUserId, ViewerGroupAccess)
**Requirement:** UFB-040 (per-role group-scope visibility)

## Goal

Land the canonical group-scope helper + extend `UserSession` with
`viewerGroupAccess: string[]` so every downstream service in 46-02..46-05 can
spread an identical Prisma `where` fragment without re-deriving role logic.

## Acceptance Criteria

- `apps/api/src/lib/group-scope.ts` exports `groupScopeFilter(session, target)` returning a Prisma `where` fragment
- `target` accepts `'user' | 'reportSection' | 'project'`
- admin → `{}` (always); head/lead → `{ <field>: { in: [session.reportingGroupId] } }`; viewer → `{ <field>: { in: viewerGroupAccess } }`; viewer with empty access → `{ id: { in: [] } }` (returns zero rows)
- `UserSession` zod schema gains optional `viewerGroupAccess: string[]`
- `trpc.context.ts` hydrates `viewerGroupAccess` from `prisma.viewerGroupAccess.findMany({ where: { viewerUserId: session.userId }, select: { groupId: true } })` for viewer sessions only (no extra query for head/admin/lead)
- `apps/api/src/lib/group-scope.test.ts` covers all 4 roles × 3 targets matrix (12 cases) + viewer-with-empty-access edge case
- existing api tests stay green

## Steps

1. Create `apps/api/src/lib/group-scope.ts` per CONTEXT spec (helper + private `computeAllowedGroupIds`)
2. Extend `userSessionSchema` in `packages/shared/src/auth/...` with `viewerGroupAccess: z.array(z.string().uuid()).optional()`
3. In `apps/api/src/infrastructure/trpc/trpc.context.ts`, after building UserSession, branch on `session.role === 'viewer'` → load access ids → attach to session before returning
4. Write unit tests `apps/api/src/lib/group-scope.test.ts` covering:
   - admin × user → `{}`
   - admin × reportSection → `{}`
   - admin × project → `{}`
   - head × user → `{ reportingGroupId: { in: [own] } }`
   - head × reportSection → `{ author: { reportingGroupId: { in: [own] } } }`
   - head × project → `{ lead: { reportingGroupId: { in: [own] } } }`
   - lead × \* → same as head (lead is single-group)
   - viewer × user (with 2 access groups) → `{ reportingGroupId: { in: [g1, g2] } }`
   - viewer × user (with 0 access groups) → `{ id: { in: [] } }`
5. Run `pnpm --filter @customreport/api test` — assert green
