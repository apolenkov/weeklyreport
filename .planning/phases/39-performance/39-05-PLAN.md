<objective>
PERF-05: full-text search across Item / Risk / Decision / Project, surfaced
in `/lead/history` (scope='mine') and `/admin?tab=products` (scope='all').

User explicitly reversed the v8.0 scope decision documented in
PERF-AUDIT-2026-05 § 7 ("FTS — NOT NEEDED in v8.0"): once a search UI was
requested, the rationale (no consumer) no longer applies.

Implementation:

1. **Storage** — `Unsupported("tsvector")?` columns in Prisma schema; STORED
   generated columns populated from `to_tsvector('russian', ...)`; GIN index
   on each. Read-only from Prisma's perspective.
2. **Query** — single `$queryRaw` with four UNION ALL chunks (one per
   type), each ranked by `ts_rank` and snippeted by `ts_headline`, ordered
   globally by rank desc. `Prisma.sql` parameter binding for `q` + `userId`
   so no user input ever lands in raw SQL.
3. **Auth** — `scope='mine'` filters items/risks/decisions to
   `reportSection.authorId = userId`, projects to `leadId = userId`.
   `scope='all'` is server-gated: `SearchAuthorizationError` for non-
   head/admin sessions, mapped to TRPCError code FORBIDDEN.
4. **UI** — `<SearchInput scope=…>` debounces by 300ms, fires when
   `q.length >= 2`, renders a dropdown of hits below the input. Snippet
   markers (`<<…>>`) become `<mark>` elements; each hit deep-links to its
   source (item/risk/decision → `/lead/report?period=<reportId>` with
   section anchor; project → `/admin?tab=products&filter=<projectId>`).

Out of scope (deferred): `pg_trgm`-based prefix autocomplete; weighted ranks
across multiple fields; cross-period faceting.
</objective>
