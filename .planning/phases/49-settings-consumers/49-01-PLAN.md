# Phase 49-01 — Drop departmentName, finalize Organization migration

**Status:** ready
**Depends on:** Phase 48 (Organization model + landing + Settings tabs landed)
**Requirement:** complete the 48-A migration by removing the transitional `AppSettings.departmentName` column

## Goal

Finish the 48-A migration: replace every reader of
`AppSettings.departmentName` with `Organization.fullName` (or
`shortName` if it's a compact reference), then drop the
`departmentName` column. BullMQ email payloads currently still
include `departmentName` — switch them to `organization` shape.
After this plan: zero references to `departmentName` in source,
zero in DB, and emails render the org-supplied brand.

## Acceptance Criteria

- New migration `<timestamp>_drop_appsettings_departmentname` runs
  `ALTER TABLE "AppSettings" DROP COLUMN "departmentName"`.
- Zero source-tree matches for `departmentName` in
  `apps/api/src`, `apps/web/src`, `packages/shared/src`,
  `prisma/seed*.ts`, `prisma/wipe-manual-uat.ts`. (Migration SQL
  files that historically reference the column are exempt.)
- Shared `appSettingsSchema` loses the `departmentName` field. Any
  consumer that read it through the schema now reads
  `organization.fullName` (where the dashboard / weekly-report
  reuses the org from the session) or `organization.shortName`.
- BullMQ email-reminder payloads no longer carry `departmentName`.
  Instead, the payload includes `organization: { shortName, fullName }`
  populated at enqueue time from the same hydration path that
  `auth.me` uses.
- Email template body renders `organization.fullName` (or
  `shortName`) in the brand footer / subject — concrete substitution
  decided in the implementation; document the choice in SUMMARY.
- All existing api / web tests stay green; fixtures that used
  `departmentName` are rewired to use the `organization` shape.
- A grep-based audit step is part of the verification: the SUMMARY
  must include `grep -rln "departmentName" apps/{api,web}/src
packages/shared/src` output showing zero matches (excluding `.next`
  build artifacts and `apps/api/dist` compiled output).

## Steps

1. Inventory the 22 source files (the grep already ran — list saved
   in this CONTEXT). For each, classify the use:

   | use class           | example                                                                                              | replacement                                                                                                                         |
   | ------------------- | ---------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
   | UI label / heading  | `weekly-report-page.tsx`, `dashboard-page.tsx`                                                       | `org.fullName`                                                                                                                      |
   | Compact mention     | `lead-form.tsx` fallback `"Development"`                                                               | `org.shortName`                                                                                                                     |
   | Settings form input | `settings-tab.tsx`                                                                                   | (removed — Identity tab owns it now)                                                                                                |
   | Shared schema field | `report.ts:appSettingsSchema`                                                                        | (drop)                                                                                                                              |
   | API repo / service  | `admin.prisma-repository.ts`, `weekly-report.prisma-repository.ts`, `lead-form.prisma-repository.ts` | replace `prisma.appSettings.select({ departmentName })` with `prisma.organization.findUnique({ where: { id: 'singleton' } })` reads |
   | BullMQ payload      | (in `reminders.dispatch*` job code)                                                                  | swap field                                                                                                                          |
   | Tests / fixtures    | many                                                                                                 | rename fixture key                                                                                                                  |
   | Migrations          | (preserve historical)                                                                                | NO change                                                                                                                           |

2. Patch the shared schema (`packages/shared/src/schemas/report.ts`):
   - Remove `departmentName` from `appSettingsSchema`.
   - Remove `departmentName` from `weeklyReportSchema` if present
     (verify; otherwise the field is already org-sourced).
   - Update unit tests in `packages/shared/src/schemas/__tests__/report.test.ts`.

3. Patch backend services:
   - `admin.prisma-repository.ts`: drop departmentName from
     `getSettings()`/`updateSettings()` mappers.
   - `weekly-report.prisma-repository.ts` + `lead-form.prisma-repository.ts`:
     where they read `appSettings.departmentName` for the weekly
     header, swap to `organizationRepository.get()` (inject the org
     repo or pass the org through the service layer).

4. Patch BullMQ email job:
   - Locate enqueue / consume path (likely
     `apps/api/src/modules/reminders/reminders.dispatch.service.ts`
     or sibling).
   - At enqueue: include `organization: { shortName, fullName }` in
     the job data, sourced from `OrganizationService.get()`.
   - At consume: render `organization.fullName` in the email body
     (subject + signature). Drop the old `departmentName` read.

5. Patch frontend:
   - `weekly-report-page.tsx`: `departmentLabel = org.fullName`
     (using `auth.me.organization`).
   - `dashboard-page.tsx`: same.
   - `lead-form.tsx`: `{draftSection.departmentName ?? "Development"}` →
     `{org?.shortName ?? "Development"}`.
   - `settings-tab.tsx`: remove the legacy departmentName deprecation
     banner / input from the Periods tab.
   - `mappers/admin.ts`: remove departmentName from `MockSettings`.
   - `mock-data.ts`: remove the seed value.

6. Test fixtures: bulk rename `departmentName:` → drop or replace
   with `organization: { shortName: 'Demo', fullName: 'Example Software Department' }`
   in api + web fixtures.

7. Generate migration:

   ```bash
   pnpm exec prisma migrate dev --name drop_appsettings_departmentname
   ```

   The generated SQL should be just `ALTER TABLE "AppSettings" DROP
COLUMN "departmentName";`. Confirm no data-loss warnings.

8. Apply + regenerate Prisma client:

   ```bash
   pnpm exec prisma generate
   docker exec customreport-api-1 sh -c "cd /app && pnpm exec prisma generate"
   docker compose restart api web
   ```

9. Run all tests, expect green:
   - `pnpm --filter @customreport/api lint && pnpm --filter @customreport/api test`
   - `pnpm --filter @customreport/web lint && pnpm --filter @customreport/web test`
   - shared package tests

10. Manual smoke:
    - `curl http://localhost:3002/trpc/org.getPublic` still returns
      Demo / Example Software Department.
    - Open `/admin?tab=settings` — Identity tab unchanged; Periods
      tab no longer shows the departmentName deprecation banner.
    - Trigger a reminder dispatch (via admin UI or scheduler) — verify
      the email body / subject uses the org brand.
