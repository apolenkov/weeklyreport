# Phase 44-03 — Period.create hook + backfill cron

**Status:** ready
**Depends on:** 44-01 (schema), 44-02 (service-layer)
**Requirement:** NOTIF-06 (autogen on Period.create)

## Goal

When a `ReportPeriod` is created (via admin UI or tRPC), automatically generate
one `ReminderRule` per active `ReminderPolicy` with `fireAt` resolved as
`period.deadline + policy.offsetMinutes` in `policy.timezone`. Backfill the
same logic for already-open Periods so existing data is covered. After this
plan: admins create Policies once and the per-period plumbing is invisible.

## Acceptance Criteria

- A `PolicyApplicator` service (or equivalent) computes `fireAt` for `(period, policy)` pairs using DST-correct math (Luxon)
- `PeriodService.create(...)` (or whatever creates `ReportPeriod` rows) calls the applicator after the create transaction commits
- `applyToPeriod(period)` is idempotent — calling twice produces zero duplicate `ReminderRule` rows (uniqueness on `(reportId, policyId)`)
- A one-shot backfill script `prisma/backfill-policy-rules.ts` runs against every open Period, attaches rules for each active policy, and is safe to re-run
- `apps/api/src/modules/reminders/reminders.scheduler.ts` is **untouched** — it still queries `ReminderRule.findMany` and fires
- All existing reminders integration tests still pass

## Steps

1. Add unique constraint to schema in a follow-up migration:

   ```prisma
   model ReminderRule {
     // …
     @@unique([reportId, policyId], map: "uq_rule_report_policy")
   }
   ```

   (Cannot live in 44-01 because 44-01 leaves `policyId` nullable; this constraint is `(reportId, policyId)` which still allows NULL `policyId` for legacy rows.)

2. Install Luxon for TZ-aware date math:

   ```bash
   pnpm --filter @customreport/api add luxon
   pnpm --filter @customreport/api add -D @types/luxon
   ```

   (Verify Luxon is not already pulled in transitively before adding.)

3. Create `apps/api/src/modules/reminders/policy-applicator.service.ts`:

   ```ts
   import { DateTime } from 'luxon';
   // …
   computeFireAt(deadline: Date, offsetMinutes: number, tz: string): Date {
     return DateTime.fromJSDate(deadline, { zone: 'utc' })
       .setZone(tz)
       .plus({ minutes: offsetMinutes })
       .toUTC()
       .toJSDate();
   }

   async applyToPeriod(period: ReportPeriod): Promise<void> {
     const policies = await this.prisma.reminderPolicy.findMany({ where: { active: true } });
     const reports = await this.prisma.report.findMany({ where: { periodId: period.id } });
     for (const report of reports) {
       for (const policy of policies) {
         const fireAt = this.computeFireAt(period.deadline, policy.offsetMinutes, policy.timezone);
         await this.prisma.reminderRule.upsert({
           where: { uq_rule_report_policy: { reportId: report.id, policyId: policy.id } },
           create: { reportId: report.id, policyId: policy.id, fireAt, kind: policy.kind, active: true },
           update: { fireAt, kind: policy.kind, active: policy.active },
         });
       }
     }
   }
   ```

4. Locate the Period.create call site (likely `apps/api/src/modules/admin/admin.service.ts` `savePeriod` upsert path) and append:

   ```ts
   if (created) await this.policyApplicator.applyToPeriod(period);
   ```

   Run after the create transaction so a failed apply doesn't roll back the Period.

5. Create `prisma/backfill-policy-rules.ts`:

   ```ts
   // For every ReportPeriod where the deadline is in the future,
   // call PolicyApplicator.applyToPeriod(period). Logs counts.
   ```

   Wire into `package.json` as `db:backfill:reminder-policies`.

6. Run backfill once locally:

   ```bash
   pnpm db:backfill:reminder-policies
   docker exec customreport-postgres-1 psql -U customreport -d customreport_dev \
     -c "SELECT count(*) FROM \"ReminderRule\" WHERE \"policyId\" IS NULL;"
   # expect: 0 (every rule now has a policy after backfill + autogen)
   ```

7. Add integration test `reminders.policy-applicator.test.ts`:
   - Create policy (deadline, T-24h, Europe/Moscow)
   - Create Period with deadline `2026-06-01T18:00:00Z`
   - Assert `ReminderRule.fireAt` = `2026-05-31T15:00:00Z` (deadline 21:00 MSK − 24h = 21:00 MSK previous day = 18:00 UTC)
   - Add a DST boundary case (March 30 / October 26)
