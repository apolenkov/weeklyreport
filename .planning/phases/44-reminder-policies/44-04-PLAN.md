# Phase 44-04 — UI rework: Reminders Tab

**Status:** ready
**Depends on:** 44-02 (tRPC contract), 44-03 (autogen so derived rules exist)
**Requirement:** UFB-036 (admin must configure once, not per period)

## Goal

Rebuild `apps/web/src/components/admin/reminders-tab.tsx` to be a **policy
editor**, not a per-period rule editor. Top: list of policies + add/edit form.
Below each policy: collapsible "Active rules per period" panel showing the
auto-derived `ReminderRule[]` filtered by `policyId` (read-only).

## Acceptance Criteria

- Reminders Tab shows a list of `ReminderPolicy` rows (kind, offset, timezone, audience, active)
- Add/Edit form fields: kind (select), offset (numeric input + "before/after deadline" toggle), timezone (reuse `TIMEZONE_OPTIONS` from UFB-035 commit `301f366`), audience (select), active (toggle)
- Save button calls `admin.savePolicy` mutation
- Each policy row has an expander showing per-period derived rules (read-only) with `fireAt`, `kind`, status badge
- Removing a policy: confirm dialog warns "this will delete N derived rules" with the count
- Empty state: "No active reminder policies. Create one to start sending reminders."
- All existing tests pass; new test covers list + form interaction

## Steps

1. Refactor `reminders-tab.tsx` props:
   ```ts
   type RemindersTabProps = {
     readonly policies: ReminderPolicy[];
     readonly derivedRulesByPolicyId: Record<string, MockReminder[]>;
   };
   ```
2. Strip the per-period form path (kind + reportId + fireAt + timezone). Keep the existing `TIMEZONE_OPTIONS` constant.
3. Add policy form. Layout:
   ```
   [kind: deadline ▾]  [offset: 24] [before deadline ▾]  [tz: Europe/Moscow ▾]  [audience: lead-with-draft ▾]  [active ☑]
                                                                                                      [Save]
   ```
4. Render policies list:
   ```tsx
   <table>
     <thead>
       <tr>
         <th>Kind</th>
         <th>Offset</th>
         <th>Timezone</th>
         <th>Audience</th>
         <th>Status</th>
         <th>Actions</th>
       </tr>
     </thead>
     <tbody>
       {policies.map((p) => (
         <tr key={p.id}>
           <td>{p.kind}</td>
           <td>{formatOffset(p.offsetMinutes)}</td> {/* "T-24h" / "T+2h" */}
           <td>{p.timezone}</td>
           <td>{p.audience}</td>
           <td>
             <Badge>{p.active ? "Active" : "Disabled"}</Badge>
           </td>
           <td>
             <EditButton /> <RemoveButton onClick={() => confirmRemove(p)} />
           </td>
         </tr>
       ))}
     </tbody>
   </table>
   ```
5. Below each row, conditional `<DerivedRulesPanel policyId={p.id} rules={derivedRulesByPolicyId[p.id]} />` with toggle button.
6. Wire mutations:
   ```ts
   const saveMut = trpc.admin.savePolicy.useMutation({
     onSuccess: invalidateAdmin,
   });
   const removeMut = trpc.admin.removePolicy.useMutation({
     onSuccess: invalidateAdmin,
   });
   ```
7. Update parent page (`apps/web/src/app/(app)/admin/page.tsx` or wherever AdminSnapshot is consumed) to derive `policies` and `derivedRulesByPolicyId` from the snapshot and pass them down.
8. Update `apps/web/src/components/admin/reminders-tab.test.tsx`:
   - Remove tests asserting the old per-period form
   - Add tests: render policy list, click "New Policy", fill form, assert mutation called with correct shape
   - Add: click expander on a policy row → derived rules render

## Out of Scope

- Bulk policy import / export
- Per-group policy variants (v9.0)
- Editing individual derived rules (they're read-only by design — edit the policy instead)
- Visual styling beyond reusing existing TabHeader + table classes (UFB-026 standardization holds)
