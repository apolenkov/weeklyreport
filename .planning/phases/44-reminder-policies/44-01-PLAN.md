# Phase 44-01 — Prisma schema + data migration

**Status:** ready
**Depends on:** none (first plan in phase)
**Requirement:** UFB-036 (Reminder Policy model)

## Goal

Land the `ReminderPolicy` Prisma model + nullable `policyId` FK on `ReminderRule`,
and backfill existing rule rows by deduping on `(kind, offsetMinutes-derived,
timezone)`. After this plan: schema migrated, every existing rule has a
`policyId`, no behavior change downstream (scheduler still fires the same way).

## Acceptance Criteria

- `prisma/schema.prisma` declares `ReminderPolicy` and adds optional `policyId` + relation to `ReminderRule`
- `ReminderAudience` enum added (`lead-with-draft`, `head-of-late`)
- Migration `prisma/migrations/<timestamp>_reminder_policies/` exists and runs idempotently against `pnpm db:reset:hard`
- Backfill SQL produces ≥1 `ReminderPolicy` row per unique `(kind, offsetMinutes-from-existing-fireAt-vs-period.deadline, timezone)` tuple, with `policyId` populated on every existing `ReminderRule`
- `pnpm prisma generate` runs clean; no codegen drift in `apps/api/src/__generated__/` (or wherever Prisma client lands)
- Existing reminders integration test (`reminders.integration.test.ts`) still green

## Steps

1. Edit `prisma/schema.prisma`:
   - Add `enum ReminderAudience { LEAD_WITH_DRAFT HEAD_OF_LATE }`
   - Add `model ReminderPolicy { id, kind, offsetMinutes, timezone, audience, active, createdAt, updatedAt, rules ReminderRule[] }`
   - On `ReminderRule`: add `policyId String?` and `policy ReminderPolicy? @relation(...)` + index `@@index([policyId])`
2. Generate migration: `pnpm --filter @customreport/api exec prisma migrate dev --name reminder_policies`
3. Hand-edit the generated SQL to append a backfill block:

   ```sql
   -- Backfill: derive one ReminderPolicy per unique (kind, derived_offset_minutes, timezone)
   -- where derived_offset_minutes = round((fireAt - period.deadline) / interval '1 minute')
   -- (uses the rule's existing fireAt and the FK-linked Report's period.deadline)
   INSERT INTO "ReminderPolicy" (id, kind, "offsetMinutes", timezone, audience, active)
   SELECT DISTINCT
     gen_random_uuid(),
     r.kind,
     EXTRACT(EPOCH FROM (r."fireAt" - rp.deadline)) / 60,
     COALESCE(r.timezone, 'Europe/Moscow'),
     CASE WHEN r.kind = 'escalation' THEN 'HEAD_OF_LATE' ELSE 'LEAD_WITH_DRAFT' END,
     true
   FROM "ReminderRule" r
   JOIN "Report" rep ON rep.id = r."reportId"
   JOIN "ReportPeriod" rp ON rp.id = rep."periodId"
   ON CONFLICT DO NOTHING;

   -- Set policyId on each existing rule by matching tuple
   UPDATE "ReminderRule" r
   SET "policyId" = p.id
   FROM "ReminderPolicy" p, "Report" rep, "ReportPeriod" rp
   WHERE rep.id = r."reportId"
     AND rp.id = rep."periodId"
     AND p.kind = r.kind
     AND p."offsetMinutes" = ROUND(EXTRACT(EPOCH FROM (r."fireAt" - rp.deadline)) / 60)
     AND p.timezone = COALESCE(r.timezone, 'Europe/Moscow')
     AND r."policyId" IS NULL;
   ```

4. Verify backfill on a fresh `pnpm db:reset:hard`:

   ```bash
   pnpm db:reset:hard
   docker exec customreport-postgres-1 psql -U customreport -d customreport_dev \
     -c "SELECT count(*) FROM \"ReminderPolicy\"; SELECT count(*) FROM \"ReminderRule\" WHERE \"policyId\" IS NULL;"
   # expect: ≥1 policies, 0 orphan rules
   ```

5. Run existing reminders test suite: `pnpm --filter @customreport/api test -- reminders`
