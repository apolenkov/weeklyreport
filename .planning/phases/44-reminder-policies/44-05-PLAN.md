# Phase 44-05 — Tests + audit log

**Status:** ready
**Depends on:** 44-02 (service), 44-03 (applicator), 44-04 (UI)
**Requirement:** UFB-036, NOTIF-06

## Goal

Lock in the policy model with a test suite covering contract, integration, and
UI; emit audit-log events for policy mutations so the action log surfaces who
changed what when.

## Acceptance Criteria

- `reminders.policy.contract.test.ts`: zod schema parses valid input, rejects malformed (negative-zero offset, empty timezone, unknown audience)
- `reminders.policy.integration.test.ts`: full create-policy → create-period → assert-rule pipeline; includes one DST boundary case (March 30 Moscow → tz transition) and one zero-policies case (creating Period without active policies → zero new rules)
- `reminders-tab.test.tsx`: render list, open form, fill kind+offset+tz+audience, click Save, assert `admin.savePolicy.mutation` called with correct shape; click remove → confirm dialog → assert `admin.removePolicy.mutation` called
- `audit-logger.ts` exports `policySave({userId, policyId, kind, action})` and `policyRemove({userId, policyId})` helpers
- `admin.service.savePolicy` and `removePolicy` invoke the audit helpers
- New audit events visible in Admin → Action Log tab

## Steps

1. Add audit helpers in `apps/api/src/lib/audit-logger.ts`:
   ```ts
   policySave: (args: { userId: string; policyId: string; kind: ReminderKind; action: 'create' | 'update' }) =>
     this.emit('admin.policy.save', { ... }),
   policyRemove: (args: { userId: string; policyId: string }) =>
     this.emit('admin.policy.remove', { ... }),
   ```
2. Wire calls into `admin.service.ts` `savePolicy` (detect create vs update via existence check before upsert) and `removePolicy`
3. Write `apps/api/src/modules/reminders/reminders.policy.contract.test.ts` covering zod parse cases
4. Write `apps/api/src/modules/reminders/reminders.policy.integration.test.ts`:
   - Setup: spin up Prisma test DB, seed one head user
   - Test 1: create policy `(deadline, -1440 min, Europe/Moscow, lead-with-draft)` → create Period (deadline `2026-06-01T18:00:00Z`) → assert one ReminderRule per Report in that Period with `fireAt = 2026-05-31T18:00:00Z`
   - Test 2: DST boundary — Period deadline `2026-03-30T18:00:00Z` (Moscow does not observe DST anymore but the test exists to lock the math regardless)
   - Test 3: create Period with zero active policies → assert zero new rules
   - Test 4: re-run applicator on same period → assert idempotent (no duplicate rules)
5. Rewrite `apps/web/src/components/admin/reminders-tab.test.tsx` per 44-04 acceptance criteria
6. Update `apps/web/src/components/admin/action-log-tab.test.tsx` (if it asserts known event types) to include `admin.policy.save` and `admin.policy.remove`
7. Run full test suite:
   ```bash
   pnpm --filter @customreport/api test
   pnpm --filter @customreport/web test
   ```
8. Manual smoke: log into admin → create policy → check Action Log tab shows the event
