<objective>
ANAL-02 (leadVelocity) and ANAL-03 (periodComparison) extend the analytics module from 30-01 with two more procedures used by the /reports/trends RSC page in 30-03. Both reuse the AnalyticsCache (invalidated by PeriodService.publishPeriod/reopenPeriod from 30-01) and AnalyticsRepository contract.

The hard problem is TZ stability per CONTEXT.md D-2: server-side `new Date(periodEnd).toISOString().slice(0,10)` is TZ-stable only because Date.toISOString returns UTC, but if any code path uses `.toLocaleDateString()` or constructs a Date from a string without explicit `Z` suffix, the label drifts under different process.env.TZ. This plan locks the contract via a vitest spec that flips TZ between Europe/Moscow and UTC.

Out of scope: chart components (30-03), the /reports/trends page (30-03), any UI work.
</objective>

    Step 3.1 — Create the spec — a pure function over fixture data, executed twice with `process.env.TZ` flipped via `vi.stubEnv`:

    ```typescript
    import { describe, it, expect, beforeEach, afterEach, vi } from 'vitest';
    import { AnalyticsService } from './analytics.service.js';
    import type { AnalyticsRepository } from './analytics.service.js';

    const fixedFixture = {
      // ISO date-only strings — server-side toISOString().slice(0,10) is UTC,
      // so identical labels MUST come back regardless of process.env.TZ.
      periods: ['2026-04-21', '2026-04-28'],
      rows: [
        { projectId: '11111111-1111-1111-1111-111111111111', projectName: 'P', statuses: ['green' as const, 'red' as const] },
      ],
    };

    function fakeRepo(): AnalyticsRepository {
      return {
        async trafficLightHistory() {
          return fixedFixture;
        },
        async leadVelocity() {
          return [
            { periodLabel: '2026-04-21', leads: [] },
            { periodLabel: '2026-04-28', leads: [] },
          ];
        },
        async periodComparison() {
          return { rows: [] };
        },
      };
    }

    function noopCache() {
      return {
        async getOrCompute<T>(_k: string, fn: () => Promise<T>) {
          return fn();
        },
      };
    }

    function snapshotLabels(out: { periods: string[] }) {
      return out.periods.join('|');
    }

    describe('Analytics labels are TZ-stable', () => {
      let originalTZ: string | undefined;
      beforeEach(() => {
        originalTZ = process.env.TZ;
      });
      afterEach(() => {
        if (originalTZ === undefined) delete process.env.TZ;
        else process.env.TZ = originalTZ;
      });

      it('produces identical labels under Europe/Moscow and UTC', async () => {
        const svc = new AnalyticsService(fakeRepo(), noopCache());
        const inputs = { periodFrom: '2026-04-01', periodTo: '2026-04-30' };

        process.env.TZ = 'Europe/Moscow';
        const moscow = await svc.trafficLightHistory(inputs);
        const moscowLV = await svc.leadVelocity(inputs);

        process.env.TZ = 'UTC';
        const utc = await svc.trafficLightHistory(inputs);
        const utcLV = await svc.leadVelocity(inputs);

        expect(snapshotLabels(moscow)).toBe(snapshotLabels(utc));
        expect(moscowLV.map((r) => r.periodLabel)).toEqual(utcLV.map((r) => r.periodLabel));
      });
    });
    ```

    Step 3.2 — Note in test header: this test asserts the contract; since the fakeRepo returns pre-computed labels, the real defense is the Prisma repo using `.toISOString().slice(0,10)` exclusively. Document that in code comments.
