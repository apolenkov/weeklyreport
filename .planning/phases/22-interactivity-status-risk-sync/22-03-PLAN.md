<objective>
Make Period Navigators URL-driven (no schema changes to backend) and replace any hardcoded list lengths with real cursor pagination via TanStack Query's useInfiniteQuery for archive list and version history.

Purpose: INT-08 (cursor pagination) and INT-09 (period nav) are independent of mutation wiring. This plan is parallel-safe with 22-01 + 22-02 because it touches a disjoint set of files.

Output: A URL-driven period navigator (head side routes to /reports/[reportId]; lead side updates ?period= query param), a generic cursor-pagination hook, and the archive list + version history wired to it.

Important constraint (per 21-04 SUMMARY): `weeklyReport.get` does NOT accept a period filter at v5.0. Path (a) chosen explicitly: Period Navigator (head side) routes to /reports/[reportId] and the existing reportId-based query handles the data. Lead-side period navigator uses the period URL param ONLY to render a read-only banner — past periods are NOT data-fetched in this plan (deferred until/unless backend gains a period filter). This is documented per the advisor's guidance.
</objective>
