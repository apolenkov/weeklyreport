<objective>
Wire `prisma generate` into the install + build lifecycle so a fresh checkout never requires the manual incantation. Two surfaces, both required:

1. **Local / dev**: `apps/api/package.json` `postinstall` hook fires after `pnpm install` and produces `@prisma/client` types.
2. **CI**: `turbo.json` declares a `db:generate` task that `build` depends on for `@customreport/api`. CI environments commonly run `pnpm install --ignore-scripts` for security; the Turbo predecessor catches that case.

Per CONTEXT.md D-QA-02: scoped to `apps/api`, NOT root, so users only touching `apps/web` or `packages/shared` do not pay the Prisma generate cost.

Purpose: eliminate "did you run prisma generate?" as an onboarding/CI failure mode.
Output: package.json delta + turbo.json delta + verification of fresh-install flow.
</objective>

      Add a `db:generate` script and a `postinstall` script that calls it. Insert into the existing `scripts` object alongside `dev`/`build`/`lint`/`typecheck`/`test`:
        `"db:generate": "prisma generate"`
        `"postinstall": "prisma generate"`
      Both run the same command — `db:generate` is the named task Turbo will reference; `postinstall` is the npm-lifecycle hook pnpm fires after install.
      Order/formatting must match existing JSON style (2-space indent, trailing comma policy of the file). Use Edit, do NOT rewrite the whole file.

      Confirm: `prisma` is invokable in `apps/api` because `@prisma/client` is a transitive dep that ships the CLI, OR because `prisma` is a devDependency.     Step 2 — `turbo.json`:
      Add a `db:generate` task entry. Update the existing `build` task to declare `db:generate` as a predecessor (in addition to the existing `^build`). The result should look like:

      ```json
      {
        "$schema": "https://turbo.build/schema.json",
        "tasks": {
          "build": {
            "dependsOn": ["^build", "db:generate"],
            "outputs": [".next/**", "dist/**"]
          },
          "db:generate": {
            "cache": false,
            "outputs": ["../../node_modules/.prisma/**", "../../node_modules/@prisma/client/**"]
          },
          "dev": { "cache": false, "persistent": true },
          "lint": { "dependsOn": ["^lint"] },
          "typecheck": { "dependsOn": ["^typecheck", "db:generate"] },
          "test": { "dependsOn": ["^test"], "outputs": ["coverage/**"] }
        }
      }
      ```

      Notes:
      - `db:generate` is `cache: false` because Prisma's own caching is sufficient and the generated client lives in `node_modules` (outside Turbo's normal output assumptions).
      - `typecheck` also depends on `db:generate` — without generated types, `tsc` fails. This catches CI runs that `--ignore-scripts` and then `turbo typecheck` directly.
      - The `outputs` on `db:generate` are best-effort declarations of where Prisma writes; Turbo will not actually cache them since `cache: false`, but the entries document intent for future readers.

    Use Edit on both files — do not Write a full overwrite (preserves any other JSON conventions in the repo).
