# Phase 19 Plan 01 — API Reference Documentation

## Objective

Generate a complete API reference document covering all tRPC endpoints with
input/output schemas, authentication requirements, and example payloads.

## Deliverable

`docs/API-REFERENCE.md` — single-file API reference

## Structure

### For each tRPC namespace

```markdown
## reports.getActive

**Auth:** protectedProcedure (any authenticated role)
**Type:** query
**Input:** none
**Output:** ReportSectionReadModel | null

Returns the active report section for the authenticated user.
```

### Namespaces to document (~30 endpoints)

1. **reports** — getActive, myHistory, saveDraft, submit
2. **review** — dashboard, assembledReport, publish
3. **pdfExport** — request, status
4. **admin** — snapshot, saveUser, saveProject, savePeriod, saveReminderRule,
   deleteUser, deleteProject, deleteReminderRule, getSettings, updateSettings,
   saveStageAssignment, deleteStageAssignment, listStageAssignments
5. **archive** — list, detail
6. **reminders** — execute, listExecutions
7. **carryOver** — execute
8. **period** — publish, reopen
9. **weeklyReport** — get
10. **leadForm** — byPeriod, fillFrom, versions, restoreVersion, revoke,
    requestReopen

### Also document

- Auth routes: `/auth/saml/login`, `/auth/saml/callback`, `/auth/logout`,
  `/auth/dev-login`
- Health endpoints: `/health/live`, `/health/ready`, `/metrics`
- Shared Zod schemas used in contracts

## Step 1 — Generate from Code

Read `trpc.router.ts` and extract all procedure definitions.
Read `packages/shared/src/schemas/report.ts` for input/output types.

## Step 2 — Write Reference

Create `docs/API-REFERENCE.md` with:

- Table of contents
- Authentication section (JWT, SAML, dev bypass)
- Endpoint reference grouped by namespace
- Error codes and handling

## Exit Criteria

1. `docs/API-REFERENCE.md` covers all ~30 endpoints
2. Each endpoint has: auth, type, input shape, output shape, description
3. Shared schemas referenced correctly

## Estimated Scope

- 1 file created (~600 lines)
