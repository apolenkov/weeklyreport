<objective>
AUTH-07 closes the layout-level role gap: today, hitting `/admin` as a viewer renders the admin shell + a flash of unauthorized content before any tRPC error surfaces. This plan moves the gate up the request lifecycle — each `(app)/{admin,head,lead,reports}/layout.tsx` becomes an async server component that reads `auth.me` via the server-side tRPC caller and renders a 403 page when the role does not match the route's required set. The user never sees the protected layout chrome.

This is plan 29-03 because per CONTEXT.md sequencing it depends on AUTH-02 (29-02): the layout reads `session.role` from a JWT that the SAML strategy now guarantees is populated. The layout WILL render a 403 in the staged-removal world too — when `AUTH_DEV_MODE_ALLOW_TEST=true` paints session.role='head' (CC-2), all four layouts pass the head check and Phase 28's integration suite remains green.

Per CONTEXT.md success criterion 3 ("proxy.ts stays cookie-presence only"): `apps/web/proxy.ts` is NOT touched. Per CC-6 PITFALLS, proxy.ts continues to redirect anonymous traffic to `/auth/login` based on cookie presence; the JWT-aware role check lives in the Node-runtime layout, never in Edge.

The 403 page is a single shared component — `apps/web/src/components/forbidden-page.tsx` — composed into each layout via inline branching. There is intentionally NO `apps/web/src/app/_403/page.tsx` (Next.js does not auto-route `_403`); putting it as a sibling component keeps the seam at the layout, which is where the role check actually happens.

Out of scope for this plan: navigation hides (29-06 — last per CC-1), full SAML cut-over (29-04), audit emit (29-01), escalation digest (29-05). The layout gate's audit emit (role-denied at SSR time) is deferred to a follow-up because the AUTH-08 logger lives on the API side; emitting from web SSR would require a new tRPC mutation. Per CONTEXT.md the 29-01 audit covers the API surface — UI 403 renders are not in the AUTH-08 scope.
</objective>

    Step 2.1 — Create `apps/web/src/lib/server/get-server-session.ts`:

    ```typescript
    import 'server-only';
    import { cookies } from 'next/headers';
    import { createServerCaller } from '../trpc/server-caller'; // existing or new — confirm path
    import type { UserSession } from '@customreport/shared';

    export async function getServerSession(): Promise<UserSession | null> {
      const jar = await cookies();
      const token = jar.get('customreport_session')?.value;
      if (!token) return null;
      try {
        const caller = createServerCaller(token);
        const session = await caller.auth.me();
        return session;
      } catch {
        return null;
      }
    }
    ```
