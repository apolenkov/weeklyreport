<objective>
AUTH-01 (full) flips the production auth path from `AUTH_DEV_MODE=true` to real Keycloak SAML. Phase 28 staged this with `AUTH_DEV_MODE_ALLOW_TEST=true` (CC-2 PITFALLS). This plan completes the cut-over: prod code paths only trust SAML, integration tests run against a mock Keycloak container, and a boot-time fence prevents the dev fallback from ever shipping outside `NODE_ENV==='test'|'development'`.

Per CONTEXT.md the suggested sequencing puts this AFTER 29-02 (JWT role claim) and 29-03 (SSR layout gate) because both are prerequisites: the SAML strategy must already produce a valid role claim (29-02) before the production path becomes the only path, and the layout-level role gate (29-03) must already be in place because removing DEV_SESSION means real users will hit real role checks. Per CC-1 (ordering), this plan ships BEFORE 29-06 (navigation hide) — cosmetic UI hides cannot ship before the actual auth cut-over.

The mock Keycloak container in `docker-compose.test.yml` is the test harness's only auth source. It loads `infra/keycloak/realm-export.json` (created in 29-02) at startup and binds 4 fixture users (lead/head/admin/viewer). Playwright's existing `global-setup.ts` is rewritten to perform a real SAML AuthnRequest against the mock — no more DEV_SESSION cookie writes.

Critical canary: the 21/21 Phase 26 integration suite must stay green. If this plan breaks them, the rollback is the priority — this is the fence Phase 28 / Plan 28-02 deliberately put in place by NOT removing DEV_SESSION mid-flight.

Out of scope for this plan: navigation hides (29-06 — last per CC-1), escalation digest (29-05), audit emit (29-01).
</objective>
