<objective>
AUTH-02 makes the JWT role claim a typed, enforced contract end-to-end: Keycloak SAML attribute mapper emits `role`, the SAML strategy parses it through a Zod schema, the JWT carries it, and `ctx.session.role` is populated for every tRPC procedure. Per A-2 (PITFALLS.md §1), the most dangerous failure mode is silent over-grant through `undefined` — that fails closed in this plan: schema-level rejection on missing/unrecognised role.

This is plan 29-02 because it is the foundation for 29-03 (SSR layout gate reads `ctx.session.role`) and 29-04 (full SAML cut-over removes the dev fallback). Only the SAML production path goes through the new strict schema. Phase 29-04 retires the dev fallbacks once the mock IdP container is wired.

It is NOT loaded at app boot; it is the source of truth for "what Keycloak must be configured to send".

    ```typescript
    import { z } from 'zod';

    export const ROLE_VALUES = ['lead', 'head', 'admin', 'viewer'] as const;
    export type Role = (typeof ROLE_VALUES)[number];

    /**
     * Strict schema for the SAML assertion profile we accept from Keycloak.
     * Per AUTH-02 / PITFALLS A-2: role is REQUIRED, not defaulted; case is
     * normalised to lowercase before enum check so a Keycloak misconfiguration
     * that emits 'HEAD' still parses successfully.
     */
    export const SamlProfileSchema = z
      .object({
        nameID: z.string().min(1),
        email: z.string().email(),
        displayName: z.string().optional(),
        role: z
          .string()
          .transform((s) => s.toLowerCase())
          .pipe(z.enum(ROLE_VALUES)),
      })
      .strict();

    export type SamlProfile = z.infer<typeof SamlProfileSchema>;
    ```

    Note `.strict()` so any extra Keycloak attribute (samlAssertion XML, sessionIndex, etc.) is dropped — prevents accidental leak into JWT.

    ```typescript
    export function createSamlStrategy(options: SamlStrategyOptions): SamlStrategy {
      const verify: VerifyWithoutRequest = (profile, done) => {
        if (!profile) {
          done(new Error('SAML profile is missing'));
          return;
        }

        // Dev fallback preserves Phase 26 / 28 integration ergonomics until
        // 29-04 retires DEV_SESSION. Production path goes through strict Zod.
        if (options.devMode) {
          done(null, {
            samlId: profile.nameID ?? profile.email ?? 'unknown-saml-id',
            email: profile.email ?? 'unknown@example.com',
            displayName: profile.displayName ?? profile.cn ?? 'Unknown User',
            role: (profile.role as Role | undefined) ?? 'viewer',
          });
          return;
        }

        const parsed = SamlProfileSchema.safeParse({
          nameID: profile.nameID,
          email: profile.email,
          displayName: profile.displayName ?? profile.cn,
          role: profile.role,
        });

        if (!parsed.success) {
          done(new Error('SAML profile missing required role attribute'));
          return;
        }

        done(null, {
          samlId: parsed.data.nameID,
          email: parsed.data.email,
          displayName: parsed.data.displayName ?? 'Unknown User',
          role: parsed.data.role,
        });
      };

      return new SamlStrategy(options, verify, verify);
    }
    ```
