<objective>
Two coupled requirements ship in one commit because PITFALLS.md CC-1 promises a silent 401 retry storm if they split. AUTH-05 closes the PDF cookie seam at `pdf-export.processor.ts:69-72` (today a `TODO(Phase 24)` block); AUTH-01 (the PDF-only enable variant per ROADMAP) introduces `AUTH_DEV_MODE_ALLOW_TEST=true` as a narrower-than-`AUTH_DEV_MODE` switch that lets the integration suite (and the Playwright runner that drives the print page) hit a real authenticated tRPC context without flipping production.

The commit message MUST mention both REQ-IDs explicitly. The integration test that proves the coupling closes is the canary: `AUTH_DEV_MODE=false`, `AUTH_DEV_MODE_ALLOW_TEST=true`, head clicks Export PDF, a non-empty PDF lands on disk within 30 seconds.

This plan is sequenced AFTER 28-01 (clean diffs) but does NOT take a strict dependency on it — the role-filter changes do not block the cookie seam. Sequencing simply isolates the diffs across two commits and keeps `git bisect` honest.

Key decisions, locked here:
1. JWT library: `jsonwebtoken` (Phase 27 / 28-CONTEXT decisions section). Signing call: `jwt.sign({ reportId }, secret, { expiresIn: '5m' })`. Secret env: `PDF_EXPORT_JWT_SECRET` (NEW). Failure to load secret = 500 at startup, not silently empty.
2. Cookie value = signed JWT. The trpc.context.ts dev-fallback consumers don't validate the cookie's JWT signature (Phase 28 scope is enable, not enforce); Phase 29 / AUTH-02 will introduce a real verifier when SAML lands. For now, the cookie just has to *be present* so that proxy.ts and the dev-mode bypass let the PDF browser through.
3. Cookie domain / secure flags: derived from `PDF_BASE_URL` URL parse (already implemented at `pdf-export.service.ts:122-145` — preserve as-is).
4. `auth.me` semantics (PITFALLS A-4) MUST remain `publicProcedure` returning `null` on no-session — DO NOT change to throwing UNAUTHORIZED.

Out of scope: Real Keycloak SAML, JWT verification in the cookie path on incoming HTTP requests, frontend role-aware nav. All Phase 29.
</objective>
