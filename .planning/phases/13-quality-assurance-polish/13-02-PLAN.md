    **BUG-013 (P1): Reject zero-width-space-only strings.**
    Create a reusable Zod refinement for text fields. In report.ts (top of file or as a helper):
    ```typescript
    /** Rejects strings that contain only whitespace or zero-width characters */
    const noInvisibleOnly = (val: string) => val.replace(/[\s\u200B\u200C\u200D\uFEFF]/g, '').length > 0;
    ```
    Apply this refinement to ALL text fields that currently use `.min(1)`:
    - priority.text (or priority name)
    - item.text
    - risk.text (or risk description)
    - decision.text
    Add as: `.refine(noInvisibleOnly, { message: 'Text must contain visible characters' })`

    **BUG-014 (P1): Reject null bytes in text fields.**
    Add a null byte check refinement. In report.ts:
    ```typescript
    /** Rejects strings containing null bytes (PostgreSQL incompatible) */
    const noNullBytes = (val: string) => !val.includes('\u0000');
    ```
    Apply to ALL string fields in schemas that go to the database.
    Can be combined with noInvisibleOnly into a single `.refine()`:
    ```typescript
    .refine(
      (val) => !val.includes('\u0000'),
      { message: 'Text must not contain null bytes' }
    )
    .refine(noInvisibleOnly, { message: 'Text must contain visible characters' })
    ```
    Alternatively, create a `safeText` helper that wraps `z.string()` with both checks:
    ```typescript
    const safeText = (opts: { min?: number; max?: number } = {}) =>
      z.string()
        .min(opts.min ?? 1)
        .max(opts.max ?? 500)
        .refine((v) => !v.includes('\u0000'), { message: 'Text must not contain null bytes' })
        .refine(noInvisibleOnly, { message: 'Text must contain visible characters' });
    ```
    Then use `safeText()` in place of `z.string().min(1).max(500)` throughout the schemas.

    **BUG-009 (P1): JWT activeReportId nullable.**

    To: `z.string().uuid().nullable().optional()`
    This allows these fields to be explicitly `null` when no active report exists.
