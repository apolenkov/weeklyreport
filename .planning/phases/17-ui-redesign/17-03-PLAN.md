# Phase 17 Plan 03 — Wave 2: Backend API Endpoints

## Objective

Implement 12 new tRPC endpoints that complete the API surface required by
mockup v14: period lifecycle (publish/reopen), revoke, weekly report
auto-compilation, fill-from, version history, admin settings, and stage
validation.

## Requirements Closed

- **API-01**: period.publish — Publish & Lock
- **API-02**: period.reopen — Reopen period
- **API-03**: leadSubmission.revoke — Revoke lead's submission
- **API-04**: leadSubmission.requestReopen — Lead requests reopen
- **API-05**: report.weekly — Auto-compiled Weekly Report
- **API-06**: report.weekly.byPeriod — Historical Weekly Report
- **API-07**: leadForm.fillFrom — Fill from past period
- **API-08**: leadForm.versions — List version snapshots
- **API-09**: leadForm.restoreVersion — Restore to version
- **API-10**: leadForm.byPeriod — Lead form for specific period
- **API-11**: admin.settings — CRUD general settings
- **API-12**: Stage assignment validation

## Step 1 — Period Lifecycle (API-01, API-02)

### New module: `apps/api/src/modules/period/`

- `period.module.ts`
- `period.service.ts`
- `period.router.ts`
- `period.prisma-repository.ts`

### Endpoints

```typescript
period.publish  // head-only mutation
  Input: { reportId: string }
  Logic:
    1. Set report.periodStatus = 'published'
    2. Set report.publishedAt = now()
    3. Set report.publishedById = userId
    4. Set report.status = 'published' (existing field)
    5. Lock all ReportSections (no further edits)
  Output: { success: true, reportId }

period.reopen  // head-only mutation
  Input: { reportId: string }
  Logic:
    1. Verify report.periodStatus === 'published'
    2. Set report.periodStatus = 'reopened'
    3. Set report.reopenedAt = now()
    4. Unlock all ReportSections for editing
  Output: { success: true, reportId }
```

## Step 2 — Revoke & Reopen Request (API-03, API-04)

### Extend: `apps/api/src/modules/report-sections/`

```typescript
leadSubmission.revoke  // head-only mutation
  Input: { reportSectionId: string }
  Logic:
    1. Set section.status = 'draft'
    2. Set section.revokedAt = now()
    3. Set section.revokedBy = userId
    4. Clear section.submittedAt
  Output: { success: true }

leadSubmission.requestReopen  // protected mutation (lead)
  Input: { reportSectionId: string, reason?: string }
  Logic:
    1. Verify caller is section author
    2. Create notification (or email) to head
  Output: { success: true }
```

## Step 3 — Weekly Report Compilation (API-05, API-06)

### New module: `apps/api/src/modules/weekly-report/`

- `weekly-report.module.ts`
- `weekly-report.service.ts`
- `weekly-report.router.ts`
- `weekly-report.prisma-repository.ts`

### Endpoints

```typescript
report.weekly  // protected query
  Input: { reportId?: string }  // defaults to active period
  Logic:
    1. Load report with all sections + includes
    2. Aggregate portfolio overview (per-product worst-case traffic light)
    3. Group items by lead, then by product
    4. Count submissions vs total leads
    5. Compile escalations (blocked stages, at-risk, unresolved risks)
  Output: WeeklyReportReadModel {
    reportId, periodStart, periodEnd, periodStatus, weekLabel,
    submissionCount, totalLeads,
    portfolioOverview: [{ productName, worstStatus, stageCount, leads }],
    leadSections: [{ leadName, items, risks, decisions, priorities }],
    escalations: [{ type, product, stage, description }]
  }

report.weekly.byPeriod  // protected query
  Input: { reportId: string }
  Logic: same as above but for specific historical period
  Output: same shape
```

## Step 4 — Fill From & Version History (API-07, API-08, API-09, API-10)

### Extend: `apps/api/src/modules/report-sections/`

```typescript
leadForm.fillFrom  // protected mutation
  Input: { targetSectionId: string, sourceSectionId: string }
  Logic:
    1. Verify caller owns target section
    2. Load source section with all includes
    3. Deep-copy items, risks, decisions, priorities to target
    4. Create a VersionSnapshot before overwriting (safety net)
  Output: { success: true, copiedItems: number }

leadForm.versions  // protected query
  Input: { reportSectionId: string }
  Logic: List version snapshots ordered by version desc
  Output: VersionSnapshot[]

leadForm.restoreVersion  // protected mutation
  Input: { reportSectionId: string, version: number }
  Logic:
    1. Load snapshot data (JSON)
    2. Replace current section content with snapshot data
    3. Create new snapshot for the overwritten state
  Output: { success: true, restoredVersion: number }

leadForm.byPeriod  // protected query
  Input: { reportId: string }
  Logic:
    1. Load section for caller + given report
    2. If report.periodStatus !== 'open', mark as read-only
  Output: { section: ReportSectionReadModel, readOnly: boolean }
```

## Step 6 — Autosave Version Snapshot Hook

### Extend: `apps/api/src/modules/report-sections/report-sections.service.ts`

On every `saveDraft` call:
1. Increment version counter for the section
2. Save current state as VersionSnapshot (JSON serialization)
3. Keep max 50 versions per section (prune oldest)
