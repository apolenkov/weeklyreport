# Phase 17 Plan 02 — Wave 1: Schema Migration + Login Stub + URL Routing

## Objective

Migrate the database schema to support mockup v14 data model (period lifecycle,
version snapshots, stage assignments), add login stub endpoint for development,
and wire URL-based routing skeleton for all pages.

## Requirements Closed

- **SCH-01**: Period lifecycle enum (Open, Published, Reopened)
- **SCH-02**: Period publishedAt, publishedBy, reopenedAt fields
- **SCH-03**: ReportSection revokedAt, revokedBy fields
- **SCH-04**: VersionSnapshot model
- **SCH-05**: Stage assignment unique constraint
- **SCH-06**: Period extended with autoCreate, defaultDeadlineDays
- **SCH-07**: Migration preserves existing v3 data
- **API-13**: Login stub (mock JWT with role selection)
- **UI-14**: URL-based routing skeleton (query params for period/tab)

## Step 1 — Prisma Schema Migration

### 1a. New enums

Add to `prisma/schema.prisma`:

```
enum PeriodStatus {
  open
  published
  reopened
}
```

### 1b. Rename Report → Period concept

The current `Report` model serves as the period container. Rename semantics:

- Add `periodStatus PeriodStatus @default(open)` field to `Report`
- Add `reopenedAt DateTime?` field to `Report`
- Keep existing `publishedAt`, `publishedById` fields (SCH-02 already satisfied)

### 1c. ReportSection revoke fields (SCH-03)

Add to `ReportSection`:

```
revokedAt    DateTime?
revokedBy    String?
```

### 1d. VersionSnapshot model (SCH-04)

New model:

```
model VersionSnapshot {
  id               String        @id @default(uuid())
  reportSectionId  String
  version          Int
  data             Json          // serialized form state
  reportSection    ReportSection @relation(fields: [reportSectionId], references: [id], onDelete: Cascade)
  createdAt        DateTime      @default(now())

  @@unique([reportSectionId, version])
}
```

Add `versionSnapshots VersionSnapshot[]` relation to `ReportSection`.

### 1e. Stage model + assignment constraint (SCH-05)

New model:

```
model Stage {
  id        String   @id @default(uuid())
  name      String   @unique   // Planning, Analysis, Design, Dev, Testing, DevOps, Support
  sortOrder Int      @default(0)
  createdAt DateTime @default(now())
}

model StageAssignment {
  id        String   @id @default(uuid())
  userId    String
  stageId   String
  projectId String
  user      User     @relation(fields: [userId], references: [id], onDelete: Cascade)
  stage     Stage    @relation(fields: [stageId], references: [id], onDelete: Cascade)
  project   Project  @relation(fields: [projectId], references: [id], onDelete: Cascade)
  createdAt DateTime @default(now())

  @@unique([userId, stageId, projectId])
}
```

Add relations to User, Project.

### 1f. Period settings (SCH-06)

Add to `Report` model:

```
autoCreate         Boolean  @default(false)
defaultDeadlineDays Int     @default(5)
weekLabel          String?  // "Week 16" display label
```

Or create a separate `AppSettings` model:

```
model AppSettings {
  id                  String @id @default("singleton")
  departmentName      String @default("Development")
  autoCreatePeriods   Boolean @default(false)
  defaultDeadlineDays Int     @default(5)
  updatedAt           DateTime @updatedAt
}
```

Decision: Use `AppSettings` singleton — cleaner separation.

## Step 3 — Login Stub (API-13)

### Purpose

Allow development without Keycloak SSO. When `NEXT_PUBLIC_AUTH_STUB=true`,
show role buttons instead of SSO redirect. Backend generates a mock JWT.

### Files to modify

- `apps/api/src/modules/auth/auth.controller.ts` — add `/auth/stub` POST
- `apps/api/src/modules/auth/auth.module.ts` — wire stub route
- `apps/web/src/app/page.tsx` — login page with stub buttons

### Endpoint

```
POST /auth/stub
Body: { role: 'lead' | 'head' | 'admin' | 'viewer', userId?: string }
Response: { token: string, redirectUrl: string }
Guard: only when AUTH_STUB=true env var is set
```

The stub picks a user from the seed data matching the requested role and
generates a valid JWT.

## Step 4 — URL Routing Skeleton (UI-14)

### Route structure

```
/                          → Login (or redirect to dashboard if authed)
/lead/report?period=<id>   → Lead form for specific period
/lead/history              → Lead's submission history
/head/dashboard            → Dashboard hub
/head/report?period=<id>   → Weekly report for period
/admin                     → Admin panel (?tab=users|products|periods|reminders|settings)
/reports/[reportId]        → Published report viewer
/reports/[reportId]/print  → Print/PDF version
/reports/history           → Report archive (redirect to dashboard)
```

### Files to modify

- `apps/web/src/app/page.tsx` — Login with stub buttons
- `apps/web/src/app/(app)/lead/report/page.tsx` — accept `period` search param
- `apps/web/src/app/(app)/head/dashboard/page.tsx` — dashboard skeleton
- `apps/web/src/app/(app)/head/report/page.tsx` — accept `period` search param
- `apps/web/src/app/(app)/admin/page.tsx` — accept `tab` search param
- `apps/web/src/app/(app)/lead/history/page.tsx` — history skeleton
- `apps/web/src/app/layout.tsx` — design system globals (fonts, colors)

### Routing contract

Each page reads params from `searchParams` (Next.js 16 server component API).
No client-side routing state — all state in URL.
