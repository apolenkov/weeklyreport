# Phase 17 Plan 01 — API Completion From Approved Mockups

## Objective

Complete the backend contract model so the approved mockups can be rebuilt on
stable API semantics instead of local assumptions.

## Why this plan exists

The mockups are now ahead of the current API. The fastest honest move is to:

1. reduce the authenticated Next.js app shell to a Hello World + API placeholder,
2. finish the API semantics from the mockups,
3. then rebuild the polished UI against stable contracts.

## Mockup-driven API scope

### 1. Product Status pipeline
- Product-centric report structure, not lead-centric rendering
- Stage ownership per product stage
- Stage health/status with head-visible aggregation
- Explicit blocked / at-risk summary semantics

### 2. Weekly report content buckets
- Current week items as explicit contract field/group
- Next week items as explicit contract field/group
- Risks / blockers as explicit contract field/group
- Decisions as explicit contract field/group
- Priorities as explicit contract field/group
- Product tagging for all report content

### 3. Review and publication workflow
- Draft
- Submitted
- Review-ready / approval-needed
- Published
- Immutable published snapshot
- Explicit head review step before publish

### 4. Archive and history semantics
- Lead history entries
- Published archive summaries
- Published archive detail
- Version history / edit trail for pre-publish states
- Compare-ready metadata between adjacent periods/versions

### 5. Admin and operational parity
- Users / product ownership / stage ownership
- Report periods and deadlines
- Reminder rules and execution metadata
- Carry-over metadata where applicable

## Highest-leverage schema files

- `packages/shared/src/schemas/report.ts`
- `packages/shared/src/trpc/router.ts`

## Highest-leverage API modules

- `apps/api/src/modules/report-sections/*`
- `apps/api/src/modules/review/*`
- `apps/api/src/modules/publication/*`
- `apps/api/src/modules/archive/*`
- `apps/api/src/modules/admin/*`

## Execution sequence

### Step 1 — Shared contract expansion
Add explicit Zod schemas and TS types for:
- product-stage read model
- current/next item groups
- blocker/risk summary groups
- decision groups
- priority groups
- review status and approval state
- report version metadata
- archive/history compare metadata

### Step 2 — tRPC surface alignment
Update shared router contracts so frontend-facing procedures describe the
mockups explicitly rather than bundling sections implicitly.

### Step 3 — Service/read-model alignment
Update review/publication/archive/report-section services so they assemble the
new explicit read models and lifecycle states.

### Step 4 — Versioning and pre-publish history
Add explicit version metadata and read models required by the mockup history and
head review flows.

### Step 5 — Contract and integration test expansion
Extend module contract tests to cover the new semantics before rebuilding UI.

## Deliverables

- Updated shared schemas covering all approved mockup semantics
- Updated tRPC contract surface for head/lead/viewer/admin flows
- Updated backend read models and state transitions
- Updated tests proving mockup/API parity
- Frontend app shell reduced to Hello World + API links until API parity is complete

## Exit criteria

This plan is complete when:

- the API can express every approved mockup section explicitly,
- head review/publish/archive/versioning states are contract-defined,
- frontend no longer needs ad-hoc assumptions to render the approved screens.
