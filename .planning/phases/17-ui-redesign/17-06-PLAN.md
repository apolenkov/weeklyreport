# Phase 17 Plan 06 — Wave 5: Admin Panel + Login + Design Polish

## Objective

Build Admin Panel (5 tabs), Login split-screen, navigation bar, and apply
design system polish across all pages. Implement all modal/dialog states.

## Requirements Closed

- **UI-11**: Admin Panel — 5 tabs: Users, Products, Periods, Reminders, Settings
- **UI-12**: Login — split-screen with Demo brand + stub buttons
- **UI-15**: Nav bar teal border constrained to content width
- **UI-16**: All pages max-w-6xl, padding uniform
- **UI-17**: Starbucks design system (finalize across all pages)
- **UI-18**: Accessibility: skip-link, aria-labels, focus rings, touch targets
- **UI-19**: UI States: all modals/dialogs per mockup s7

## Step 1 — Admin Panel (UI-11)

### Tab routing

URL: `/admin?tab=users|products|periods|reminders|settings`

Default tab: `users`. Tab switch updates URL param without page reload.

### Users Tab (`users-tab.tsx`)

Table: Name | Email | Role | Department

- Add User button → dialog with form
- Edit button → same dialog, pre-filled
- Delete button → confirmation dialog
- Role dropdown: lead, head, viewer

Data source: tRPC `admin.snapshot` → users.

### Products Tab (`products-tab.tsx`)

Table: Product Name | Lead Owner | Stages | Status

- Add/Edit/Archive product
- Stage assignment editor per product
- 7 stage dropdowns (one per SDLC stage) → assign user

### Stage Assignment (`stage-assignment-editor.tsx`)

For each product, 7 dropdowns (one per stage):

- Dropdown lists all lead users
- Selection calls `admin.saveStageAssignment`
- Validates unique constraint (API-12)

### Periods Tab (`periods-tab.tsx`)

Table: Week Label | Start | End | Deadline | Status

- Create/Edit period
- Status: Open / Published / Reopened
- Auto-create toggle from settings

### Reminders Tab (`reminders-tab.tsx`)

Toggle switches:

- "On deadline day" — active/paused
- "24h before deadline" — active/paused
- "Weekly summary" — active/paused
- Manual "Send Now" button per rule

### Settings Tab (`settings-tab.tsx`)

Form fields:

- Department name (text)
- Auto-create periods (toggle)
- Default deadline days (number)
- Save button → `admin.updateSettings`

## Step 2 — Login Page (UI-12)

### Split-screen layout

Left panel (50%):

- Demo brand gradient (teal → dark green)
- Geometric shapes (CSS-only: circles, triangles)
- Department name: "Software Development"
- Tagline: "Weekly Status Reporting"

Right panel (50%):

- CustomReport logo
- "Sign in with SSO" button (navigates to `/auth/saml`)
- When `NEXT_PUBLIC_AUTH_STUB=true`:
  - "Development Mode" label
  - 4 role buttons: Enter as Lead / Head / Admin / Viewer
  - Each calls POST `/auth/stub` → sets JWT cookie → redirects

### Route

`apps/web/src/app/page.tsx` — replaces current placeholder.

## Step 3 — Navigation Bar (UI-15)

### `nav-bar.tsx`

- Top nav bar with teal bottom border
- Border constrained to `max-w-6xl` content width (not full viewport)
- Logo left, role-aware links center, user avatar + name right
- Links: varies by role
  - Lead: My Report, History
  - Head: Dashboard, Weekly Report
  - Admin: Dashboard, Weekly Report, Admin
- Active link: teal underline
- Mobile: hamburger menu

### `skip-link.tsx`

Hidden skip-to-content link, visible on Tab focus.

## Step 4 — Design System Polish (UI-16, UI-17)

### Global layout

All page content wrapped in `max-w-6xl mx-auto px-4 sm:px-6 lg:px-8`.

### Spacing audit

- Section spacing: `space-y-8`
- Card padding: `p-6`
- Form gap: `gap-4`

### Typography

- h1: 24px, Lexend, weight 600, color: var(--color-primary)
- h2: 20px, Lexend, weight 500
- Body: 16px, Source Sans 3, color: var(--color-text)
- Muted: 14px, color: var(--color-text-muted)

### Buttons

- Primary: bg-[var(--color-primary-accent)], text-white, rounded-[50px], min-h-[44px]
- Secondary: border-[var(--color-primary)], text-[var(--color-primary)]
- Active: transform scale(0.95) on press
- All: 44px min touch target

### Cards

- bg-white, rounded-[12px], shadow (0.14/0.24 alpha)
- Hover: subtle shadow increase

## Step 5 — Accessibility (UI-18)

- Skip-link: first focusable element
- aria-labels on all interactive elements
- Focus rings: 3px rgba(0,98,65,0.3)
- Touch targets: min 44px
- Reduced motion: `prefers-reduced-motion` media query
- Color contrast: all text meets WCAG AA

## Step 6 — Modal/Dialog States (UI-19)

### Confirmation dialogs (from mockup s7)

Create reusable `confirmation-dialog.tsx`:

- Title, description, confirm/cancel buttons
- Variants:
  - Submit: "Submit your report? This cannot be undone."
  - Publish: "Publish & Lock this period? All lead forms will be locked."
  - Reopen: "Reopen this period? Leads can edit again."
  - Revoke: "Revoke [lead name]'s submission? Their form returns to Draft."
  - Fill From: "Fill from [period]? This will overwrite your current draft."
  - Version Restore: "Restore to version [n]? Current changes will be lost."
  - Delete: "Delete [item]? This action cannot be undone."

All use shadcn/ui AlertDialog component.
