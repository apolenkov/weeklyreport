# Phase 17 Plan 04 — Wave 3: Lead Form + Lead History UI

## Objective

Build the Lead Form page (most complex frontend page) and Lead History page,
matching mockup v14 slide 1 and slide 9. SDLC pipeline visualization,
period navigator, Fill From, version history, and all form sections.

## Requirements Closed

- **UI-01**: Lead Form — SDLC pipeline with 7 stages
- **UI-02**: Lead Form — period navigator (← combobox →)
- **UI-03**: Lead Form — "Fill from Previous" split button
- **UI-04**: Lead Form — version history with diff preview
- **UI-13**: Lead History — traffic light dots per card
- **UI-17**: Starbucks design (partial — applied to these pages)
- **UI-18**: Accessibility (partial — applied to these pages)

## Component Architecture

```
apps/web/src/
  app/(app)/lead/report/page.tsx          — server component, reads ?period=
  app/(app)/lead/history/page.tsx         — server component
  components/lead/
    lead-form.tsx                          — client component, main form
    sdlc-pipeline.tsx                      — product × stage grid
    stage-chip.tsx                         — individual stage status chip
    period-navigator.tsx                   — ← Week 16 → combobox
    fill-from-button.tsx                   — split button + dropdown
    version-history-nav.tsx               — ← v3 → with rollback
    current-week-section.tsx              — items grouped by product
    next-week-section.tsx                 — items grouped by product
    risks-section.tsx                     — risk entries with product tags
    decisions-section.tsx                 — decision entries
    priorities-section.tsx                — numbered priority list
    item-card.tsx                         — single item with status badge
    lead-history-list.tsx                 — history cards with traffic lights
```

## Step 1 — SDLC Pipeline Component (UI-01)

### `sdlc-pipeline.tsx`

Grid layout: rows = products, columns = 7 stages.

Each cell renders `<StageChip>` with states:

- **Your stage (filled)**: full color, clickable, status icon
- **Your stage (empty)**: pulsing dashed border, "Set status" prompt
- **Locked stage (other lead's)**: opacity 0.35, grayscale, lock icon
- **Unassigned**: dashed border, muted

Data source: tRPC `leadForm.byPeriod` → products × stage assignments.

### `stage-chip.tsx`

120px pill button per mockup:

- `✓ On Track` — green background
- `! At Risk` — yellow background
- `✕ Blocked` — red background
- Empty state — dashed outline

Click opens a dropdown to change status.

## Step 2 — Period Navigator (UI-02)

### `period-navigator.tsx`

```
← | Apr 14–20 · Week 16 ▾ | →
```

- Left/right arrows cycle through periods
- Combobox dropdown lists all periods
- Selecting a period navigates via URL: `?period=<reportId>`
- Past periods: show "Read Only" badge, form inputs disabled
- Current period: show "Open" badge, form editable

Data source: tRPC `admin.snapshot` → periods list.

## Step 3 — Fill From Button (UI-03)

### `fill-from-button.tsx`

Split button:

- Primary action: "Fill from Previous" (last submitted period)
- Dropdown: searchable list of all past submitted periods

On click:

1. Show confirmation dialog: "This will overwrite your current draft"
2. Call tRPC `leadForm.fillFrom`
3. Refresh form data

## Step 4 — Version History (UI-04)

### `version-history-nav.tsx`

```
← v3 → | Autosaved 2m ago
```

- Left/right arrows navigate version snapshots
- Shows diff preview (changed fields highlighted)
- "Restore" button calls `leadForm.restoreVersion`
- Current state always shown as latest version

Data source: tRPC `leadForm.versions`.

## Step 5 — Form Sections

### Current Week (`current-week-section.tsx`)

- Items grouped by product
- Each item: product badge, stage badge, status (In Progress/Completed/Blocked), text, delete
- "Add Item" button per product section
- Auto-tag with product and stage from pipeline

### Next Week (`next-week-section.tsx`)

Same structure, "Planned" status badge.

### Risks & Blockers (`risks-section.tsx`)

- Free-text entries with product tag, severity badge
- Fields: risk, impact, mitigation

### Decisions (`decisions-section.tsx`)

- Entries with product tag
- Fields: text, owner, deadline, impact

### Priorities (`priorities-section.tsx`)

- Numbered 1-3 (min 1 required for submit)
- Drag-to-reorder or numbered input

## Step 6 — Submit Flow

Submit button at bottom:

1. Validates all required fields (Zod schema)
2. Shows confirmation dialog
3. Calls tRPC `reports.submit`
4. Form locks to read-only
5. "Submitted" badge appears

## Step 7 — Lead History Page (UI-13)

### `apps/web/src/app/(app)/lead/history/page.tsx`

Card grid of past submissions:

- Period dates + week label
- Status badge (Submitted/Draft)
- Traffic light dots (green/yellow/red counts from portfolio)
- Click navigates to `?period=<id>` on lead form (read-only)

Data source: tRPC `reports.myHistory`.

## Step 8 — Autosave Integration

On every form change (debounced 2s):

1. Call tRPC `reports.saveDraft`
2. Backend creates VersionSnapshot automatically
3. Update "Autosaved" indicator

## Exit Criteria

1. Lead Form renders SDLC pipeline grid matching mockup s1
2. Period navigator switches periods via URL; past periods read-only
3. Fill From copies data from past period with confirmation dialog
4. Version history shows snapshots; restore replaces current data
5. All form sections (current/next/risks/decisions/priorities) editable
6. Submit locks the form with confirmation dialog
7. Lead History shows cards with traffic light dots
8. All components use Starbucks design tokens
9. Tab navigation and focus rings work (a11y)
10. `pnpm typecheck` passes clean
