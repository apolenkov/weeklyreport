# Phase 47-02 — Git hooks + GitHub Actions CI

**Status:** ready
**Depends on:** none
**Requirement:** DX-02 (auto-install on pull, CI red-light on push)

## Goal

After any `git pull` / `git rebase`: lock changes auto-trigger
`pnpm install`, schema changes auto-trigger `pnpm exec prisma generate`.
And every push to `main` (and every PR) runs lint + test + build in
GitHub Actions, surfacing breakage immediately. After this plan: nobody
ever has to «forget» to install deps or regenerate Prisma client; CI
fails loudly when a commit breaks the build.

## Acceptance Criteria

- `.husky/post-merge` exists, marked executable, runs the conditional
  `pnpm install` + `pnpm exec prisma generate` block.
- `.husky/post-rewrite` exists, marked executable, runs the same logic
  for the rebase case.
- Hooks are idempotent — re-running them with no relevant changes is a
  near-zero-cost no-op (just two `grep` calls).
- `.github/workflows/ci.yml` exists with jobs `test` and `build`.
- Workflow uses Node 22 + pnpm 10, postgres 15 service, redis 7 service,
  applies migrations via `pnpm exec prisma migrate deploy`, then runs
  `pnpm lint && pnpm test && pnpm build`.
- The workflow runs successfully in `act` (or dry-run validates via
  `actionlint`) — no syntax errors, no missing actions.
- README adds a CI badge stub
  (`![CI](https://github.com/<owner>/customreport/actions/workflows/ci.yml/badge.svg)`).

## Steps

1. Add `.husky/post-merge` (chmod +x):

   ```sh
   #!/usr/bin/env sh
   # DX-02 (47-02): auto-install + auto-generate on pull/merge.
   # Runs only when the relevant files changed in this merge.
   changed="$(git diff-tree -r --name-only --no-commit-id ORIG_HEAD HEAD 2>/dev/null || true)"
   if echo "$changed" | grep -qE '^pnpm-lock\.yaml$|^package\.json$'; then
     echo "[post-merge] lock or root package.json changed → pnpm install"
     pnpm install
   fi
   if echo "$changed" | grep -qE '^prisma/schema\.prisma$|^prisma/migrations/'; then
     echo "[post-merge] schema or migrations changed → pnpm exec prisma generate"
     pnpm exec prisma generate
   fi
   ```

2. Add `.husky/post-rewrite` (chmod +x) — same body, different trigger.

3. Add `.github/workflows/ci.yml`:

   ```yaml
   name: ci
   on:
     push:
       branches: [main]
     pull_request:
       branches: [main]

   jobs:
     test:
       runs-on: ubuntu-latest
       services:
         postgres:
           image: postgres:15-alpine
           env:
             POSTGRES_USER: customreport
             POSTGRES_PASSWORD: localdev
             POSTGRES_DB: customreport
           ports: ["5432:5432"]
           options: >-
             --health-cmd "pg_isready -U customreport"
             --health-interval 5s
             --health-timeout 5s
             --health-retries 10
         redis:
           image: redis:7-alpine
           ports: ["6379:6379"]
           options: >-
             --health-cmd "redis-cli ping"
             --health-interval 5s
             --health-timeout 5s
             --health-retries 10
       env:
         DATABASE_URL: postgresql://customreport:localdev@localhost:5432/customreport
         REDIS_URL: redis://localhost:6379
       steps:
         - uses: actions/checkout@v4
         - uses: pnpm/action-setup@v4
           with: { version: 10 }
         - uses: actions/setup-node@v4
           with:
             node-version: "22"
             cache: "pnpm"
         - run: pnpm install --frozen-lockfile
         - run: pnpm exec prisma migrate deploy
         - run: pnpm lint
         - run: pnpm test
         - run: pnpm build
   ```

4. Sanity-check the workflow YAML with `actionlint` if available,
   otherwise `yamllint`. Both are read-only.

5. Add CI badge line near the top of README (the placeholder URL is fine;
   becomes live as soon as the repo gets a GitHub remote).

6. Smoke test the hooks locally:

   ```bash
   # Simulate a merge that changed schema:
   git commit --allow-empty -m "test"
   # Manually run the hook script:
   sh .husky/post-merge
   # Assert: noop output (no changes from empty commit)
   ```
