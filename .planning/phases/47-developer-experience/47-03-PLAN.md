# Phase 47-03 — tRPC latency Prometheus + Grafana dashboard

**Status:** ready
**Depends on:** none (Phase 37 already provisioned Prometheus + Grafana)
**Requirement:** DX-03 (visible p50/p95/p99 per tRPC procedure)

## Goal

Instrument the NestJS tRPC pipeline with prom-client histograms and expose
them at `/metrics`. Wire Prometheus to scrape that endpoint. Provision a
Grafana dashboard with p50/p95/p99 panels, error rate, top-10-slow
procedures, and request volume. After this plan: any slow procedure is
visible without grepping JSON logs.

## Acceptance Criteria

- `apps/api/src/infrastructure/metrics/` directory contains
  `metrics.module.ts`, `metrics.controller.ts` (exposes `GET /metrics`),
  and `trpc-metrics.middleware.ts`.
- `prom-client` installed as direct dependency in `apps/api`
  (`pnpm --filter @customreport/api add prom-client`).
- `/metrics` endpoint returns Prometheus text format with at least these
  series:
  - `trpc_request_duration_seconds_bucket{procedure, type, status, le}`
  - `trpc_request_duration_seconds_sum{procedure, type, status}`
  - `trpc_request_duration_seconds_count{procedure, type, status}`
  - `trpc_request_total{procedure, type, status}`
- The metrics middleware is wired in `trpc.router.ts` BEFORE the existing
  logger middleware (so timings exclude logger overhead).
- Prometheus scrape config in `docker/prometheus/prometheus.yml` (or wherever
  the file lives — verify in the plan) gains a job targeting
  `customreport-api-1:3002/metrics` with a 15s scrape interval.
- Grafana dashboard JSON at
  `docker/grafana/provisioning/dashboards/trpc-latency.json` with 4 panels:
  1. Latency p50/p95/p99 timeseries by procedure (top 5)
  2. Error rate stat
  3. Top-10 slowest procedures bar gauge
  4. Request volume timeseries
- Dashboard auto-loaded on Grafana container start (existing provisioning
  config picks up new files in that directory).
- Smoke test: hit `admin.snapshot` 10 times, then
  `curl /metrics | grep admin.snapshot` shows the histogram count = 10.
- All existing api tests still green; one new unit test verifies the
  middleware emits the right labels.

## Steps

1. Locate Phase 37 provisioning structure:

   ```bash
   find /Users/ap/work/customreport/docker -name 'prometheus*.yml' -o -name 'dashboards' -type d 2>/dev/null
   ```

   Adjust the file paths below to match what exists.

2. Install dep:

   ```bash
   pnpm --filter @customreport/api add prom-client
   ```

3. Create `apps/api/src/infrastructure/metrics/trpc-metrics.middleware.ts`:

   ```ts
   import { Histogram, Counter, register } from "prom-client";

   const requestDuration = new Histogram({
     name: "trpc_request_duration_seconds",
     help: "tRPC request duration in seconds",
     labelNames: ["procedure", "type", "status"] as const,
     buckets: [0.005, 0.025, 0.05, 0.1, 0.25, 0.5, 1, 2.5, 5, 10],
     registers: [register],
   });

   const requestTotal = new Counter({
     name: "trpc_request_total",
     help: "tRPC request count",
     labelNames: ["procedure", "type", "status"] as const,
     registers: [register],
   });

   export function createTrpcMetricsMiddleware(t: {
     middleware: <T>(fn: T) => unknown;
   }) {
     return t.middleware(
       async ({
         path,
         type,
         next,
       }: {
         path: string;
         type: string;
         next: () => Promise<{ ok: boolean }>;
       }) => {
         const labels = { procedure: path, type };
         const end = requestDuration.startTimer(labels);
         try {
           const result = await next();
           const status = result.ok ? "success" : "error";
           end({ ...labels, status });
           requestTotal.inc({ ...labels, status });
           return result;
         } catch (err) {
           end({ ...labels, status: "error" });
           requestTotal.inc({ ...labels, status: "error" });
           throw err;
         }
       },
     );
   }
   ```

4. Create `apps/api/src/infrastructure/metrics/metrics.controller.ts` (NestJS):

   ```ts
   import { Controller, Get, Header } from "@nestjs/common";
   import { register } from "prom-client";

   @Controller("metrics")
   export class MetricsController {
     @Get()
     @Header("Content-Type", register.contentType)
     async metrics(): Promise<string> {
       return register.metrics();
     }
   }
   ```

5. Wire `MetricsController` into the existing module graph (likely the root
   `AppModule` in `apps/api/src/app.module.ts`).

6. In `apps/api/src/infrastructure/trpc/trpc.router.ts`, register the
   metrics middleware BEFORE the existing logger middleware.

7. Configure default Node.js process metrics (CPU, heap):

   ```ts
   // in metrics.module.ts onModuleInit
   import { collectDefaultMetrics } from "prom-client";
   collectDefaultMetrics();
   ```

8. Add Prometheus scrape job. Find the existing file
   (`docker/prometheus/prometheus.yml` likely), append:

   ```yaml
   - job_name: "customreport-api"
     scrape_interval: 15s
     static_configs:
       - targets: ["api:3002"]
   ```

   Then `docker compose restart prometheus`.

9. Create Grafana dashboard JSON. Skeleton (4 panels):
   - Panel 1: `histogram_quantile(0.95, sum by (le, procedure) (rate(trpc_request_duration_seconds_bucket[5m])))`
   - Panel 2: `sum(rate(trpc_request_total{status="error"}[5m])) / sum(rate(trpc_request_total[5m]))`
   - Panel 3: `topk(10, histogram_quantile(0.95, sum by (le, procedure) (rate(trpc_request_duration_seconds_bucket[5m]))))`
   - Panel 4: `sum by (procedure) (rate(trpc_request_total[1m]))`

   Save as `docker/grafana/provisioning/dashboards/trpc-latency.json`.
   Reuse panel structure from any existing Phase 37 dashboard to keep
   style consistent.

10. Restart grafana to pick up the new dashboard:

    ```bash
    docker compose restart grafana
    ```

11. Smoke test:

    ```bash
    for i in $(seq 1 10); do
      curl -s "http://localhost:3002/trpc/admin.dlqCount?..." >/dev/null
    done
    curl -s http://localhost:3002/metrics | grep 'trpc_request_total{procedure="admin.dlqCount"'
    # expected: counter ≥ 10
    ```

12. Add a unit test
    `apps/api/src/infrastructure/metrics/trpc-metrics.middleware.test.ts`:
    - Call the middleware twice with `path='admin.snapshot'`
    - Assert `register.getSingleMetric('trpc_request_total')` shows
      count=2 with the right labels.
