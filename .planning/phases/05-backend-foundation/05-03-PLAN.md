**ReportSectionsPrismaRepository** (HIGH complexity -- 6 nested models):

Define a shared Prisma include constant for the full section aggregate:
```typescript
const reportSectionFullInclude = {
  author: true,
  projectStatuses: { include: { project: true } },
  items: true,
  risks: true,
  decisions: true,
  priorities: { orderBy: { rank: 'asc' as const } },
} satisfies Prisma.ReportSectionInclude;
```

`getSectionById(reportSectionId)`:
- `prisma.reportSection.findUnique({ where: { id: reportSectionId }, include: reportSectionFullInclude })`
- Map to `ReportSectionReadModel` via `toDomain()`:
  - `reportSectionId` = Prisma `id`
  - `reportId` = Prisma `reportId`
  - `authorId` = Prisma `authorId`
  - `authorName` = Prisma `author.name`
  - `status` = Prisma `status`
  - `submittedAt` = Prisma `submittedAt`
  - `projects` = Prisma `projectStatuses.map(ps => ({ projectId: ps.projectId, projectName: ps.project.name, trafficLight: ps.status }))`
  - `items` = Prisma `items.map(i => ({ itemId: i.id, projectId: i.projectId, type: i.type, text: i.text, tag: i.tag, workflowStatus: i.workflowStatus, carriedOver: i.carriedOver, completed: i.completed }))`
  - `risks` = Prisma `risks.map(r => ({ riskId: r.id, projectId: r.projectId, risk: r.risk, impact: r.impact, mitigation: r.mitigation }))`
  - `decisions` = Prisma `decisions.map(d => ({ decisionId: d.id, text: d.text, owner: d.owner, deadline: d.deadline, impact: d.impact, resolvedAt: d.resolvedAt }))`
  - `priorities` = Prisma `priorities.map(p => ({ priorityId: p.id, rank: p.rank, text: p.text }))`

NOTE: The exact field names MUST match the Zod schema fields. Read `reportSectionReadModelSchema` carefully. The mapping above is approximate -- verify field names against the actual schema.

`saveSection(section)`:
- Use a Prisma transaction to atomically update the section and its nested relations:
  1. Update `reportSection` status and submittedAt
  2. Delete existing projectStatuses, items, risks, decisions, priorities for this section
  3. Create new ones from the domain model
  4. Re-fetch with full include and return mapped result
- Use `prisma.$transaction([...])` for atomicity.
- Set timeout: `{ timeout: 15000 }` for safety.

**PublicationPrismaRepository**:

`getAssembledReport(activeReportId)`:

- Re-fetch and return the mapped result.
- NOTE: Publication just updates the report row status -- the sections are already saved by the sections repository.

**CarryOverPrismaRepository** (HIGH complexity -- transactional multi-table write):

`findExecutionByDedupeKey(dedupeKey)`:
- `prisma.carryOverExecution.findUnique({ where: { dedupeKey }, include: { records: true } })`
- Map to `CarryOverExecution` domain shape.

`getSourceSection(sourceReportId)`:
- Query `prisma.reportSection.findFirst({ where: { reportId: sourceReportId }, include: reportSectionFullInclude })`
- Reuse the same `toDomain()` mapper from ReportSectionsPrismaRepository. Import or duplicate the mapper.
- Returns `ReportSectionReadModel | null`.

`getTargetSection(targetReportId)`:
- Same as getSourceSection but for target report.

`saveCarryOver(execution, records, targetSection)`:
- Use `prisma.$transaction(async (tx) => { ... }, { timeout: 15000 })` (Pitfall 5):
  1. `tx.carryOverExecution.create({ data: { id: execution.executionId, sourceReportId: execution.sourceReportId, targetReportId: execution.targetReportId, dedupeKey: execution.dedupeKey, status: execution.status } })`
  2. `tx.carryOverRecord.createMany({ data: records.map(r => ({ id: r.recordId, executionId: execution.executionId, sourceItemId: r.sourceItemId, sourceDecisionId: r.sourceDecisionId, targetItemId: r.targetItemId, targetDecisionId: r.targetDecisionId, recordType: r.recordType })) })`
  3. Create new items and decisions in target section: `tx.item.createMany(...)` and `tx.decision.createMany(...)` from `targetSection.items` and `targetSection.decisions` that were carried over.
  4. Return `{ execution, records }` mapped to domain shapes.

**AdminPrismaRepository** (MEDIUM complexity -- multi-table snapshot):

`getSnapshot()`:
- Read 4 tables in parallel:
  ```typescript
  const [users, projects, periods, reminderRules] = await Promise.all([
    this.prisma.user.findMany(),
    this.prisma.project.findMany({ include: { lead: true } }),
    this.prisma.report.findMany(),
    this.prisma.reminderRule.findMany(),
  ]);
  ```
- Map to `AdminSnapshot` shape: `{ users: AdminUser[], projects: AdminProject[], periods: ReportPeriod[], reminderRules: AdminReminderRule[] }`.
- Each mapper translates Prisma output to the Zod schema field names.

`saveSnapshot(snapshot)`:
- Diff and apply changes for each entity type using upsert/delete.
- Users: upsert each user, delete removed ones.
- Projects: upsert each project, archive removed ones (set `archived: true`).
- Periods (Reports): upsert each report period.
- ReminderRules: upsert each rule, delete removed ones.
- Re-fetch snapshot and return.
