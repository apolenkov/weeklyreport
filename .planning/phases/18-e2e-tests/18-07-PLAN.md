# Phase 18 Plan 07 — Visual Regression Baselines + Accessibility E2E

## Objective

Establish Playwright screenshot baselines for all pages and verify accessibility
requirements (E2E-10).

## Requirements Closed

- **E2E-10**: Visual regression baselines (Playwright screenshots, 223 scenarios as reference)

## Step 1 — Visual Regression Baselines

### Test file: `apps/web/e2e/visual/screenshots.spec.ts`

### Pages to screenshot (~12 baselines)

1. Login page (/) — full split-screen
2. Login page (/) — dev stub buttons visible
3. Lead Form (/lead/report) — filled form
4. Lead Form — submitted/locked state
5. Lead History (/lead/history) — card grid
6. Dashboard (/head/dashboard) — full page with KPIs
7. Weekly Report (/head/report) — with accordions expanded
8. Weekly Report — published/locked state
9. Admin Panel (/admin?tab=users) — users table
10. Admin Panel (/admin?tab=products) — stage assignments
11. Published Report (/reports/[id]) — formatted view
12. Auth Error (/auth/error) — error page

### Screenshot config

```typescript
expect(page).toHaveScreenshot('login.png', {
  maxDiffPixelRatio: 0.01,
  fullPage: true,
});
```

Baselines stored in `apps/web/e2e/visual/screenshots.spec.ts-snapshots/`.

## Step 2 — Responsive Breakpoints

### Test file: `apps/web/e2e/responsive/breakpoints.spec.ts`

### Scenarios (~6 tests)

1. Mobile (375px) — login page stacks vertically
2. Mobile — lead form scrollable, touch targets 44px
3. Tablet (768px) — dashboard grid 2 columns
4. Tablet — admin panel tabs scroll horizontally
5. Desktop (1280px) — full layout, max-w-6xl centered
6. Large (1920px) — content doesn't stretch beyond 1152px

Covers: SC-59..SC-62 (Responsive & Accessibility)

## Step 3 — Accessibility Audit

### Test file: `apps/web/e2e/a11y/accessibility.spec.ts`

### Scenarios (~8 tests)

1. Skip-link visible on Tab press, navigates to #main-content
2. All interactive elements have aria-labels
3. Focus rings visible on Tab navigation (3px green ring)
4. Touch targets minimum 44px on all buttons/links
5. Color contrast meets WCAG AA (text on canvas, text on cards)
6. Keyboard navigation: Tab through lead form fields in order
7. Keyboard navigation: Enter submits focused button
8. prefers-reduced-motion: animations disabled

### Tools

Use `@axe-core/playwright` for automated a11y checks where possible.

## Exit Criteria

1. 12 visual baselines generated and committed
2. Screenshot comparison passes on re-run (< 1% diff)
3. 6 responsive breakpoint tests pass
4. 8 accessibility tests pass
5. No WCAG AA violations on core pages

- 3 test files
- ~400 lines of test code
