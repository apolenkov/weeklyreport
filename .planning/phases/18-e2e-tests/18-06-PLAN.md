# Phase 18 Plan 06 — Error Paths + Edge Cases E2E

## Objective

Test error handling, authorization failures, and boundary conditions (E2E-09).

## Requirements Closed

- **E2E-09**: Error paths: 403 wrong role, 404 invalid period, network disconnect

## Test file: `apps/web/e2e/error-paths.spec.ts`

### Authorization Errors (~4 tests)

1. Lead navigates to /admin → sees 403 or redirect
2. Viewer navigates to /lead/report → sees 403 or redirect
3. Unauthenticated user navigates to /head/dashboard → redirected to login
4. Expired session → redirected to /auth/error?reason=session_expired

### Not Found Errors (~3 tests)

1. Navigate to /lead/report?period=nonexistent-uuid → error state
2. Navigate to /reports/nonexistent-uuid → 404 page
3. Navigate to /admin?tab=invalid → defaults to users tab

### Edge Cases (~5 tests)

1. Submit with empty required fields → validation errors shown
2. Double-click Submit → only one submission (idempotent)
3. Very long text in item field → truncated or scrollable
4. Large number of items (50+) → form still responsive
5. Browser back/forward → URL state preserved

Covers: SC-47..SC-58 (Data Integrity, UI States, Edge Cases)

## Exit Criteria

1. Authorization errors handled gracefully (no blank screens)
2. 404 and invalid params show appropriate error UI
3. Edge cases don't crash the application
4. All 12 tests pass

## Estimated Scope

- 1 test file
- ~300 lines of test code
- ~12 test cases
