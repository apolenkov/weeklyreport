## Detailed Findings

### Pillar 1: Copywriting (2/4)

- **WARNING:** Static chrome is still English while business content is Russian. Examples: nav labels `My Report`, `My History`, `Dashboard`, `Weekly Report`, `Archive`, `Admin` in `apps/web/src/components/navigation/nav-bar.tsx:28`; dashboard/report headings in `apps/web/src/components/dashboard/dashboard-page.tsx:110` and `apps/web/src/components/weekly-report/weekly-report-page.tsx:247`; reports tabs `My Drafts` and `Published` in `apps/web/src/app/(app)/reports/page.tsx:82`.
- **WARNING:** The Phase 35-08 summary says Reports tabs shipped as `"Мои черновики"` and `"Опубликованные"` (`.planning/phases/35-ux-polish/35-08-SUMMARY.md:81`), but the implemented labels are English (`apps/web/src/app/(app)/reports/page.tsx:84`, `apps/web/src/app/(app)/reports/page.tsx:90`).
- **WARNING:** Forbidden copy is developer-oriented and exposes a dev-only recovery path: “Switch role from the floating role-switcher” (`apps/web/src/components/forbidden-page.tsx:34`). That should not be product copy outside stub mode.

### Pillar 2: Visuals (2/4)

- **BLOCKER:** Dashboard visual trust is degraded by repeated `Lead 1` rows and duplicate React key errors. Evidence: `desktop-head-dashboard.png`; pending-lead fragments key by display name in `apps/web/src/components/dashboard/alert-bar.tsx:67`, which is not unique.
- **WARNING:** The floating dev switcher visibly overlaps review surfaces, especially `mobile-lead-lead-report.png` where it sits over product status chips. It should be hidden in non-dev screenshots or pinned outside content flow.
- **WARNING:** Mobile lead form renders the SDLC pipeline as tightly wrapped chips with arrows and truncated cards; the focal task is hard to scan. Evidence: `mobile-lead-lead-report.png`; dense SDLC and item grids are rendered inside one long form surface (`apps/web/src/components/lead/lead-form.tsx:960`).

### Pillar 3: Color (2/4)

- **WARNING:** The palette is visually coherent, but token discipline is weak. Hardcoded hex/RGBA usage appears 373 times across app/ui files; arbitrary gradient/shadow/color usage appears heavily in major screens (`apps/web/src/components/weekly-report/weekly-report-page.tsx:283`, `apps/web/src/components/lead/lead-form.tsx:1039`).
- **WARNING:** The Starbucks-style green/cream/gold theme dominates most surfaces, while warning/destructive colors carry real workflow meaning. Some warning panels and badges use custom yellows/reds rather than semantic tokens (`apps/web/src/components/dashboard/alert-bar.tsx:80`, `apps/web/src/components/admin/users-tab.tsx:304`).
- **Positive:** Status colors are generally meaningful on report/lead surfaces: blocked red, at-risk yellow, submitted green.

### Pillar 4: Typography (2/4)

- **WARNING:** Typography uses too many ad hoc sizes: `text-xs`, `text-sm`, `text-base`, `text-lg`, `text-xl`, `text-2xl`, `text-4xl`, plus arbitrary `text-[8px]`, `[9px]`, `[10px]`, `[11px]`, `[12px]`, `[13px]`, `[15px]`, `[28px]`, `[32px]`, `[56px]`.
- **WARNING:** Five font weights are used (`normal`, `medium`, `semibold`, `bold`, `extrabold`). That is too much for dense operational UI and contributes to noisy hierarchy.
- **WARNING:** Mobile report cards rely on truncation instead of responsive hierarchy; evidence JSON clipped dashboard row labels such as `ОНОльга Н. · lead...` and screenshot `mobile-lead-lead-report.png` shows column headers reduced to fragments.

### Pillar 5: Spacing (2/4)

- **WARNING:** There are 403 arbitrary spacing/radius/shadow/gradient patterns, including `rounded-[...]`, `shadow-[...]`, `tracking-[...]`, and fixed pixel/rem values. This makes responsive polish fragile.
- **BLOCKER:** Mobile lead action row is overcrowded: `Fill from Previous`, `Toggle All`, `Request Reopen`, and `Submit Report` render in one row and squeeze text (`mobile-lead-lead-report.png`; source `apps/web/src/components/lead/lead-form.tsx:981`).
- **WARNING:** Mobile admin table hides action affordances from the first viewport and shows only `Name`/`Email` unless the user discovers horizontal scroll. Evidence: `mobile-head-admin.png`; source table is only `overflow-x-auto` (`apps/web/src/components/admin/users-tab.tsx:119`) instead of a mobile card/action layout.

### Pillar 6: Experience Design (1/4)

- **BLOCKER:** Direct route capture rendered forbidden pages for `/`, `/head/dashboard`, `/lead/report`, `/reports`, `/reports/history`, `/admin`, and `/head/report` even though the chrome showed a Department Head identity. Evidence: `evidence.json`, `mobile-home.png`, `mobile-lead-report.png`. This breaks task entry unless the user knows to dev-login/role-switch.
- **BLOCKER:** Submitted lead form still displays a primary `Submit Report` button, merely disabled (`apps/web/src/components/lead/lead-form.tsx:1027`). Regression contract expects the submit button hidden when submitted and a submitted badge instead (`.planning/REGRESSION-TEST-SCENARIOS.md:232`).
- **WARNING:** The same submitted state should make inputs disabled/visibly read-only (`.planning/REGRESSION-TEST-SCENARIOS.md:139`, `.planning/REGRESSION-TEST-SCENARIOS.md:189`, `.planning/REGRESSION-TEST-SCENARIOS.md:224`), but the lead screenshot shows many editable-looking cards and controls. The read-only banner helps, but individual affordances still look active.
- **WARNING:** Base button styling lacks a default `cursor-pointer`, so evidence flagged `Menu`, `Toggle All`, `Publish & Lock`, `Add User`, `Edit`, `Delete`, and tab controls as clickable elements without pointer cursor. Shared button variants omit cursor styling (`packages/ui/src/components/ui/button.tsx:7`); many raw buttons also omit it (`apps/web/src/components/dashboard/toggle-all-button.tsx:23`).
- **WARNING:** Admin user add/edit form lacks client-side required/email validation before mutation (`apps/web/src/components/admin/users-tab.tsx:87`), so errors are pushed to backend/toast rather than inline form states.
