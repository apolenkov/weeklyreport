# Slide Density Audit — v8.4.2

**Цель:** задокументировать поведение `Own`-слайда на 3 вьюпортах перед
редизайном v8.4.3.

**Seed-данные:** medium-density section Василия И. (lead), ветка
`fix/PRJ-2/shiny-eagle`. Данные стандартного seed (`db:wipe:manual-uat`):

- CURRENT WORK: 3 пункта (с тегами P1/P2/P3, 3 разных продукта)
- NEXT FOCUS: 2 пункта
- RISKS: 1 пункт (amber triangle)
- DECISIONS: 2 пункта

**Контекст рендеринга:** слайд встроен в Edit-страницу (`inReportMode=true`),
режим `Own`, вьюпорт задан через Playwright `browser_resize`. Fullscreen-режим
(`:fullscreen_&`) не тестировался — требует отдельного Playwright сценария с
`keyboard F11` или `document.documentElement.requestFullscreen()`.

**Скриншоты:** `.planning/notes/slide-density/`

```
│   └─────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────┘
```

**Статус:** WARN.

- Нижние ~50% карточки — пустое пространство. На широком мониторе это
  особенно заметно: карточка «висит» в верхней трети, нижняя половина
  полностью пуста.
- Карточка не растягивается на полную высоту контейнера.
- `auto-rows-fr` делит карточку на 2 равные строки, но нижняя строка
  (RISKS + DECISIONS) визуально вдвое меньше верхней по контенту.

## Диагностика

### Корневые причины

```text
[auto-rows-fr]
      │
      ├── равная высота строк независимо от контента
      │   → нижняя строка (RISKS+DECISIONS) раздута под высоту верхней
      │
      ├── нет min-height на секции
      │   → sparse (0-1 item): пустая секция растянется на 50% card height
      │
      └── карточка без min-h-full / h-full
          → на 1728+ экранах card висит в верхней трети viewport
```

### Что будет при Sparse (0 items)

Если все 4 секции пустые:

- 2×2 grid = 4 пустых ячейки равной высоты
- Карточка схлопнется до header + product-chips + 4 пустых равных квадрата
- Визуально: 4 «лопатки» с заголовками CURRENT WORK / NEXT FOCUS / RISKS /
  DECISIONS и пустым пространством внутри каждой

Если 1 секция заполнена (1 элемент), остальные пусты:

- Заполненная ячейка имеет ту же высоту, что пустые
- Верхний правый и оба нижних квадрата — пустые белые поля

### Что будет при Heavy (4 items, 3 risks, 2 decisions)

- CURRENT WORK: 4 пункта × ~1.5 строки = ~6 строк → переполнит ячейку если
  `fr` не успеет вырасти
- RISKS: 3 пункта, каждый может быть 2 строки → суммарно ~6 строк
- Риск: текст выйдет за `fr`-границу, либо `auto-rows-fr` сделает строки
  такими высокими, что карточка выйдет за высоту viewport
- Не тестировалось — нужен heavy seed

## Рекомендации для v8.4.3 redesign

### Приоритет 1 — устранить пустоту при Medium/Sparse

```text
Текущий:     grid grid-cols-2 auto-rows-fr   (строки = равные доли)
Вариант A:   grid grid-cols-2 auto-rows-auto  (строки = по контенту)
             + min-h-[120px] на каждой секции
Вариант B:   vertical stack (4 секции подряд, не 2×2)
             + collapsible пустые секции
Вариант C:   2×2 + min-h-[160px] и overflow:hidden с line-clamp
```

**Рекомендую Вариант A** — минимальное изменение, решает Sparse, не ломает
Medium, Heavy ограничивается через min-h.

### Приоритет 2 — растянуть карточку на viewport

```text
Текущий:     нет явного h-full на карточке внутри scroll-контейнера
Кандидат:    flex flex-col + flex-1 на контент-области карточки
             (карточка растягивается, grid-секции заполняют пространство)
```

### Приоритет 3 — протестировать Heavy перед редизайном

Создать seed с 4 current work пунктами (длинный текст), 3 рисками, 2 decisions.
Сделать скриншоты аналогично Medium. Зафиксировать в матрице.

### Приоритет 4 — Fullscreen сценарий

Playwright: `page.keyboard.press('F11')` или `.requestFullscreen()` через
`page.evaluate()`. Три density × fullscreen → 3 скриншота.

мониторах (пустота + нерастянутая карточка). Для v8.4.3 решение принять
**после** тестирования Heavy (пункт 3 выше) и Fullscreen (пункт 4).
