# CustomReport product excellence through SDLC

Make CustomReport/WeeklyReport an exemplary, maintainable product: architecture,
code style and code quality come first; user experience, accessibility, testing,
observability, delivery, recovery and documentation prove and sustain that
quality. Runtime and infrastructure are evidence-only work: they are used only
when needed to demonstrate a product property.

The shared, accepted outcomes are in [facts.md](facts.md). The ordered,
source-aware implementation and verification path is in [plan.md](plan.md).

## Done condition

All accepted facts are proved for one current source SHA/tree; every active
product requirement is reconciled; the full applicable product denominator has
zero missing, skipped or unknown cells and current browser/API/worker/DB/Redis/
Loki/OpenTelemetry/Bugsink evidence; no blocking architecture, code-style,
code, UX/accessibility, data-integrity, observability, recovery, release or
documentation finding remains; required checks, CI and independent final Sol
review pass; and CR-001 required remainder is zero with no owned agent,
process, listener, container, volume, worktree or secret residue.
