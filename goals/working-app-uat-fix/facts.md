# Facts — Working-app UAT + fix (all roles, one goal)

## Outcome facts (testable)

- Все 4 роли (lead / head / admin / viewer) открывают свои основные экраны с нулём console-ошибок на свежем билде.
- В отчёте лида: приоритет (priority rank) айтема сохраняется после перезагрузки и снова отображается в диалоге редактирования.
- В отчёте лида: edit-режим и slides-режим доступны рядом (split-view); переключение/просмотр не теряет несохранённые правки — единый источник данных.
- У хеда: split-view показывает сборный (агрегированный) статус и его слайд-форму рядом; хед там НЕ редактирует, только просматривает.
- У хеда: группировку можно переключать между «по продукту» и «по лидам» — и в статус-виде, и в слайд-виде.
- Head dashboard = «пульс» статусов текущего периода: видно, какие секции уже сданы/зафиксированы, а какие ещё нет.
- У хеда: кнопки Revoke (по лиду) и Revoke All появляются и работают, когда есть сданные секции лидов.
- На ключевых экранах нет видимого «прыжка» при загрузке: скелетон совпадает по размеру с финальным контентом (CLS≈0).
- Стадии SDLC показывают реальный цвет статуса (green/yellow/red) даже если контрибьютор стадии другой (cross-author) — НЕ серый; заблокированная для редактирования стадия показывает замок рядом (read-only), но цвет статуса сохраняется. Ячейка стадии окрашивается при наличии хотя бы одной стадии/риска/блока. Источник: `apps/web/src/components/lead/sdlc-pipeline.tsx`, `stage-chip.tsx`.
- Каждая найденная UAT-проблема (визуальная и алгоритмическая, ▲-high и ▼-low) починена до зелёного — ничего не отложено.
- Замороженные направления не тронуты: AI/RAG, тёмная тема, i18n, holidays-calendar, Telegram, Director.
- Все гейты зелёные: pnpm typecheck, pnpm lint, pnpm test, pnpm lint:md.
- Логирование покрывает ключевые пути по максимуму (входящие запросы, tRPC-процедуры, БД-запросы с таймингами, медленные операции, ошибки) так, что при UAT по логам видно, где подключить кэш и где нужны индексы БД. Результат — аудит покрытия логами + список перф-возможностей (cache / DB-index) с привязкой к конкретным запросам; явные evidence-backed выигрыши (индексы, кэш) применяются, крупные — в роадмапу. Опора на существующий observability-стек (pino, OTel, Prometheus/Grafana, `pnpm logs`).

- Паритет lead↔head по экрану отчёта (UAT-фидбек 2026-05-22): кнопка `ArchiveToggle` («Show archived periods») стоит рядом с выбором периода и у лида, и у хеда; layout/тулбар/сборка слайдов одинаковые; у хеда вместо Submit — submit-export / log (строка действий та же, отличие только в версии); хед read-only. Источник кнопки: `apps/web/src/components/report-shell/archive-toggle.tsx`.

## Process facts (how)

- Check-first: многое уже реализовано — сначала проверить и доработать, не строить заново.
- Прогнать code-simplifier + code-modernization + code review по затронутому коду (как отдельные gate-проходы).
- ESLint/Prettier до современных стандартов: Google config + объединённые eslint+prettier плагины; зависимости подтянуть до последних совместимых версий.
- Обязательный Vercel best-practices аудит через их скиллы (если скилл/CLI не установлен — установить).
- Исполнение максимально параллельное: Haiku — скан/разведка/аудит, Sonnet — фиксы и per-domain review; Opus — только синтез/конфликты/архитектурные решения, где это реально оправдано.
- Коммиты атомарные на ветке fix/PRJ-2/shiny-eagle.
