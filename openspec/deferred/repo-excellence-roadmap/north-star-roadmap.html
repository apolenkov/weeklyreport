CustomReport — North-Star Roadmap

Дорога к эталонному репозиторию: учебно-эталонный, production-ready, по best practices. Версия-черновик от 2026-06-22 · коммит f7cb2c56.

North-star (одна фраза): репозиторий, который новый инженер любого уровня читает как учебник, поднимает за 30 минут и безопасно выкатывает в production — где каждая строка возводится к идее продукта, а качество держится автоматическими воротами, а не ревью на глаз.

Эталоны, к которым привязаны оси: ISO/IEC 25010 и CodeScene (код), C4-модель + Clean/Hexagonal + ADR (архитектура), DDD + трассируемость (связь с идеей), DORA + 12-factor + OWASP ASVS (процессы/production), Testing-Trophy + observability (разработка/обучение).

2. Последовательность (фазы и зависимости)

Принцип: понятность раньше переделки. Сначала сделать код читаемым и прослеживаемым (низкий риск), затем упрощать и закреплять границы, и только потом — production. Каждая фаза опирается на предыдущую.

3. Каденс исполнения (защита от поломок)

  • Один эпик = одно grilled OpenSpec-изменение. Никаких массовых проходов.
  • Гейт зелёный между эпиками (typecheck + lint + test).
  • Горячая зона — характеризующий тест первым (фиксирует поведение до правки).
  • Карта здоровья кода — не разрешение на рефакторинг. Каждая строка карты → свой эпик.

Это прямой урок прошлого: «армейский» массовый рефакторинг прошёл гейт, но сломал поведение.

4. Эпики по осям

Ось 1 — Качество кода ISO 25010 · CodeScene

E1.1 — Снять мёртвые поблажки ✓ начато (7 снято 2026-06-22)

Зачем: устаревшие исключения в линтере молча гасят правила.
Готово, когда: каждое снятое исключение не ломает гейт; остаток — в карте.

E1.2 — Декомпозиция горячих точек

Зачем: lead-form (#1, 1322 стр., cognitive 55) и trpc.router (#2) — главный долг.
Готово, когда: топ-точки живут под стандартом 300/20/15 без исключения; поведение неизменно (характеризующий тест).

E1.3 — Мёртвый код и дубли в гейт

Зачем: измерения, которых сейчас нет (knip / jscpd).
Готово, когда: оба инструмента в CI с framework-aware конфигом; ноль ложных от Nest/Next/tRPC.

E1.4 — Ноль поблажек как инвариант

Зачем: конечная цель — пустой список исключений.
Готово, когда: блоки per-file exemptions пусты; ratchet не даёт новым появиться.

Ось 2 — Архитектура C4 · Clean/Hexagonal · ADR

E2.1 — C4-диаграммы + дополнить ADR

Готово, когда: есть Context/Container/Component-диаграммы; ключевые решения — в docs/adr.

E2.2 — Границы слоёв как тест CI fitness function

Готово, когда: запрещённый импорт через границу = красный CI (eslint-boundaries / dependency-cruiser), не ревью на глаз.

E2.3 — Закрыть утечку Prisma-типов

Готово, когда: репозитории возвращают доменные типы, не сырые Prisma-строки (см. repository-scope-guard).

E2.4 — Единый источник для traffic-light/enum

Готово, когда: TrafficLightStatus из packages/shared — единственный; ноль локальных перетипизаций.

Ось 3 — Связь с идеей DDD · трассируемость · OpenSpec

E3.1 — Документ видения продукта

Готово, когда: есть явный north-star продукта (проблема, пользователи, ценность), на который ссылаются спеки.

E3.2 — Матрица способность → спека → код → тест

Готово, когда: каждая способность прослеживается до спеки и до теста; пробелы видимы.

E3.3 — Полный глоссарий CONTEXT.md

Готово, когда: все доменные термины определены однозначно; код использует их же имена.

Ось 4 — Процессы и Production DORA · 12-factor · OWASP ASVS

E4.1 — Зрелость CI/CD

Готово, когда: стадии (lint/type/test/build/e2e), кэш, превью-окружения, авто-откат.

E4.2 — DORA-метрики

Готово, когда: частота деплоя, lead time, % сбоев, время восстановления — измеряются автоматически.

E4.3 — Production-readiness чеклист

Готово, когда: secrets/конфиг по 12-factor, миграции append-only, бэкапы, health/readiness, лимиты — закрыты.
⚠ Здесь снимается режим «MVP: база одноразовая» — это явный переход.

E4.4 — Безопасность (OWASP ASVS baseline)

Готово, когда: ASVS-базовый уровень пройден; dependency-audit в CI; SAML/authz проверены.

E4.5 — Definition of Done + Release + CHANGELOG

Готово, когда: DoD кодифицирован, Conventional Commits + SemVer + генерируемый CHANGELOG.

Ось 5 — Разработка и обучение Testing-Trophy · observability · DX

E5.1 — Онбординг за 30 минут

Готово, когда: один скрипт поднимает всё; README-quickstart; новый человек видит данные за полчаса.

E5.2 — Здоровье тест-пирамиды

Готово, когда: баланс unit/integration/e2e осознан; цель покрытия; проба mutation-теста на ядре.

E5.3 — Полнота наблюдаемости

Готово, когда: трассы ↔ логи ↔ ошибки связаны (OTel/Sentry/LGTM уже есть — закрыть пробелы).

E5.4 — Учебный тур по коду

Готово, когда: есть «архитектурный тур» (как читать репозиторий) + ADR как учебник принятых решений.

6. Движок ночного исполнения

Ты запускаешь один оркестратор-Workflow roadmap-grind и уходишь. Он идёт по эпикам в порядке зависимостей, между ними — зелёный гейт-чекпойнт, при падении возобновляется с последнего чекпойнта (читает зафиксированный git, не память агента). Полный дизайн и скелет оркестратора: docs/roadmap-execution-engine.md.

AUTO 4 · SUPERVISED 10 · HUMAN_GATE 6  (скептик понизил E4.4 SAML/authz и E5.3 горячий OTel-путь до HUMAN_GATE ⬇) 

flowchart TD
    Start([Запуск оркестратора roadmap-grind]) --> Resume{Есть незавершённый прогон}
    Resume -->|да| LastGreen[Возобновить с последнего зелёного чекпойнта из git]
    Resume -->|нет| FreshQueue[Построить очередь эпиков по dependsOn]
    LastGreen --> Pick
    FreshQueue --> Pick

    Pick{Очередь не пуста} -->|нет| Finalize[Финальные гейты, перезапуск стенда, утренний отчёт]
    Pick -->|да| Next[Взять следующий эпик готовый по зависимостям]
    Next --> DepCheck{Зависимости выполнены}
    DepCheck -->|нет| Skip[Отложить эпик, взять следующий независимый] --> Pick
    DepCheck -->|да| Idem{Уже сделано archived или merged}
    Idem -->|да| Pick
    Idem -->|нет| Worktree[Создать git-worktree, cwd залочен на путь worktree]

    Worktree --> Classify{Класс автономности}

    Classify -->|AUTO| RunAuto[Skill-исполнитель в worktree]
    Classify -->|SUPERVISED| RunSup[Skill-исполнитель в worktree]
    Classify -->|HUMAN_GATE| GrillFirst[Plan-grill - свежий Opus-скептик пока нет Codex]

    GrillFirst --> CharTest[Characterization-тест ПЕРВЫМ, зелёный на ДО-коде]
    CharTest --> RunHG[Skill-исполнитель в worktree, поведение-сохраняющий срез]

    RunAuto --> Audit[Аудит эпика - поведенческий оракул]
    RunSup --> Audit
    RunHG --> Audit

    Audit --> Gate{4 гейта зелёные typecheck lint test build}
    Gate -->|RED| Halt[Остановить fail-closed, переоткрыть это изменение] --> EnqFix[Очередь человеку: красный гейт] --> Pick
    Gate -->|GREEN| Behavior{Поведенческий оракул совпал, golden-master не разошёлся}
    Behavior -->|нет| Halt
    Behavior -->|да| Branch{Класс автономности}

    Branch -->|AUTO| CommitArchive[Коммит + openspec-archive = чекпойнт] --> Pick
    Branch -->|SUPERVISED| OpenPR[Ветка + Pull Request, НЕ мёржить] --> EnqReview[Очередь человеку: ревью PR] --> Pick
    Branch -->|HUMAN_GATE| Pause[Пауза в точке решения] --> EnqDecision[Очередь человеку: одобрить дизайн и diff] --> Pick

    Finalize --> Done([Отчёт готов, без авто-push в main])

Три класса автономности

  • AUTO — идёт ночью без присмотра: коммит + архив. Доки, аудиты, мёртвый код, снятие поблажек.
  • SUPERVISED — агент доводит до ветки и открывает PR, НЕ мёржит; ждёт твоё ревью.
  • HUMAN_GATE — пауза в точке решения; рискованное (горячий код, SAML, схема/миграции) сам не доводит.
