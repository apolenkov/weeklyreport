# Design

## Context

The selected D37-F13 roots are existing UI-state consumers. No server contract changes. Provider baseline controls pass; schema-admitted pending tests and unmeasured embeddings fail at the public card.

## Goals / Non-Goals

Preserve lifecycle, stage ownership and read-only rules. No new defaults, resource operations, authorization, redesign or performance policy.

## Decisions

Share the existing pending-execution predicate between action eligibility and workflow explanation, and one null-measurement label between actual diagnostic consumers. Distinct typed form callbacks preserve reasoning-error clearing and endpoint resets. Retry autofocus follows explicitly requested next-page failure. Only resolved products can be zero-owned-stage dead ends; Risk uses the existing ParentPicker error channel. Confirmation checks current read-only state without forcing dismissal.

## Risks / Trade-offs

JSDOM proves component state and callbacks, not native focus/layout or server acceptance. Root owns browser/AT and aggregate gates. Report lifecycle tuples, canonical middleware and destructive guards stay unchanged.

## Migration Plan

No schema or data migration. Scoped patch delivery and source-only rollback.
