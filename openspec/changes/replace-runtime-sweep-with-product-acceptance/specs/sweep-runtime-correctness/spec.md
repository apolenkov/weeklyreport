## ADDED Requirements

### Requirement: Runtime correctness MUST be proven without an exhaustive interaction platform

The existing React warning, hydration, accessibility, console-source, and behavior-focused assertion requirements MUST be verified by focused unit/integration tests, the catalog route sweep, or bounded critical-journey acceptance. No correctness requirement in this capability may require a continuation graph, campaign ledger, per-control exhaustive traversal, or AI-import protocol as its sole evidence source.

#### Scenario: A runtime correctness regression is introduced

- **WHEN** a cataloged route or critical journey emits a covered React warning, hydration error, unclassified console/network failure, or targeted accessibility violation
- **THEN** a focused gate or bounded browser scenario fails and identifies the affected product surface
- **AND** no exhaustive interaction campaign is needed to reproduce the regression
