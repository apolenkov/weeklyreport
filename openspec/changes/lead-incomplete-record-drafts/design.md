## Goals / Non-Goals

Capture primary text durably with honest null details; retain every existing authorization, parent/stage, identity/comment, submission and lifecycle invariant except the deliberate relaxation of draft detail completeness. No invented severity, ownership, text or context. No new retention job, automatic incomplete carry, general draft store, reopen permission, item workflow change or duplicate save coordinator.

Period dual-state writes remain atomic through the existing transition builder. The seven canonical procedure builders (reference-identical `leadProcedure`) and destructive DB guard are unchanged. Reviewer/admin privilege is not private-draft access. Existing complete content in unsubmitted sections remains publishable.

## Decisions

### 1. One stored row, distinct contracts

Use existing Risk/Decision tables, not a parallel draft table. Only `Risk.impact`, `Risk.mitigation`, `Decision.impact` become nullable. Primary text, severity, owner, parent XOR and Product-stage/Activity-no-stage invariants stay required. Completeness is derived from these nulls, not a persisted boolean that can disagree. Existing stored non-null text remains readable through stored-text rules; new non-null writes use safeText. Empty detail controls normalize to null; reject other malformed nonblank values. No retroactive normalization or refreezing of old snapshots.

Shared owner exports separate draft write/read versus strict submit/complete/published schemas and reusable completeness predicates. Public projections are complete-only even when the caller is the author using ordinary search. Private author form and recovery alone carry incomplete text. On the author form, incomplete risks are visible but do not floor statuses or satisfy coverage completeness; the label and missing-detail guidance prevent a green status being mistaken for “no risk”. All existing references to a _covering_ risk in alarm/lock contracts mean a complete covering risk under the modified derivation requirements; item progress, stage defaults, raw empty status and foreign complete-risk attribution stay unchanged.

Before:

`form → filter incomplete rows → strict draft schema → CAS → delete/recreate → mapper(all risks) → all-section snapshot/index/PDF`

After:

`form → nullable draft + deletion intents → validated own context → locked authoritative reconciliation → CAS → comment-preserving rewrite → matching receipt`

`raw section → scope + partition complete/incomplete → complete-only status derivation → reviewer content + omission metadata → same-state snapshot/index → scoped job snapshot → print`

`retained own source → private read-only recovery → explicit create in eligible current target → new stableId + normal draft save`

### 2. Reject omission; do not silently merge

Choose rejection over the earlier alternative “preserve or reject”: silent merge makes receipts and strict submission harder to explain. Add optional `deletedIncompleteRecords` to save/submit input, defaulting to an empty list for old clients. Each entry is `{kind: "risk" | "decision", stableId}`; enclosing section ID and expected version bind it to one authoritative collection. This is an explicit user delete intent, not a generic tombstone store. Reject duplicate entries, foreign/nonexistent identities and simultaneous include-and-delete. Resolve IDs by kind + section + stableId; physical IDs may remint and cannot be the deletion key. A stale version remains a conflict, not an invitation to reinterpret delete intent.

Retain the existing service validation order and locked lifecycle/deadline/lineage/CAS guards. Extend the authoritative published-lineage check, before CAS or child clearing, to reject making a published decision incomplete with `PUBLISHED_RECORD_LOCKED`. Identify Impact and ask the author to restore it or supply a valid replacement; keep the rejected edit visibly unsaved, without inventing text. Published item/decision deletion remains forbidden; this adds no published-risk protection. Never-published decisions and risks may become incomplete. No new publication-history store or public stableId metadata is needed: a protected decision stays complete and therefore survives P2's snapshot/index replacement. Regression: sole witness D in P1 → reopen → rejected impact clearing → P2 with D → reopen → rejected deletion, also after projection rebuild/cache reset.

Within the transaction, after the version guard and before child clearing, read authoritative existing incomplete rows, detect omission and validate the resulting collection (strictly for submit). A validation exception rolls back even a provisional version bump; response reports no committed mutation. Reject omitted incomplete rows unless explicitly deleted. Completion is inclusion of the same identity with complete detail, not delete/create. The published-lineage guard remains stronger than explicit deletion. `report-record-ordering` distinguishes its lineage subcheck from final replacement: never-published complete decisions and items remain deletable by omission; never-published incomplete risks/decisions require intent.

Apply the invariant to every replacement path, including fill-from; do not weaken fill-from's existing source/lineage guards. Additive carry writes retain target private rows. Existing complete-row deletion semantics are unchanged. Invalid edits to the primary text of an existing row cannot drop that row through a client filter: keep the last durable row and visibly unsaved edit, or reject the replacement. Comments on surviving identities preserve IDs/authors/timestamps through recreation; no copying comments to a recovered new identity.

Fill from previous is not recovery copy: exclude incomplete source risks/decisions before `isCarryable`/row mapping, even if Product-parented rows would otherwise copy. Preserve complete-source mapping, fresh target stableIds, existing Product behavior after stage reassignment, removed-Activity exclusion and complete decision `resolvedAt` copying. Expose an entitled own-source notice/link to retained recovery in the existing Fill From flow; explicit recovery copy alone revalidates target context and resets resolution metadata. Extend Fill From input with the same optional target deletion-intent list; source exclusion never supplies target deletion consent. Mixed-source, changed-stage, removed-Activity, resolved-decision and incomplete-target regressions must assert source immutability separately from target guards.

Use the existing TASK-836 immutable-request/receipt coordinator. Retry a lost ACK only with the same payload, expected version and identities; a conflict requires uncached authorized reconciliation of the whole request, not a matching-text heuristic or replay at a new version. Record-specific saved-incomplete state requires exact matching scope, generation, stableId and normalized fields. Cancel after dispatch requires resolved outcome and explicit identity-targeted compensation. This change does not claim the separate receipt package is implemented.

### 3. Shared projection before every derivation

Projection hiding is not reviewer command authorization. Reviewer comment creation and deletion must re-resolve the anchor's current kind, stableId, section author and completeness after the existing User → Report locks. If actor is not section author and the risk/decision is currently incomplete, reject with the established inaccessible-anchor not-found response (`Record not found.` for creation; inaccessible comment not-found for deletion), never a completeness-specific disclosure. There is **no exception for deleting one's existing reviewer comment**, nor for nonauthor Head/admin. Preserve comments through incomplete saves and later completion. Whichever operation wins serialization determines behavior: a comment committed first survives; an incomplete save committed first blocks the comment. Normal complete-anchor, item, verdict and acknowledgement permissions remain unchanged; authorship does not itself grant reviewer rights, and the sibling item-only Lead reply route is not widened.

Implement one completeness/partition policy in shared; use it in report-persistence before Product/Activity mapping, referenced-only membership, status floors and all aggregates. Keep author mapping nullable but pass only complete risks into its status derivation. Introduce an explicit complete projection entry point rather than changing the author mapper to hide its own drafts. Cross-author/Everyone, weekly live reads, preview and freeze consume that projection. Apply the existing group/shared-product lens before serializing omission metadata. Preserve owned Product membership even if it has no complete records; do not introduce a referenced-only card solely to reveal private draft context.

Omission metadata on each new frozen section is versioned, known, and derived from the same raw rows as its complete content. Store aggregate buckets keyed by record kind, parent kind/id and the canonical set of stage names with a count; no text, record stableIds, comments or free-form titles. Bucket stage sets allow counting once when a multi-stage risk overlaps several selected stages. Public group-only views may expose only totals; strip unrelated buckets before a subject-scoped response. Missing legacy section metadata is unknown, not a parser default of zero. Malformed present metadata fails integrity checks. Summary shape distinguishes known risk/decision subtotals and unknown coverage; mixed unknown never becomes an exact total. Empty authorized scope returns empty disclosure, not unknown existence for inaccessible sections.

Show counts separately from pending sections, escalations and submission counts. Head confirmation shows its authorized scope and labels it as scoped, not global; the committed snapshot is authoritative if a save changes counts after preview. Viewer default submitted-only view counts only shown authorized sections, Show all adds authorized drafts. Newly published view counts every included section. Copy says records were excluded and the report may be incomplete, never “no risks”.

### 4. Publication serialization must be strengthened

Manual publication already participates in `lockStatusGraph`; section saves acquire the same lane before Report. For automatic publication, join that same lane **before** reminder-policy or graph reads and use ReadCommitted, matching the manual strategy. Do not acquire a RepeatableRead snapshot in a statement waiting on the advisory lock and assume it refreshes afterwards. Preserve automatic deadline and full lifecycle predicates exactly; do not call the manual helper or require a submitted section on auto-publish. Manual still requires at least one submitted section.

Graph lane → reminder policy locks → guarded Report write → fresh graph freeze is the coordinated publication order; saves take graph lane → Report → section CAS. Freeze content, omission buckets, scope projection and search documents inside the winning transaction. Assignment writers already use the graph lane; implementation must test against actual source and detect any writer that bypasses the lane rather than rely on comments. A save before the lane is acquired appears in both content and counts. A publish that wins first closes the subsequent save. Failure/zero CAS produces no publication side effects.

Reopen leaves the previous snapshot representation alone; republish replaces `Report.publishedSnapshot` and its projections. There is no claim that this single column stores all historical publication versions. Already-created PDF jobs retain P1; P2 cannot mutate their content. Retained private rows are current source rows, not an immutable omission revision ledger.

### 6. Private recovery is a narrow own-section read

Add a dedicated retained-drafts query using canonical `leadProcedure`, authenticated actor identity and a report/section pair, never caller-supplied author authority. Query current active entitled user and exact `ReportSection.authorId` together; preserve the builder's established role coverage, with ownership mandatory even for Head/admin. Existing own-section access is not conditional on continuing to own each source Product stage: loss of assignment forbids copying to that context, not reading one's retained text. Group or co-owner scope does not grant private recovery. Invalid current identity/role or no own source returns no content; do not add a new privilege to compensate.

Apply that **same current-role predicate to every private nullable-text and retained-discovery path**, not only the new query: `reports.getActive`/`getActiveSection`, `reports.myHistory`, `leadForm.byPeriod`, `leadForm.statusOverview`, recovery, and Fill From's source notice. Pass actor identity into service reads; a cached `activeReportSectionId` is not authorship proof. Use canonical builders unchanged plus one shared service/query authorization policy based on current database user activity/role and exact section authorship in the protected read's authorization observation. Cached session roles and cached response bodies must not bypass the current check; scope/invalidate server caches and clear private client caches on observed entitlement loss. This cannot retract previously delivered text and does not require a new authorization framework.

Mixed existing routes keep their existing admission for complete content/history: an active demoted author receives only otherwise authorized complete projections, without private retained counts, links, draft IDs, text or discussion. Dedicated recovery denies as inaccessible. Inactive users stay denied by normal authentication; nonauthor Head/admin receive only their existing public scoped content. Public live/frozen omission notices remain governed by report scope, not private retained discovery; they must not be suppressed or mislabeled as retained counts by this rule. Test freshly hydrated demotion, cached pre-demotion session, inactive user, stale foreign section pointer, exact own source, nonauthor leadership and still-entitled author after stage reassignment on every named route. No global conversion of `reports.myHistory` to authoring-only access is permitted.

History discovery must include old open, archived-unpublished and published sources. Read-only recovery does not use the latest viewer route or `ensureLeadSection`, and never creates rows. Frozen omission counts and currently retained draft counts are distinct: restored snapshots may have no live source, and reopened sources may have changed. State “source draft unavailable” for a legitimately removed source; no permanent retention promise. When reopened, the normal authoring path controls edits; recovery itself stays read-only.

Explicit copy prefills primary and available detail text into a currently editable, own eligible target. Revalidate parent and stages, let the author choose changed context, retain explicit severity and derive owner from target author. Save creates a new stableId; its retry uses that same new ID. Source identity, comments, dates representing resolution and historical status are not silently cloned; normal create date rules apply. No target write or source deletion until the user saves; no automatic carry or reopen.

## Risks / Trade-offs

- Global graph-lane contention → reuse the existing lane rather than introduce another lock hierarchy; exercise queued auto-publish/save and assignment changes in guarded integration tests.
- Nullable rows leak through an untraced direct query → source-owner consumer matrix plus negative fixtures for byPeriod/Everyone, raw SQL and assistant before enabling writes; do not regard mapper tests as exhaustive protection.
- Old clients cannot parse nullable own drafts → fail visibly/reload to upgraded client; no fake fields and no silent deletion. Server omission rejection protects their writes. Coordinated deployment avoids mixed old servers writing the new data.
- Omission metadata itself leaks context → scope before serialization, no record IDs/text, and separate scoped counts from existing organization progress metrics.
- Multiple changes touch the same web/schema files → single owner per file and integrate dependent quick-entry work serially; no competing workers.

## Migration Plan

1. Confirm deployment state with the gate. Default to a forward additive migration: relax only three detail columns, extend frozen scope totals as nullable, preserve all parent/severity/lineage checks and generated full-text columns. Existing complete rows stay byte-equivalent. A preproduction canonical-init rebaseline is allowed only after proving no production deployment and retaining its contract test; this specification does not authorize a reset of the owner's preview.
2. Deploy shared readers, projection filtering, old-client omission guards, published-decision completeness guard, Fill From source exclusion and target protection, locked reviewer create/delete checks, all-route private-read entitlement, recovery and consumer transports together while incomplete creation remains unavailable. Regenerate Prisma. Rebuild scope projections from validated existing snapshots; legacy unknown remains null. Do not mutate historical snapshot JSON or completed PDF jobs.
3. Drain old API/web processes before allowing new nullable saves. Enable only when every consumer and source writer in the matrix is covered and the gate has independent review, DB race tests and browser evidence. Use deployment sequencing, not a speculative permanent feature-flag framework.
4. Rollback before nullable writes can restore the prior application after schema compatibility checks. After nullable writes exist, disable new capture but keep null-aware reads, protection and recovery; fix forward. Never set NOT NULL, delete drafts or invent details to force an old binary to run. Narrowing storage requires all affected authors' explicit completion/deletion through eligible flows and separate verified migration.
