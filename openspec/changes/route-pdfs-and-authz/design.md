## Context

PDF export is fully wired. The BullMQ worker writes `{pdfDir}/{jobId}.pdf` and
stores `artifactUrl = '/pdfs/{jobId}.pdf'` on the export job row. The frontend
polls export status and, on `completed`, calls
`window.open(data.artifactUrl, '_blank')`
(`apps/web/src/components/weekly-report/export-pdf-button.tsx`).

Two production-only gaps (invisible in local dev):

1. **Routing (P0-3).** The Caddy `@api` matcher in both Caddyfiles lists
   `/trpc /auth /health /metrics /admin/queues` but not `/pdfs`. The relative
   download request therefore reverse-proxies to `web:3000` and 404s. The dev
   `next.config.ts` rewrite list omits it too.
2. **Authz (P0-11).** `apps/api/src/main.ts:353` mounts
   `express.static(pdfDir, { fallthrough: false })` with no authentication.
   `docker-compose.prod.yml:199` publishes the API port to the host
   (`${API_PORT:-3001}:3001`), so the static files are readable by job-id guess
   off-edge. The council raised this independently (Codex High, Kimi Critical).

Key constraint that shapes the design: the **session is a cookie**.
`trpc.context.ts` reads `req.cookies.customreport_session`. A same-origin
`window.open` GET carries that cookie automatically — so an authz-checked
download handler can rely on the ambient session with no client change to how
the link is opened.

## Goals / Non-Goals

**Goals:**

- PDF download works end-to-end in production, staging, and local dev.
- An artifact is streamed only to a caller who is the job's `requestedBy` OR has
  role+scope read access to the bound report.
- No unauthenticated path to artifact bytes remains on any port.
- Reuse the existing session-verification + revocation + `isActive` pipeline.

**Non-Goals:**

- Removing the direct host-port publication in `docker-compose.prod.yml`
  (broader deploy-seam, also exposes `/metrics`; owned by `BL-DEPLOY-SEAM-MISC`
  and P1-11). It is defense-in-depth here, not the fix.
- Touching the inbound PDF worker token (`signPdfExportToken` /
  `verifyPdfExportToken`) used by the headless Playwright render — a separate
  path.
- Persisting the PDF checksum (`BL-PDF-CHECKSUM-DEAD`).

## Decisions

### D1 — Authorize via the ambient session cookie, not a signed URL token

`window.open` issues a credentialless GET (no `Authorization` header), but the
session lives in a cookie, so the GET is in fact authenticated same-origin. The
download handler verifies `customreport_session` with the existing
`verifySessionToken`, then authorizes against the bound job.

Alternatives considered:

- **Signed-URL token in `artifactUrl`** (reuse `signPdfExportToken`). Rejected:
  unnecessary given the cookie is already carried; a token in the URL leaks via
  history/referrer/logs and adds an expiry-window foot-gun. Keep that token for
  its existing single purpose (worker render auth), not for user downloads.
- **tRPC procedure returning bytes.** Rejected: tRPC is JSON-shaped; binary
  streaming with a browser-native download belongs on a plain GET route.

### D2 — Replace the static mount with an Express download handler at `/pdfs/:file`

Mount a handler on the same `/pdfs` base in `main.ts`, removing the
`express.static` mount entirely. The handler:

1. Reads + verifies the session cookie; runs the revocation fast path and the
   `isActive` check (the same three steps `trpc.context` performs). Fail → 401.
2. Parses `jobId` from the path, loads the export job, reads `requestedBy` and
   the bound `reportId`.
3. Authorizes: caller is `requestedBy` OR passes the report read check
   (role + group scope) reused from the report read path. Fail → 403.
4. Streams the file from `pdfDir` with `Content-Type: application/pdf` and
   `Content-Disposition: attachment`; missing file → 404.

Replacing the mount (not merely adding a Caddy matcher) is what actually closes
P0-11: once no unauthenticated `express.static` exists, the direct host port
serves the same authz-checked handler, so the bypass is gone on every port.

Alternative: keep `express.static` and gate it with Caddy `forward_auth`.
Rejected: leaves an unauthenticated mount reachable on the direct host port, and
splits authz across two systems.

### D3 — Authorization predicate is requester OR report read access

The role model lets a viewer/head download a published report PDF generated by
someone else, so `requestedBy` alone is too narrow. The predicate is
`caller === job.requestedBy` OR caller has role+scope read access to
`job.reportId`. The scope half reuses the same group-scope read check the report
surfaces already apply, so authz stays single-sourced.

## Risks / Trade-offs

- **[Cookie not sent if download ever moves cross-origin]** → keep the artifact
  URL relative/same-origin (it already is); document the invariant in the
  handler.
- **[Streaming a file from disk in the request path]** → bounded: single
  report-sized PDF, attachment disposition; stream rather than buffer.
- **[Removing the static mount could regress an unknown consumer]** → grep
  confirms the only consumer is `export-pdf-button.tsx` via `artifactUrl`;
  the download path stays `/pdfs/{jobId}.pdf`, so the URL contract is unchanged.
- **[Direct host port still exposes other API surfaces]** → out of scope here;
  the PDF bypass itself is closed by D2. Cross-reference P1-11 / deploy-seam.

## Migration Plan

1. Add `/pdfs /pdfs/*` to `@api` in both Caddyfiles; add the `/pdfs/:path*`
   dev rewrite in `next.config.ts`.
2. Ship the authz download handler and remove the `express.static` mount in the
   same change so no unauthenticated window exists between deploys.
3. Deploy API before/with the edge config; the handler keeps the same
   `/pdfs/{jobId}.pdf` shape, so already-issued `artifactUrl`s keep working.
4. Rollback: revert the Caddy matcher + handler together. There is no schema or
   data migration to undo.
