# Тотальное ревью скила `agent-council` — 2026-07-10

> **Статус на 2026-07-10, после ревью:** все находки P1 и весь блок P2-предохранителей
> исправлены в коде, покрыты тестами (было 14, стало 33) и проверены живьём. Прошли
> три раунда: базовые фиксы → регрессы из adversarial-верификации → «fail closed»
> для full-режима по замечанию Codex (прогон возвращает 0 только если билд завершён,
> proof прошёл и вердикт APPROVED; провал proof, REVISE или убитый builder дают 1).
> Не сделано одно: симлинк `~/.claude/skills/agent-council` — установку в собственную
> конфигурацию агента должен выполнить пользователь (команда в конце файла).
> Ниже — исходный текст ревью; он описывает состояние ДО починки.

**Вердикт: харнесс сделан крепко, но три обещания из его же документации не выполняются, а в Claude Code скил вообще не виден.**

1. **Ревьюер в full-режиме не видит новых файлов.** `gitDiffForReview` зовёт голый
   `git diff` — новые файлы (обычный результат работы builder-а) в него не попадают.
   Ревьюер получает `(empty)` и штампует `APPROVED` коду, которого не читал.
2. **Недоверенный вывод детей протекает из-под фенсов в родительский промпт.**
   `architecture.md:95` обещает: «Child outputs are fenced and treated as untrusted data».
   Position/Confidence вставляются в метаданные и в таблицу без фенсов.
3. **Скил не установлен туда, где Claude Code ищет скилы**, хотя `ADR 0002:17`
   называет Claude Code одним из двух поддерживаемых хостов.

Отдельно: гейт `--allow-writes` **не** пробивается злоумышленником — но обходится
собственной опечаткой в конфиге. Это дыра в защите от дурака, не в защите от врага.

## Модель угроз, по которой калибровались severity

Скил объявляет её сам, и я держусь её, а не собственных интуиций:

- `ADR 0001:32` — «It is a workflow harness, **not a security boundary** against malicious repositories».
- `architecture.md:97` — «This is not a security sandbox for hostile code. Run the council only in a **trusted local workspace**».
- `architecture.md:95` — недоверенным объявлен **вывод детей**, не конфиг.

Отсюда деление:

- **Ломается на честном конфиге и честном прогоне** → P1. Это сломанные обещания.
- **Требует неверного конфига** (его пишет сам пользователь, у которого и так есть shell) →
  P2: отсутствующий предохранитель, а не эскалация привилегий.
- **Вывод ребёнка пробивает контейнмент** → P1, потому что это ровно тот единственный
  периметр, который скил обещает держать.

Первая версия этого отчёта ставила «writable seat как advisor» в P0 и выносила в
заголовок «full-mode небезопасен». Это была ошибка калибровки: чтобы туда попасть,
нужно самому вписать в конфиг seat с `write_mode: true` и поставить его в advisors.

## P1 — сломанные обещания, без неверного конфига

### Full-режим: ревьюер не видит того, что написал builder

`scripts/agent-council.mjs:1995`

`gitDiffForReview` запускает только `git diff --stat` и `git diff` — это рабочее
дерево против индекса, по отслеживаемым файлам. Ни `--cached`, ни `HEAD`, ни
untracked. Full-режим стартует с чистого дерева, значит типичная работа builder-а
(новый модуль + новый тест) — это untracked-файлы, и `git diff` печатает пустоту.
Ревьюер получает в промпте `## git diff\n(empty)` при инструкции «Review the diff
like a contributor PR» и выносит вердикт по самоотчёту builder-а.

Собственная e2e-фикстура скила создаёт именно untracked-файл — то есть тест
воспроизводит баг и не замечает его.

Смежно: `spawnSync` в этой функции не проверяет `status`/`error`. Диф больше
1 MB (`maxBuffer`) убивает child по ENOBUFS, `stdout` = null, ревьюер снова видит
`(empty)`. Большие изменения — ровно те, где ревью нужнее всего.

**Починка:** `git add -N .` перед снятием дифа, либо `git diff HEAD` + список
untracked из `git status --porcelain`; проверять `status`/`error` обоих вызовов.

### Недоверенный вывод ребёнка попадает в родительский промпт без фенсов

`scripts/agent-council.mjs:1381`, `scripts/agent-council.mjs:1469`

`architecture.md:95` обещает, что вывод детей фенсится и считается недоверенными
данными. Фактически:

- `extractedPosition` и `extractedConfidence` (текст, который написал ребёнок)
  подставляются в буллеты метаданных и в markdown-таблицу **без фенсов** —
  только экранирование `|` и обрезка до 180/240 символов.
- Извлечение заголовков (`^##\s+(Position|...)$`) не различает код-фенсы и берёт
  **первое** совпадение. Ребёнок, который эхом вывел шаблон промпта внутри фенса,
  получает свои «секции» распознанными оттуда, а настоящие — отброшенными как дубли.

Значит скомпрометированный или просто болтливый advisor может подделать структуру
промпта, который читает родитель-агент. Это единственный периметр, который скил
обещает держать, — и он дырявый.

Верификаторы поставили сюда P2. Я поднял до P1 по объявленной модели угроз:
недоверен именно вывод детей.

**Починка:** прогонять `position`/`confidence` через `fenced()` либо жёстко
санировать (одна строка, вырезать backticks и `#`); при извлечении игнорировать
заголовки внутри код-фенсов.

### EPIPE от stdin-seat роняет весь консилиум

`scripts/agent-council.mjs:951`

`child.stdin.end(prompt)` без обработчика `error` и без колбэка. Если CLI умирает
не дочитав stdin (плохой флаг, протухшая авторизация, SIGTERM по таймауту посреди
записи промпта >64 KB — а промпты builder-а как раз такие), запись падает с EPIPE,
это необработанное событие `error` на сокете, Node бросает, оркестратор умирает
целиком. Работа всех живых seats теряется, их детачнутые дети остаются сиротами.

**Починка:** `child.stdin.on("error", () => {})` перед записью.

### Ctrl-C оставляет сиротой writable builder

`scripts/agent-council.mjs:945`

Каждый ребёнок спавнится с `detached: true` (POSIX) — он лидер своей группы.
В файле **ни одного** `process.on`. Ctrl-C доставляет SIGINT только группе
переднего плана, то есть оркестратору; он умирает, а `codex exec
--dangerously-bypass-approvals-and-sandbox` продолжает править репозиторий, когда
пользователь уверен, что прогон отменён. Таймеры терминации умерли вместе с родителем.

**Починка:** вести список живых детей, повесить `SIGINT`/`SIGTERM` и звать
`terminate()` по каждой группе.

### Proof-команда без таймаута вешает консилиум навсегда

`scripts/agent-council.mjs:1113`

`runShellCapture` → `spawnSync(command, {shell: true})` без `timeout` и без учёта
глобального дедлайна. Гейт `assertBuildAllowed` требует proof-команду, но не
ограничивает её. Зависший тестовый прогон вешает всё.

**Починка:** передать `timeout` в `spawnSync`, вычесть из остатка дедлайна.

### Обрезка вывода молча выключает fix-раунды

`scripts/agent-council.mjs:2027`

`verdictOf` якорит `VERDICT:\s*REVISE\s*$` в конец **всего** stdout. Но
`createCapture.value()` при переполнении дописывает последней строкой маркер
`[agent-council: output truncated at N chars]`. Длинное ревью → якорь не совпадает
→ вердикт `""` → fix-раунды не запускаются, и сам факт нигде не фиксируется.
Та же обрезка режет хвост, где вердикт и стоял.

**Починка:** искать вердикт построчно с конца, игнорируя служебный маркер;
записывать распознанный вердикт в артефакты.

### Артефакты full-режима теряют то, ради чего он существует

`scripts/agent-council.mjs:798`, `scripts/agent-council.mjs:785`, `scripts/agent-council.mjs:1396`

- В `build-report.json` и в родительский промпт попадает только proof **нулевого**
  раунда; proof-и, перезапущенные после фиксов, выбрасываются.
- `reviewerResult` перезаписывается каждый fix-раунд, поэтому именно те ревью,
  которые потребовали правок, не сохраняются нигде.
- Секция Build Phase родительского промпта отдаёт только `extracted`, а у builder-а
  шесть обязательных заголовков никто не просил (`buildBuilderPrompt` их не требует).
  Значит список изменённых файлов, отступления от плана и строка `BUILD: COMPLETE`
  до родителя не доходят вообще.

**Починка:** накапливать `proofs[]` и `reviews[]`; в промпт builder-а добавить
требование тех же шести заголовков либо перестать считать его `incomplete`.

### Консилиум выходит с кодом 0, даже когда сдохли все seats

`scripts/agent-council.mjs:245`

`process.exitCode = 1` выставляется только в `main().catch`. Прогон, где все
советники упали, таймаутнулись или уткнулись в дедлайн, печатает нормальный
промпт синтеза и возвращает 0. Ни один вызывающий скрипт — включая
bash-инвокацию из самого `SKILL.md` — не может проверить результат по коду возврата.

**Починка:** ненулевой код, если `health.statuses.ok === 0` (или по порогу).

### Скил не виден Claude Code, хотя ADR называет его хостом

`references/architecture.md:198`, `SKILL.md:4`

`ADR 0002:17`: «The same skill should work when invoked from Codex or Claude Code».
Но установочные раскладки в документации — `.agents/skills/` и `~/.agents/skills/`,
а Claude Code сканирует только `.claude/skills/`, `~/.claude/skills/` и плагины.
Скила нет ни в одной из этих директорий: в Claude Code он недоступен ни модели,
ни пользователю.

Frontmatter при этом написан именно под Claude Code и внутренне противоречив:

- `disable-model-invocation: true` запрещает модели вызывать скил — но `description`
  написан как триггерное описание для модели («Use when the user wants a council…»).
  Пользовательский вызов `/agent-council` при этом работает; описание просто мёртвый груз.
- `allowed-tools: Bash(node ${CLAUDE_SKILL_DIR}/scripts/agent-council.mjs *)` —
  `${CLAUDE_SKILL_DIR}` документирован для bash-инъекций, но **не** для `allowed-tools`
  (там документирован только `${CLAUDE_PROJECT_DIR}`). Даже если он раскроется, то в
  абсолютный путь, а тело `SKILL.md` велит звать относительным
  `node .agents/skills/agent-council/scripts/agent-council.mjs …`. Bash-паттерны
  сравниваются текстуально, без нормализации путей — совпадения не будет, каждый
  документированный вызов упрётся в запрос разрешения.

**Починка:** `ln -s ~/.agents/skills/agent-council ~/.claude/skills/agent-council`
и добавить этот шаг в packaging; выровнять `allowed-tools` с реальным написанием
команды; убрать `disable-model-invocation` либо переписать `description` как
«вызывается только пользователем».

## P2 — предохранители, которых нет (нужен неверный конфиг)

### Writable seat можно поставить в advisors, и никакой гейт не сработает

`scripts/agent-council.mjs:533`

`validateProfile` проверяет advisors только на существование. `write_mode` у
reviewer-а запрещён явно (строка 561) — но лишь внутри ветки `mode === "full"`.
Конфиг с `profiles.soft.advisors: [codex-builder]` проходит валидацию, и soft-режим
спавнит `codex exec --dangerously-bypass-approvals-and-sandbox` без `--allow-writes`,
без чистого дерева и без proof-команды. Проверено вживую.

Дырой в защите это не является: конфиг пишет тот же человек, у которого есть shell.
Но асимметрия («reviewer защищён, advisors — нет») выглядит как недосмотр, а не
как решение.

**Починка:** в `validateProfile` бросать, если любой seat из `advisors` или
`final_reviewer` имеет `write_mode: true`.

### Reviewer из sample-конфига умеет писать, несмотря на `write_mode: false`

`scripts/agent-council.mjs:86`

Шаблонный `claude-reviewer` получает `--allowed-tools Read,Glob,Grep,Bash(git *),Bash(pnpm *),Bash(node *)`
и `--permission-mode dontAsk`. `Bash(git *)` — это `git checkout`, `git reset`,
`git commit`. Валидация `write_mode !== true` при таком наборе инструментов
декоративна. `glossary.md:25` называет этот seat read-only.

**Починка:** убрать `Bash(...)` из шаблонного reviewer-а либо сузить до
`Bash(git diff *)`, `Bash(git status *)`.

### Пустое значение в YAML парсится как `{}`, а `{}` — истинно

`scripts/agent-council.mjs:1596`

`parseYamlObject` для пустого значения кладёт `{}`, тогда как `parseYamlArray` в
той же ситуации кладёт `null`. По YAML пустое значение — это `null`. Последствие:
`proof_cmd:` (оставленный как TODO) даёт `{}`, гейт «Full mode requires --proof-cmd»
пропускает, writable builder отрабатывает и правит дерево, и только потом
`spawnSync({})` падает с `ERR_INVALID_ARG_TYPE` — правки легли, proof не проверен,
ревьюер не запускался.

**Починка:** `object[key] = null` для пустого значения — как в ветке массива.

### `extractThreadId` кладёт недоверенную строку ребёнка в argv привилегированной команды

`scripts/agent-council.mjs:2018`

Первое совпадение `"thread_id":"([^"]+)"` где угодно в stdout builder-а подставляется
в `resume_command`, который запускается с `--dangerously-bypass-approvals-and-sandbox`.
Валидации подставляемой строки нет (хотя валидатор конфига уже запрещает `--last`,
то есть про опасность argv здесь думали).

**Починка:** парсить событие `thread.started` из `--json`-потока, а не первое
совпадение; валидировать по UUID-подобному шаблону.

### `resume_command` без `{thread_id}` проходит валидацию — вопреки собственному ADR

`scripts/agent-council.mjs:585`

`ADR 0002:34` фиксирует требование: «resume commands must use `{thread_id}`, never
`--last`». Код проверяет только половину — отсутствие `--last`. Команда без
плейсхолдера валидна, и fix-раунд молча возобновит не тот тред.

**Починка:** требовать наличие `{thread_id}` хотя бы в одном элементе.

### Гейт чистого дерева проверяется один раз, за минуты до старта builder-а

`scripts/agent-council.mjs:183`

`assertBuildAllowed` зовётся до initial/self-grill/adversarial фаз. По sample-конфигу
это минуты работы CLI. К моменту, когда builder реально стартует, дерево может быть
грязным — оно не перепроверяется. Плюс сам прогон пишет `.agent-council/runs/`
в cwd, из-за чего в чистом репозитории второй full-прогон отваливается по этому
гейту; `--setup-config` не создаёт `.gitignore`.

**Починка:** перепроверять `gitStatusPorcelain` непосредственно перед builder-ом;
дописывать `.agent-council/` в `.gitignore` при `--setup-config`.

### Дубликаты в advisors молча теряют вывод одного из детей

`scripts/agent-council.mjs:529`, `scripts/agent-council.mjs:1024`

Уникальность не проверяется, а `runAdvisorPlan` кладёт результаты в `Map` по имени
seat-а. `advisors: [claude-opus, claude-opus]` спавнит два процесса, второй
перезаписывает первый, фаза показывает один и тот же результат дважды. Ошибка
в потерянном ребёнке невидима. Воспроизведено вживую.

**Починка:** сравнить `advisors.length` с `new Set(advisors).size` в `validateProfile`.

### Санитарный контур permissions привязан к ярлыку `provider`, а не к бинарю

`scripts/agent-council.mjs:894`

Единственный активный контейнмент ребёнка (инъекция `OPENCODE_PERMISSION` +
отключение skills) выбирается по свободному полю `provider`. Seat с
`provider: custom`, запускающий бинарь `opencode`, инъекции не получит. Seats
codex/claude read-only ровно настолько, насколько автор конфига не забыл флаги.

## Порядок починки

1. `gitDiffForReview` — `git add -N` + проверка `status`/`error`. Один час, чинит
   главное сломанное обещание full-режима.
2. `child.stdin.on("error")` — одна строка, убирает падение всего прогона.
3. Ненулевой exit при мёртвом консилиуме — делает скил пригодным для скриптов.
4. Фенсы/санация для `position`/`confidence` + игнор заголовков внутри фенсов.
5. `validateProfile`: запретить `write_mode` в advisors; требовать `{thread_id}`;
   запретить дубликаты; проверять все профили.
6. Парсер: пустое значение → `null`.
7. Обработчики сигналов + таймаут proof-команды.
8. Установить скил в `~/.claude/skills/` (симлинк) и починить `allowed-tools`.

Пункты 1–3 закрывают всё, что реально ломается на честном прогоне, и стоят
меньше дня. Остальное — предохранители и гигиена.
