- `role-home.ts` / `role-visibility.ts` / `safe-next.ts` / `client-logger.ts` / `web-vitals.ts`
  / `pluralize.ts` / `format-date.ts` / `cache-keys.ts` / `client-error-reporting.ts` /
  `query-client.ts` / `trpc*.ts(x)` all have catalog Domain = `auth`, `telemetry`, `shared-ui`,
  or `infra`, but none of those is a `features/` slice in the Target tree (the features list
  is `report-sections, period, review, dashboard, slides, admin, analytics, weekly-report,
viewer, search, auth, landing, organization, …` — `auth` IS a slice, but the Target tree's
  own `shared/lib` bullet explicitly names `role-home/visibility`, `safe-next`, `client-logger`,
  `pluralize`, `format-date`, `query-client`, `trpc client/provider/context` verbatim as
  `shared/`-resident). Explicit Target-tree file lists win over the domain-column default.
- `weekly-report-*.ts` catalog Domain says `report-sections`, but the canonical-domain table
  lists `weekly-report` as its own domain distinct from report-sections' absorb list
  (`report-sections, lead-form, report, lead-history` — no `weekly-report`). Collapsed to the
  canonical `weekly-report` slice per the doc's own instruction to not lift an overlapping raw
  label.
- `lib/mappers/index.ts` is the barrel the Target tree explicitly says "dissolves into each
  slice's `model/`" — no single target path; each future slice grows its own `index.ts`.
- `last-role.ts`, `session-provider.tsx`, `use-session.ts` stay in `features/auth/model/`
  (not `shared/`) — single/primary consumer within auth, not named in the `shared/lib` bullet.
- `cross-author-content-gate.ts` has two slice consumers (slides + report-sections) — the
  rule-of-2 (web) graduates it to `shared/` at the second slice consumer; non-component pure
  gate logic → `shared/lib` per Axis 2.
