# Mapping — api-mod-admin (2026-07-02)

Source catalog: `docs/architecture/catalog/api-mod-admin-2026-07-02.md` (21 files).

Per TARGET-STRUCTURE-2026-07-02.md, `admin` is bucketed **MODERATE** in the api target
tree (`admin/ carry-over/ weekly-report/ archive/ reminders # MODERATE — flat + explicit
port where a repo exists`) — i.e. it stays **flat** (`X.service.ts` + `X.prisma-repository.ts`

- `X.module.ts` at the module root), NOT split into `domain/application/infrastructure`
  subfolders. That full hexagon split is reserved for the invariant-bearing trio
  (period, report-sections, review/publication) per the "Right-sizing" decision — admin is
  explicitly named as a moderate/flat module even though it already has the
  `AdminRepository` port + `admin.prisma-repository.ts` facade shape. Result: every file in
  this catalog already sits at its target path today. No relocations in this migration slice.

The "admin" canonical domain absorbs "admin, products, reminders (admin-side CRUD)" per
the Grouping-rules table — so admin-side reminder/period/project CRUD services stay under
`modules/admin/` even though their catalog `Domain` column names a finer label
(`period`, `organization`, `reminders`, `auth`). That finer label is descriptive of what
data the file touches, not a directive to relocate it into another api module — moving it
would be a cross-module extraction (Migration slice 6: facades + lint-zone flip), out of
scope for this flat/no-move slice.

- 21/21 files: **no move**. Admin is already at its target flat layout; the MODERATE
  bucket in TARGET-STRUCTURE-2026-07-02.md explicitly rejects the full
  `domain/application/infrastructure` split for this module.

  `session-revocation.service.ts`) carry a catalog `Domain` label finer than the module
  they live in; canonical-domain collapse keeps them in `modules/admin/` for this slice.

  `session-revocation.service.ts` if/when an api `auth` module is introduced — not proposed
  here.
