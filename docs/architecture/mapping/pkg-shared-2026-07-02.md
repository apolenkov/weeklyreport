## Why zero, not a false-negative

The target-structure doc explicitly scopes packages-level change to two things only:
(1) locking the dependency-direction lint zones (a config/gate change, not a file move),
and (2) curating `packages/ui`'s public `exports` map (a `packages/ui` concern, out of
scope for this `pkg-shared` catalog). It states plainly: "Packages are already correctly
layered (`shared` = runtime-pure Zod/tRPC contracts, `ui` = presentational primitives)
with a single one-way lint zone" and rejects "Promoting a domain to its own package"
and any further package split as over-granular for a two-consumer monorepo. No file in
this catalog fails the layer test (all are either `schema-dto`/wire contract, pure
`util`, or `module-wiring` barrel — none import Prisma/Nest/React) or the domain test
(all are legitimately cross-app). Hence every row's target equals its current path.
