# LLM Report Assistant

Этот раздел описывает встроенный помощник для Lead в Weekly Report. Он отвечает
на вопросы о доступных пользователю отчётах: черновике текущей недели и
опубликованной истории. Помощник не является источником данных и не имеет
прямого доступа к базе: он получает только факты, которые сервер уже нашёл и
разрешил показать конкретному Lead.

## Что мы сделали

В форме отчёта Lead появилась кнопка чата. Пользователь задаёт один вопрос,
например «Какие риски у продукта X?» или «Сколько открытых задач осталось?».
Сервер просит Mistral превратить вопрос в ограниченный план поиска, проверяет
этот план и применяет права доступа. Затем он собирает факты из текущего
черновика или неизменяемых опубликованных снимков. Если вопрос требует поиска
по смыслу, pgvector ранжирует только этот уже разрешённый набор. Mistral получает
компактную подборку фактов и формирует ответ со ссылками на источники; сервер
проверяет ссылки перед отправкой ответа в интерфейс.

Такой порядок важен: модель не выбирает SQL, идентификаторы, права, период или
источник данных, а семантический поиск не может расширить доступный набор.
Сбой Mistral не затрагивает сохранение, отправку и публикацию отчётов.

## С чего начать новому участнику команды

1. Откройте [логическую схему](./logical-flow.mmd): она показывает путь одного
   вопроса и все его контролируемые исходы.
2. Затем посмотрите [архитектурную схему](./architecture.mmd), чтобы понять
   границы web, API, PostgreSQL/pgvector, Redis/BullMQ и Mistral.
3. Для правил предметной области и ограничений прочитайте
   [сводку решений](./lead-report-assistant-decision-summary.md). Точные контракты
   запроса и промптов находятся рядом; они нужны при изменении API или адаптеров.

## Главные инварианты

- Доступен только Lead и только данные, разрешённые его текущими правами.
- Текущий открытый или переоткрытый отчёт читается из live-таблиц; история —
  исключительно из `publishedSnapshot`.
- Сначала точный поиск и ACL, затем — при необходимости — семантическое
  ранжирование. Векторная база хранит хэши и embeddings, но не текст отчётов.
- Ответ опирается на серверные факты, а каждая ссылка проверяется сервером.
- Вопросы, ответы, текст отчётов, embeddings и идентификаторы не попадают в
  логи и labels метрик.
