# Проверка OpenRouter для Weekly Report

Дата проверки: 11 августа 2026. Проверка выполнялась синтетическими запросами из приложения; ключ, отчётные данные и пользовательские данные не передавались и в этот документ не включены.

## Краткий вывод

Текущая конфигурация Mistral подтверждённо проходит полный capability test. Для протестированных бесплатных моделей OpenRouter не найдено сочетания, которое стабильно прошло бы все обязательные проверки. Это не означает, что OpenRouter в целом несовместим: его платную конкретную модель нужно проверить тем же тестом до активации и только после разрешения на расходы.

## Что именно проверяет приложение

Перед активацией приложение намеренно требует все три возможности:

| Часть      | Что должно получиться                                                                                     | Зачем это нужно                                                                                   |
| ---------- | --------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| Planner    | Ровно один принудительный вызов `search_report_entries`, без параллельных вызовов, с валидным JSON Schema | Модель не получает отчётные записи напрямую и не может сама решать, что ей разрешено искать.      |
| Answer     | Строгий структурированный JSON и корректный учёт токенов                                                  | Ответ, ссылки и лимиты должны быть проверяемыми, а не угадываться из произвольного текста.        |
| Embeddings | Два упорядоченных конечных вектора одинаковой положительной длины                                         | По ним строится семантический индекс; смешивать или молча принимать несовместимые вектора нельзя. |

Размерность вектора не вводится вручную и не передаётся поставщику: приложение измеряет её по успешному ответу embeddings и сохраняет вместе с конфигурацией.

## Почему Mistral работает, а эти бесплатные варианты OpenRouter — нет

Mistral принял полный диалект запроса, который нужен Weekly Report: обязательный tool call, отключённые параллельные tools, строгую схему ответа и embeddings без параметра размерности. Поэтому его конфигурация прошла проверку целиком.

OpenRouter — это шлюз к разным провайдерам и моделям. Метка «поддерживает tools/structured output» ещё не гарантирует, что конкретный бесплатный upstream примет весь наш строгий запрос: в нём есть принудительный выбор одного инструмента, отключение parallel calls и сгенерированная вложенная JSON Schema. В проверках встретились три нормальных для бесплатных маршрутов класса отказа: неподдержанный полный диалект (400/422), ответ другого формата и временное ограничение нагрузки (429). Capability test должен отклонять такую конфигурацию, иначе проблема проявится уже у Лида во время работы с отчётом.

## Что делать дальше

1. Не активировать бесплатную OpenRouter-конфигурацию для рабочей системы: сейчас она не доказала полный контракт.
2. Если нужен OpenRouter, выбрать конкретную платную модель и явно разрешить тест с расходами. Успех нельзя обещать по названию модели или её карточке — нужно выполнить capability test именно с ней.
3. Если тест пройдёт, размерность embeddings будет записана автоматически; вручную задавать её не потребуется.

Справка по возможностям OpenRouter: [tool calling](https://openrouter.ai/docs/guides/features/tool-calling), [structured outputs](https://openrouter.ai/docs/guides/features/structured-outputs), [каталог моделей embeddings](https://openrouter.ai/api/v1/embeddings/models).
