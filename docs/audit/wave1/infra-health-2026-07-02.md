## Killed by verification

- **redis.health.ts lines 12-15** — ad-hoc `process.env.REDIS_HOST ?? "localhost"` / `Number(process.env.REDIS_PORT ?? 6379)` silent fallbacks bypassing the env.schema/requireEnv pattern. Refuted: REDIS_HOST and REDIS_PORT are ALREADY required, defaultless fields in `env.schema.ts` (lines 45-46: `z.string()` / `z.coerce.number().int().positive()`), validated at boot via `ConfigModule`'s `validateEnv` useFactory provider — a missing var fails boot loudly, so the `?? "localhost"` fallback can never fire in a booted app. The finding's core risk claim ("missing var silently pointing at localhost") is false, and its suggestion ("add REDIS_HOST/REDIS_PORT as required fields in env.schema.ts") describes state that already exists. This is exactly the "env fallback actually validated by env.schema.ts" refutation case. (The same read pattern also exists in bullmq-options.ts, session-revocation.service.ts, telemetry.cache.ts, analytics.cache.ts — any residual DI-style cleanup is a repo-wide stylistic sweep, not a health-module defect; the duplication itself is captured as a kept, downgraded finding above.)
