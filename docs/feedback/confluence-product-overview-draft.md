# CustomReport — что это и как работает

**CustomReport** — внутренний инструмент Development для еженедельных статус-отчётов.
Лиды независимо заполняют свои разделы, голова (head) сводит, ревьюит и публикует
единый отчёт, а наблюдатели видят актуальный статус. Цель — за минуты собрать
честную картину недели по всем продуктам, без переписок и табличек вручную.

## Кому что

| Роль                     | Что делает                                                                                                                |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------- |
| **Лид**                  | Заполняет свой раздел: что сделано/планируется, риски, решения, статусы стадий по своим продуктам. Сдаёт раздел (Submit). |
| **Голова (head)**        | Видит живой отчёт группы, ревьюит, может вернуть раздел на доработку, публикует и лочит период, экспортирует.             |
| **Ревьюер**              | Голова или назначенный наблюдатель: комментирует конкретные записи и выносит вердикт, не лоча период _(в разработке)_.    |
| **Наблюдатель (viewer)** | Видит актуальный статус своих групп только на чтение; может «ознакомиться» _(в разработке)_.                              |
| **Админ**                | Заводит пользователей, группы, продукты, периоды, напоминания; ведёт справочники.                                         |

## Основные понятия

- **Период** — недельное окно отчёта. Живёт по состояниям: открыт → опубликован
  (залочен) → в архиве. «Сдан» — это всегда про конкретного лида, не про весь период.
- **Продукт** — единица, вокруг которой строится отчёт. Принадлежит одной группе; над
  одним продуктом могут работать несколько лидов, каждый по своим стадиям SDLC.
- **Стадия SDLC** — Planning / Analysis / Design / Development / Testing / DevOps /
  Support. Запись (айтем/риск/решение) всегда привязана к стадии, которой владеет автор.
- **Статус-светофор** — зелёный / жёлтый (риск) / красный (блок) на продукте и стадии.
- **Запись** — айтем (текущая/следующая неделя), риск, решение. У айтема есть статус
  работы: в работе / сделано / заблокировано.

## Поток недели

```
1. Период открывается → у каждого лида появляется его раздел с его продуктами.
2. Лид заполняет: айтемы недели, риски, решения, статусы стадий. Сохраняется автоматически.
3. Лид сдаёт раздел (Submit).
4. Голова видит живой отчёт (по умолчанию — только сданное), ревьюит,
   при необходимости возвращает раздел лиду с комментариями.
5. Голова публикует и лочит период — получается единый отчёт + экспорт.
6. Наблюдатели видят актуальный статус своих групп на чтение.
```

## Что в разработке (ближайшее)

- **Ревью и «Ознакомлен»** — наблюдатели/ревьюеры дают обратную связь по конкретным
  записям и возвращают раздел на доработку, не лоча период.
- **Единый быстрый ввод** — одна кнопка для быстрого добавления записей; опциональный
  вид «по состоянию».
- **Проектные активности** — отчётность по активностям без стадии SDLC, рядом с продуктами.
- **Мобильный/компактный layout** — работа с телефона и планшета.
